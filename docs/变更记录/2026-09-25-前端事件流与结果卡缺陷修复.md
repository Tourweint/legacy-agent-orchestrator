# 前端事件流与结果卡缺陷修复

> **文档性质：变更记录（带日期，追加不改写）。时点：阶段 8 与参数标定收尾之后，交付收口轮。**
> 触发：用户在浏览器里实跑前端（`http://localhost:5173`）报告"没效果"——输入一句话点发送后，界面上什么也不发生。
> 排查结论：**引擎链路完全正常，问题全在前端**——两处缺陷让"可解释性外化"这条主线在浏览器里从未真正跑起来。

---

## 一、排查过程（结论有据）

| 步骤 | 观测 | 判读 |
|---|---|---|
| 1. 直连引擎 `POST /api/chat`（UTF-8） | `{"code":0,"message":"accepted"}` → 任务 `terminal=DONE`，7 步，真实写入预约 #255 | 引擎 + 理解层 + 编排 + 存量系统**全通** |
| 2. 快照 `GET /api/tasks/{id}` | `status: terminal`、`result.terminal: DONE`、证据 19 条 | 引擎侧一切正常 |
| 3. 取 `GET /api/tasks/{id}/events`（经 5173 代理） | 正常吐出 `id: 1 / event: decision / data: {...}` 等帧 | 代理与事件流**服务端侧正常** |
| 4. 浏览器实操（Playwright 驱动）：输入 → 点"发送" | 用户气泡出现、taskId 出现，但 **P1–P6 全部 0 事件**，无结果卡 | 前端收事件这一环断了 |
| 5. `agent-browser console` / `errors` / `network requests` | ① `[Vue warn]: Property "terminal" was accessed during render but is not defined on instance. at <TrajectoryPane>`；② `/events` 被 **反复重连**（同一 taskId 数十次 EventSource 请求） | 两条独立缺陷同时命中 |

**定位一（致命）**：`frontend/src/api/sse.js` 用 `es.onmessage` 订阅。而 SSE 规范中 `onmessage` **只接收没有 `event:` 字段的默认帧**；引擎对每帧都按类型命名发送（`event: decision` / `call` / `terminal` …，见第 10 章 §6.3 与 `docs/基线文档/对外接口清单.md` §四）。结果：**一条事件都收不到**；因为收不到 `terminal`，前端也不会关流，EventSource 便无限重连。

**定位二**：`frontend/src/components/TrajectoryPane.vue` 第 29 行 `v-if="terminal"` —— 该组件里**根本没有 `terminal` 这个变量**（Vue 每帧渲染都告警）。它是"结果视图"的开关，恒为假 → **`ResultCard` 永不渲染**：三视图里的"结果"实际上不存在。

## 二、修复

| # | 文件 | 改动 |
|---|---|---|
| 1 | `frontend/src/api/sse.js` | 按**类型闭集**逐个 `addEventListener(type, handleFrame)` 订阅（闭集常量 `EVENT_TYPES` 就地登记，注明以对外接口清单 §四 为准、新增 type 必须先登记再补表）；`onmessage` 保留为未命名帧的兜底（不静默丢步）。终态关流、重连状态、帧解析缺陷上报等原有行为不变 |
| 2 | `frontend/src/components/TrajectoryPane.vue` | 新增 `isTerminal = computed(() => store.taskStatus === 'terminal')`，模板 `v-if="terminal"` → `v-if="isTerminal"`，结果卡恢复渲染 |

两处均为前端展示层修复，**未触碰引擎、接口契约与设计口径**。

## 四、给后续会话的提醒

1. **"经代理的 REST 通了"不等于"界面能收到事件"。** 阶段 7 的烟测验的是 REST 路径（见该记录的后续更正注），浏览器侧的 SSE 消费从未验过——**事件流这类"命名帧"协议，必须用真正的浏览器（或 EventSource 客户端）验一次**。
2. **模板里引用了未定义的变量，Vue 只告警不报错**，界面表现为"某个区块永远不出现"。改完前端后，**看一眼控制台**是最省事的兜底。
3. 事件 type 是**闭集**（对外接口清单 §四）：前端订阅表与引擎发送表是两处需要同步维护的地方，新增 type 时两处都要动。

## 五、回滚建议

- 两处修复均为前端展示层，删除/还原文件即回滚；对引擎与存量系统无依赖。
- **不建议回滚**：回滚即界面收不到任何事件、结果卡不显示——演示路径将完全不可用。

# 2026-09-27 对话工作台：全屏改造、取消可用性、答案与过程分层

> **文档性质：变更记录。** 起因是演示前提出的四个体验问题（页面太小气、取消任务不生效、答案被藏在思考过程里、对话整体待优化）。四项都落地了，并在联调中挖出**一个真正的地基缺陷**——它同时解释了"取消不生效"与"对话卡住要重启"。

## 一、根因：新轮次的状态更新不触发渲染（地基缺陷）

**现象**：发送一句话之后，界面**永远停在"运行中"**：没有思考过程、没有答案、取消按钮点了没反应；点左栏历史会话再切回来，结果又"突然出现"。

**定位**：浏览器里直接读 Pinia 状态，发现数据**全是对的**——18 条事件、终态结果、结论文案都在 store 里，只是视图不重渲染。于是问题不在事件流、不在代理、不在后端。

**根因**（`frontend/src/stores/task.js` 的 `_newTurn`）：

```js
const turn = makeTurn(userText, this.turns.length)
this.turns.push(turn)
return turn            // ← 返回的是**原始对象**
```

Vue 3 的 `reactive` 是**读时才代理**的：`this.turns.push(原始对象)` 只把原始对象存进底层数组，之后所有 `turn.status = …`、`turn.events.push(…)` 都作用在**原始对象**上，不经过代理的 set 拦截，因此**不通知任何依赖**。而 store 的 getter（`s.turns.find(...)`）走的是代理，读到的是同一份底层数据——所以数据"看起来是新的"，界面却一动不动。

**修法**：返回 `this.turns` 里那一份（代理），修改即触发渲染。已在代码里写下注释说明这个坑（它的症状极具迷惑性）。

**为什么这解释了另外两问**：
- "取消不生效"：点了停止 → `cancelRequested` 改了但界面不动 → 用户以为没反应，再点、再等，最后去重启；
- "要重启"：终态到了但界面停在"运行中"，用户无从判断任务是否还在跑，只能重启整个前端。

> 附带一条同类兜底：引擎重启后任务已不存在（K3：运行栈随任务销毁），轮询会发现 404 并**如实收场**（"这次任务在服务重启后已无法继续跟踪，请重新说一遍"），不再让界面永远转圈。

## 二、全屏工作台（DeepSeek 式）

- 外壳改为**占满视口、页面自身不滚动**（`html/body/#app` 高 100%）：顶栏（56px 细边框）／左栏／对话区三段，**只有消息区滚动**，输入框永远贴在手边；
- 顶栏改为三段式（左：侧栏开关 + 品牌；中：任务与连接状态；右：主题 + 身份）；
- **左栏可完全收起**（不再留窄边），展开入口是顶栏开关按钮；宽屏默认展开、窄屏（<900px）默认收起；
- 对话区不再是一张 920×640 的小卡片：铺满右侧，内容宽度上限 820px 居中（宽屏不拉散，窄屏不挤压）；
- 左栏底色浅一档（`--bg`），与对话区拉开层次。

## 三、取消：写请求发出前都能停

**口径修正（B8 的补完）**：原来只有**挂起态**（AWAIT_CLARIFY）的取消会被受理，而前端按钮在"运行中但还没发出写请求"时也是可点的——**界面答应的事，后端一律拒绝**，还只给一行静默的 409，用户看到的就是"点了没反应"。

现在的口径（引擎与界面同一套）：

| 任务所处阶段 | 取消行为 |
|---|---|
| 挂起中（等你补充信息） | 立即取消，直接给结论 |
| 运行中、**写请求尚未发出**（理解／消解／收集／判定／降级） | **受理**：置停止标记，运行循环在下一个状态边界收口 |
| 写请求已发出（提交／判定结果／查证／补偿） | **不受理**，如实说明"结果正在核对，暂时不能中断" |

- 引擎侧新增 `CANCELABLE_STATES` / `WRITE_STATES` 两个状态集合（`run-engine.js`），`#drive` 循环在**状态边界**收口，走的是与挂起态取消**同一条边**（`USER_CANCELLED → REJECTED`）——用户看到的是同一个"已取消"，而不是两种取消；
- 接入层：`DELETE /api/tasks/:id` 运行中取消回 **202 `cancel-requested`**（终态仍由事件流给出）；提示性的失败回 **409 + 具体原因**，不再吞掉；
- **运行栈可见**：`executeChatTask` / `executeTask` 新增 `onStack` 回调，接入层从任务创建起就持有运行栈（原来只在挂起时回填，运行中的取消连状态都读不到）；
- 界面：停止按钮写成输入框正上方的轻量胶囊（"■ 停止这次办理"+"还没有向系统提交任何变更"），落终态后如实显示**已取消**（顶栏、答案卡、左栏状态点三处口径一致）；
- **不假装已经停住**：202 之后前端只记"已请求停止"，等终态到达再改口；万一请求与终态擦肩而过（已经办成），就如实说办成了。

## 四、答案与过程分层：结论不进思考过程

用户口径：**"思考过程里面包含了结果，肯定不行。"**

- **结论事件退出思考过程**（`useThinking.js` 新增 `isAnswerEvent`）：`terminal` 与 P2 及之后的 `decision`（如只读意图的答案）不再计入步骤数和明细；只有 P1 的"识别为…"属于过程。示例话术"查一下明天上午数智楼 123 有没有空"的步骤数因此从 18 步变为 16 步，结论只在大字答案卡里出现一次；
- **答案用大字**（`AnswerBubble.vue`）：主答话 22px 加粗居中成视觉重心；引擎拼在结论末尾的"请确认"推算依据（§7.3）拆成小字附注，不再抢大字；
- **办成了就收起过程**：终态 DONE 默认收起（答案已经回答了问题，想看依据再点开）；只有没办成才自动展开失败链；
- **标题改口径**："为什么没办成" → **"为什么是这个结果"**（查询类同样会有不成立的命题，那时用户问的是"你凭什么这么答"，不是"哪里办错了"）；失败计数改为**只数逐条判定项**，不再把汇总行也算成一项（此前标题会说"2 项没通过"，而用户只数得到 1 项）；
- **顺带清掉内部黑话**：用户可见文案里的 `K2 常量`／`J4` 去掉（"（按部署地时间）"），零术语纪律同样管"请确认"注记。

## 五、对话体验的其他修正

- 助手消息**不再套气泡**（像正文一样读），左对齐 + 品牌圆点标识；用户消息保持右侧淡蓝气泡（限宽 82%）；
- **自动滚动只在用户本来就在看最新一条时发生**（距底 120px 内）——读历史时不再被拽回底部；
- 发送/追问/终止后的滚动与置底行为统一；
- 停掉"运行中一律禁用输入"之外的隐性阻塞：取消落终态后输入框立即可用（先取消、再重发这条用户路径已实测走通）。

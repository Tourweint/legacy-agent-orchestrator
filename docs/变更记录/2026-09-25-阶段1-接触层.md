## 一、变更背景

阶段 0 落地了口径、证据层与配置数据。阶段 1 按第 13 章 §二 的接触层规格实现**防腐网关**：唯一 HTTP 出口、按注册表选择身份并注入凭证、吸收协议异构、执行三值判定（W1–W13 / R1–R10）。

## 二、核心设计决策（实现级，均有方案依据）

| # | 决定 | 依据 |
|---|---|---|
| 1 | **模块切分为五件**：`http-transport`（唯一出口，仅传输）、`identity-pool`（凭证池，凭证不出模块）、`adapters`（异构吸收，字段名只在这里出现）、`verdict-rules`（W/R 规则表数据化，唯一判定点）、`contact-gateway`（组装与编排：语义参数 → 三值结论） | 第 02 章 §四/§五、第 13 章 阶段 1 职责四条 |
| 2 | **规则表 = 有序数据行**（`match` + 结论 + `resolve` 分叉钩子），未列出组合走 `DEFAULT_UNKNOWN`（白名单式）；行号 W1–W13/R1–R9 与文档逐行对应，R10 是"读重试超限"兜底结论而非信号行（二审口径） | 第 05 章 §四；C11/C15 |
| 3 | **W4/W13 的补偿分叉落在规则行内**：接口声明 `verdictFork: compensation`（注册表新增可选字段，目前仅 cancel），命中 200+400/404 时判 UNKNOWN（进 recordId 查证）而非 FAILURE | 第 05 章 W13/L1、第 06 章 §8.1、D10 实测 |
| 4 | **读接口的有限重试在接触层内执行**（透明重登 R6/J5 + 瞬态重试 R8/R9，上限 C13=2 次短间隔），打满落 R10 `FAILURE + 事实不可得`；写接口任何情形零自动重试 | 第 05 章 R6/R8/R9/R10、第 01 章 M4、C13 |
| 5 | **协议级信号（HTTP 状态码/业务码/响应片段）只进证据链**（metadata 档），结果对象只含三值结论 + 语义数据——编排层永远写不出 `if (httpStatus === 409)` | 第 13 章 阶段 1 契约 vs 第 05 章 §八 的调和：evidence 归证据链（第 02 章 A5"证据链保留原响应片段"） |
| 6 | **响应片段入链前做两级净化**：结构化字段按键名剔除（阶段 0 redact），文本片段按凭证形态清洗（`"token":"…"`、JWT 三段式）；登录响应整段跳过（其体内含 token） | 第 05 章 §八 evidence 不得含凭证；C16 |
| 7 | **证据链 basis 扩展**：允许引用判定规则行 `{rule: 'W2'}`（与 F#/P-# 并列），并新增可选 `metadata` 档——接触层判定依据（规则行号）由此进链，I4 的"凭什么这么判"可被复查 | 第 05 章 §八 规格 2；阶段 0 交付物的最小扩展，向后兼容 |
| 8 | **约束机器化**：新增 `scripts/constraint-check.mjs` 并入 `npm run check`——约束 A（网络请求写法只在 http-transport、存量系统地址零字面量）与约束 C（LLM 客户端零出现）grep 式判否；约束 B 无法静态检查，由 8 条结构自检的 SUBMITTING 入边项承接 | 第 02 章 §四"检查规则" |
| 9 | **注册表增补**：12 条接口全部补 `timeoutClass`（write/read/readHeavyList → 对应 constants 的超时档，B3 初值）；seat.create 的适配器修正为 `reservation-seat-create`（阶段 0 误与教室创建共用，两者请求体字段不同） | 第 04 章 §十"单次调用超时按接口分级"；B3 |
| 10 | **M3 式本地拦截**：`min_capacity`/`building` 必填、`keyword` 禁用、时间参数必须是绝对时刻（Date）——不合格请求在适配器构造期直接抛 `ContactError`，零 HTTP 发出 | 第 01 章 M3、第 06 章 §五、基线 §7.4 #9 |

## 四、实现期的新发现（已登记基线文档）

| # | 发现 | 落点 |
|---|---|---|
| 1 | **openapi LoginVO 又错了**：登录响应 schema 写 `data.token`，实测是 `data.accessToken` + `data.refreshToken`。机器可读文档与实现再次不一致（上游 D 系列第 7 条） | 基线 §九 D7；身份池按实测取值 |
| 2 | **列表响应不含 `classroom_id`**：DB 实体有、SEAT 行 100% 带值（三审实测无误），但 `AdminReservationVO`/`ReservationVO` 不暴露该字段——SEAT 行教室只能经 `resourceName`（"楼栋 房间号 座位号"，源码拼接）或 seat→classroom 映射间接得到。**这是阶段 2 实现 F4 归并（C9/J3）前必须解决的口径**，两条路径的取舍留待阶段 2 实测定 | 基线 §8.4 新行；不在代码里静默偏离 |
| 3 | （实现过程，非存量系统异构）Node fetch 的 HTTP 头值只允许 ASCII——设备名默认值原写中文导致传输层 `disconnect`；已改 ASCII 并在 constants 注明 | constants.yaml contact.device |

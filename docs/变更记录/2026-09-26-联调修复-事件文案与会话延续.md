> **文档性质：变更记录（带日期）**。起因是把三件套**真跑起来**做端到端联调（存量系统 8080 + 引擎 8090 + 前端 5173），
> 而不是只看构建与单测。**一次联调抓出 5 个问题**，其中 1 个是致命运行时缺陷、2 个是删掉右侧轨迹面板后暴露的老洞。
> 依据：[对话工作台界面方案](../设计方案/2026-09-26-对话工作台界面方案.md) §3.1/§四、[对外接口清单](../基线文档/对外接口清单.md) §四。

## 一、为什么要"真跑"：`npm run build` 通过 ≠ 能跑

最直白的一例：

| 缺陷 | build | lint | 真跑 |
|---|---|---|---|
| `sse.js` 里 `handleFrame` 被引用但**从未定义** | ✅ 通过（未定义变量被当成全局） | ❌ **报 `no-undef`** | ❌ SSE 一条事件都收不到 |
| 事件文案只有 "ok" / "SATISFIED" | ✅ 通过 | ✅ 通过 | ❌ 用户看到的是机器话 |

**结论**：三道关各有盲区——`build` 管打包、`lint` 管静态引用、**端到端管"人看到什么"**。这次三者都跑了才收干净。

## 二、修的 5 个问题

### 1.（本次引入，致命）`sse.js` 的 `handleFrame` 未定义

- **现象**：前端能连上 SSE，但**任何事件都收不到**（轨迹空、终态不触发、界面停在"正在办理"）。
- **根因**：清理冲突标记时，把 HEAD 侧的 `const handleFrame = (msg) => {...}` 整段删掉了，却保留了
  `es.addEventListener(type, handleFrame)` 与 `es.onmessage = handleFrame` 两处引用。
- **修法**：补回 `handleFrame`（单帧统一处理器，命名帧与默认帧共用）。顺带把注释改成**实情**：
  引擎当前发的是默认帧（`id:` + `data:`，见 `sseFrame`），`onmessage` 是主路径，`addEventListener` 是帧格式变化时的保险。
- **验证**：前端 `npm run lint:check` 干净（此缺陷只有它抓得住）；真实链路 38 条事件全部到达。

### 2.（既有洞，删右栏后暴露）`call` 事件的 text 只有 `"ok"`

- **现象**：对话里"调用 N 次，全部成功"没问题，但**失败的调用**逐条展开时只会显示 `ok`——等于没说。
- **根因**：事件的 text 取的是接触层返回的 message（成功时就是 `ok`）；业务名原本靠**右侧轨迹面板**去查证据补上
  （`TrajectoryItem` 里的 `INTERFACE_NAMES`）。右栏一删，这条路断了。
- **修法**：**让事件自带人话**，且名字不新建映射——从**接口注册表**派生
  （`buildInterfaceNames` 取每条接口 `purpose` 的首段："教室详情——把人读名解析成系统 id……" → `教室详情`）。
  成功时不再念 `ok`；失败时接上返回内容（`提交整间教室预约 · 系统拒绝了这次提交`）；映射缺失时给中性说法
  （`与业务系统交互`），**绝不把接口 id 漏给用户**。
- **顺带**：前端 `constants/display-names.js` 里的 `INTERFACE_NAMES` 删除（只留身份名），避免两份映射漂移。

### 3.（既有洞，同类）`proposition-judged` 的 text 是枚举 `"SATISFIED"`

- **现象**：判定行原样是 `SATISFIED`——而"办不成"时**正是这些行要展开给用户看**。
- **修法**：命题人话名从**术语对照表**派生（`buildPropositionNames(configStore.getGlossary())`，与
  `GET /api/meta/glossary` 同源），结论枚举翻译成人话。现在是：

  ```text
  找到了这间教室 · 成立
  这个时段是空的 · 不成立
  这间教室这段时间不在检修 · 成立
  ```

- **纪律**：证据里若带额外说明（不是枚举复述）就括注出来；缺名字时给 `这一项条件`，不塞 `P-SLOT-FREE`。

### 4.（既有体验问题）接续语"那改成…"被理解成别的意图，且不沿用上文

- **现象**：同一会话里先说"帮我借明天下午数智楼123"，再说"那改成后天上午"，引擎把它理解成**查询/撤销我的预约**；
  改成对的意图后，又把 `classroomName` 留空去追问"哪间教室"。
- **根因**：提示词没有交代"接续语"这件事；而"纪律 4（没说清的信息不要猜）"与"延续上一轮"之间缺一条边界。
- **修法**（`understanding/prompt.js`，提示词是行为的一部分，故记档）：
  - 新增纪律 7：接续语指**上一轮那件事**；上一轮已说清的信息要**沿用并写进本次 slots**——"它已经由用户说过，不是猜"；
  - 加一组少样本：`帮我借明天下午数智楼123` → `那改成后天上午` → 仍是 `borrow-classroom`、`classroomName` 沿用 `数智楼123`。
- **验证**（真实链路）：`那改成上午九点到十一点` → `已为您办妥：数智楼 123（预约 #127，2026-09-28 09:00–11:00）` ✅

### 5.（既有可解释性缺陷）降级换了教室，结论却不说为什么

- **现象**：说"借数智楼123"，123 该时段被占、系统按规则换到 222，结论只写"已为您办妥：**数智楼 222**"——
  用户会以为系统听错了。
- **修法**（`run-engine.js` 新增 `#degradeNote`）：发生过换教室时，结论补一句
  `（原教室 数智楼 123 在该时段不可用，已按同楼栋优先、不降容量的规则换到 数智楼 222）`。
- **依据**：I4"必须能回答为什么做了这一步"——那不是加分项，是必须项。

## 四、留下的经验

1. **改完前端要跑三样**：`npm test`（纯函数）、`npm run lint:check`（静态引用）、`npm run build`（打包）。
   这次的致命缺陷只有 lint 抓得住，而"人看到什么"只有真跑才知道。
2. **删掉一个展示层，要检查它是否在替后端"补话"**：右栏一直在替事件补业务名与命题名——删它才暴露出
   事件文案本身不完整。**判据**：界面不该各自拼展柜文案，事件就该自带人话。
3. **演示前务必真跑一遍**：`start-all.bat` 起四件套后，按界面方案 §六 的四个镜头走一遍。

# 2026-09-27 启动脚本自动拉起 Redis（顺带查清"账号密码不对"的真身）

> **文档性质：变更记录。** 起因是一个报障："登录不进去了，账号密码不对。" 查下来账号密码是对的——**Redis 没启动**。这一条把两件事一起改了：`start-all.bat` 现在会自动拉起 Redis；同时把"Redis 缺席会在界面上伪装成密码错"这条坑登记进运维事实，避免下次再往错方向查。

## 一、真因：不是密码错，是 Redis 缺席

**现象**：三个演示账号全部登不进去，界面提示"账号或密码不正确"。

**排查**：`3306 / 5173 / 5174 / 8080 / 8090` 全部在监听，**唯一缺席的是 6379（Redis）**（既无监听端口，也无 `redis-server` 进程）。拉起 Redis 后复测三条链路，全部恢复：

| 入口 | 结果 |
|---|---|
| 存量系统直连 `8080/auth/login` | HTTP 200 |
| 引擎 `8090/api/auth/login` | `code=0` |
| 浏览器实际走的 `5173/api/auth/login` | `code=0`，`233/233`→TEACHER、`abc/abc`→STUDENT、`admin/admin`→ADMIN |

**真因**：存量系统的**登录会话、刷新令牌、设备会话全部存在 Redis 里**；Redis 缺席时它的登录接口直接拒绝。项目文档早有登记（`docs/变更记录/2026-09-25-阶段1-接触层.md` §踩坑：登录失败报 code 500 的根因是 Redis 未启动）。

**为什么界面说的是"账号或密码不正确"**（误导来源）：`orchestrator/src/access/auth-endpoints.js` 把所有"被拒"统一翻成同一句：

```js
const message = /被拒/.test(err.message) ? '账号或密码不正确' : `登录失败：${err.message}`
```

而 `/被拒/` 同时覆盖「HTTP 401（真的密码错）」与「业务码非 200（服务端故障，如 Redis 挂导致的 500）」两种情况——**底层是服务端故障，界面却指着正确密码说"你输错了"**。本次**未改此处文案**（属于引擎侧改动，留作待办，见 §五）。

## 二、改动：`start-all.bat` 自动拉起 Redis

零侵入口径不变：Redis 不是存量系统的一部分，本改动不碰 `mock-legacy/`。

| 项 | 改动 |
|---|---|
| 新增模式 | `start-all.bat redis` —— 只启动 Redis（6379） |
| 自动拉起范围 | `all` / `legacy` / `legacyui` / `redis` 四种模式**先确保 6379 就绪**；`engine` / `web` 不碰 Redis（它们与存量会话无关） |
| 定位顺序（新增 `:findRedis` 子过程） | 环境变量 `REDIS_SERVER` → `PATH`（`where redis-server`）→ scoop（`~\scoop\apps\redis\current\`、`~\scoop\shims\`）→ `C:\Program Files\Redis\` 等常见路径。新装法落在这几处即免配置 |
| 启动口径 | 窗口工作目录 = 数据目录 `deploy\data\redis`（即 `--dir` 的默认值，因此命令行不必再拼含空格路径）；参数 `--port <SPRING_DATA_REDIS_PORT> --appendonly yes`，与 `deploy/scripts/start-redis.sh` 同口径（AOF 持久化） |
| 成功判据 | 用既有 `:waitPort` 等 6379 真就绪（最多 15 秒）再往下走，不靠"窗口起来了"就算数 |
| 失败处理 | **找不到 `redis-server.exe` 时明确中止并指名**（打印安装/配置指引），不静默跳过——静默跳过等于把用户送回"密码错"的坑 |
| 顺带 | 前置检查的 6379 行、等待就绪段、汇总横幅（新增 Redis 一行）同步更新；头部用法说明写明定位顺序与理由 |

**为什么把"没装 Redis"做成中止而不是警告**：存量系统缺 Redis 时登录必然失败，而失败会被显示成"账号或密码不正确"；与其让使用者对着正确密码反复试，不如在启动阶段就把话说明白。

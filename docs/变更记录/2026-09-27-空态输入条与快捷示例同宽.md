# 空态输入条与快捷示例同宽（2026-09-27）

## 背景

用户反馈空态输入条"左右的宽度拉得太长了"——上一轮为统一 hero/dock 把宽度设成 `min(820px, calc(100% - 48px))`，空态时 820px 占对话区（971px）84%，与下方窄窄的快捷示例 chips（实测 486px）不协调。用户要求：**输入条与快捷示例保持同宽，且无论左栏收起还是不收起宽度都不变**。

## 实测

- chips 容器宽 **486px**（2 行：最长行 394px，容器按内容排布）；
- 输入条 820px（占对话区 84%）——确实太长；
- 左栏收起后 chat 变宽（971→1239），chips 是 `absolute` shrink-to-fit 层，**可用宽度变大后重新换行变宽到 620px**——所以 chips 宽度也必须固定，否则"收起/不收起不一致"。

## 改动（`ChatPane.vue`）

1. `.composer-host`（空态基础）宽度 `min(820px, calc(100% - 48px))` → **`min(486px, calc(100% - 48px))`**（与 chips 同宽，窄屏回退）；对话态 `.chat.has-turns .composer-host` 保持 `min(820px, …)`（底部 dock 惯例宽度，无 chips 参照）。
2. 恢复 `transition: width 300ms`（hero 486 ↔ dock 820 切换时宽度平滑过渡，与 top 同步）。
3. `.chips` 加 **`width: 486px`（纯固定）** + `justify-content: center`——chips 不随左栏状态/对话区宽度换行变宽；⚠️ 不能写 `min(486px, calc(100% - 48px))`：`.chips` 的父级 `.hero-chips` 是 absolute shrink-to-fit 层，`%` 宽度循环依赖不可靠（实测左栏收起后 620、再展开 438）。

## 验证

- 前端 `npm test` 10/10、`npm run lint:check`（0 error，1 条既有 warning）、`npm run build` 全绿。
- 浏览器三态实测 host/chips 宽度：左栏展开 **486/486**、左栏收起 **486/486**、左栏再展开 **486/486**——输入条与快捷示例始终同宽、不受左栏状态影响。
- 切换动画：hero→dock 宽度 486→820 平滑过渡（rAF 采样连续）、top 356→717px 连续。

## 尚存说明

- 486px 是当前示例文案（TEACHER_EXAMPLES 4 条）下的实测宽度；若以后改示例文案，需同步调整此固定值。
- dock（对话态底部）仍为 820px——用户本轮只点名空态输入条过长；若希望底部也收窄可再调。

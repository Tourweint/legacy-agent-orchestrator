# 2026-09-27 结论结构化与多行渲染

## 起因

用户反馈：查询结果（如"有几条预约生效"）返回的数字"摞在一起"（单行 `；` 拼接），需要**结构化**呈现；且"模型输出的内容有时有条理、渲染出来却连在一起"——需要系统对结构化内容做**多行渲染**。要求不只查询我的预约，其他列表类内容（如候选教室）一并结构化。

（说明：这些文案是引擎确定性拼接的、不是大模型重写，因此格式可以精确控制；"模型输出有条理但渲染连在一起"的真实来源是引擎单行拼接 + 前端按一段文本渲染。）

## 改动

### 引擎侧：列表类结论结构化（`orchestrator/`）

- **`src/orchestration/run-engine.js`**：
  - `#recordList(rows)` 从单行 `；` 拼接改为**每条一行、带序号**（`1. …\n2. …`）；
  - `#locateMyReservation` 两处列表话术（无匹配时的"当前生效的预约"、多命中时的"N 条匹配的预约"）改为**冒号后换行接列表**、提示语另起一行；
  - `#readOnlyAnswer` 查询结论 `您名下当前有 N 条生效预约：\n{列表}`。
- **`src/judgment/judgment-engine.js`**：`#vars` 的候选教室（`P-CLASSROOM-EXISTS` 的"现有教室：{{candidates}}"）同样改为**每条一行带序号**。

### 前端侧：多行结构化渲染（`frontend/`）

- **`src/components/AnswerBubble.vue`**：结论按 `\n` 拆成块级段落（`paragraphs`）；以 `数字. ` 开头的行识别为列表项（`isItem`），**悬挂缩进 2.4em** 让序号与正文对齐——换行不再被折叠成"摞在一起"的一行。
- **`src/components/ChatPane.vue`**：修复能力入口点击守卫——`useExample` 原来在 `terminal` 时直接 return，**恢复会话被标终态后入口点击零请求发出**（实测抓到）；改为只挡 `pending / suspended`，终态后"接着办下一件"是合法链路，与 `send()` 的 terminal 分支口径一致。

## 说明与遗留

- 历史会话缓存显示旧格式（单行 `；`）属预期；新任务走结构化多行。
- "我订了哪些教室"仍偶发被真实 LLM 判为域外意图（REJECTED）——与已知相邻缺陷①（reply 补槽位话被理解成新意图）同源，另立任务。
- 结构化仅覆盖列表类结论（预约列表、候选教室）；单条结论（办成/撤销/幂等）保持一句话。

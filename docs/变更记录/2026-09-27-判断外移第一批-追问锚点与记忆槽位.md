# 2026-09-27 判断外移（第一批）：追问锚点与记忆槽位

> **文档性质：变更记录。** 依据：[判断外移方案](../设计方案/2026-09-27-判断外移方案-追问锚点与记忆槽位修复.md) §四（第一批）+ [03 章 §8.4](../设计方案/2026-09-24-系统设计方案/03-智能体职责划分与理解层方案.md)。用户口径：**系统只钉"极其重要的边界"，其余交给模型判断；材料由系统保证齐备**。
> **起因**：理解卡落地后实测撞出两条相邻缺陷（见[理解卡与一句话改口实现登记](2026-09-27-理解卡与一句话改口实现登记.md) §三）——两者同源：**引擎手里已经有确定下来的意图与槽位，却不肯在下一轮理解时交给模型**。

## 一、两条缺陷的根因（已核验）

| # | 现象 | 根因 |
|---|---|---|
| ① | 追问回复"下午三点到四点"被真实模型理解成「查询教室可用性」——用户要**借**，系统去**查** | 追问轮的第二次理解只看得到"追问句 + 回复"：`chat-bridge.js` 的 `#clarify` 只推追问句、`beginResume` 只重复推一遍同一句（**追问句被注入了两次**，而**用户原话一次都没有**），已确定的意图与已收槽位也不在。提示词的接续纪律挂在"历史里最后一条**助手摘要**的 intent"上，追问轮里没有这条摘要 → 纪律不生效，模型只能裸判 |
| ② | 改口新轮"改成周五下午"接不上上一轮的教室（又被问一次"哪间教室"） | `task-runner.js` 的 `#chatSummary` 读 `tc.chat.slots`，**全仓从未写入过**该字段（探针实证恒 `{}`）；真正合并进来的槽位在 `tc.slots` |

**顺带**：缺陷 ① 还会让 P1 的 `decide:understand` 只剩新意图，原意图无结构化留痕（I4 答不上"为什么换了"）。

## 二、改了什么

| # | 文件 | 改动 |
|---|---|---|
| 1 | `orchestrator/src/understanding/prompt.js` | 新增**纪律 8**：历史里若出现"你自己给出的结构化理解（含 `missing`）"，表示上一轮已确定到哪一步、还缺什么——**很可能是在补缺口**，那就沿用同一意图并输出 `intentSource: "resumed"`；明显改主意/换事/超域则输出 `"switched"`（附正反例）。纪律 7 末尾补一句：助手摘要里的 `outcome = REJECTED` 表示**那一次被取消或放弃了**（教室可沿用，日期时间以本次为准）。输出格式补 `intentSource` 字段；少样本补一组"追问锚点 → 补槽位沿用（resumed）" |
| 2 | `orchestrator/src/understanding/schema.js` | 新增 `INTENT_SOURCES = {resumed, switched}`：**只认枚举**（自由文本承担判断 → 判违规、走格式重试），合法值随校验结果带出 |
| 3 | `orchestrator/src/understanding/understanding.js` | ok 分支透传 `intentSource`（追问轮才有） |
| 4 | `orchestrator/src/orchestration/chat-bridge.js` | ① 每轮把**用户原话**落进历史（此前原话丢失）；② `beginResume` 改为注入**结构化锚点**（`#anchor`：已确定意图 + 已收槽位 + 机械算出的缺口，与少样本同形），**不再重复推追问句**（顺带修掉"追问句注入两次"）；③ `#decideUnderstand` 增 `priorIntentId`：把模型自报的 `intentSource`、"追问前的意图"、以及**自称沿用但意图确实变了**（`intentSourceContradicted`）写进证据 `input`（I4） |
| 5 | `orchestrator/src/orchestration/task-runner.js` | `#chatSummary` 的槽位改取 `tc.slots`（合并后的真实槽位）——记忆因此带上"教室是数智楼123"这类上下文 |
| 6 | `orchestrator/test/understanding.test.mjs` | 新增 2 条：`intentSource` 契约（只认枚举 / 缺省为 null / 自由文本判违规）；**追问锚点**集成用例（第二次理解的消息里含锚点 + 本轮原话 + 追问句恰好一次；证据链里 `intentSource=resumed`、`priorIntentId=borrow-classroom`、无矛盾标记） |
| 7 | `orchestrator/test/access.test.mjs` | 修掉那条**假绿**断言：改为断言**真正注入的那一条**记忆摘要（`{"intent":…,"slots":{…},"outcome":…}`）里的槽位，不再用 `includes('数智楼123')` 去撞提示词自带的少样本例子 |

**对外契约未变**：没有新增事件类型、没有新增端点字段——`intentSource` 落在证据条目的 `input` 里（复核口径），事件 `text`/schema 一律照旧。前端无需改动。

## 三、判断权归谁（本次确立的口径）

| 事项 | 谁定 |
|---|---|
| 追问轮"沿用上一轮意图"还是"改了口气" | **模型**（`intentSource`）；系统只校验意图落在闭集内、并留痕 |
| 跨轮该沿用哪些信息（改口新轮带不带上一轮的教室） | **模型**：记忆如实给出槽位与上一轮终态（含 `REJECTED`），沿用与否模型判断——**系统不做"取消轮一律不算数"的过滤**（试验性，见 §五） |
| 缺口（还缺哪几个必填） | **系统**机械计算（闸门三，材料给模型，判定权不下放）——硬边界 |
| 有副作用调用前的校验 / 最小身份调用 / 写请求发出后不可中断 / 业务结论只能来自事实 | **系统**（硬边界，见方案 §2.1） |

⚠️ **本次实测撞出并修掉一个我自己引入的回归**：第一批写的**纪律 8** 里那句"已收的槽位不必重复说，系统会合并"——它**只对同一轮内的追问锚点成立**，模型却把它外推到了跨轮，于是第二轮不再重写教室槽位（首跑场景 8 因此失败：又被问"哪间教室"）。修法：纪律 7 明确"跨轮是另起一轮，沿用的信息**必须重新写进本次 slots**，系统不会替你合并上一轮"；纪律 8 把"不必重复"限定在**同一轮**并显式指向纪律 7。修后 4 次全通过。

**未验证（如实登记）**：浏览器界面侧（理解卡、改一下按钮、运行中改口的三段交互）需要人眼点一遍；真实模型有随机性，上面每次结论都是**少量重复**（① 2 次、② 4 次）的结果，不是统计意义上的稳定性结论。

## 五、留存的不确定性 / 体验判据（做完先看体验，好就留）

1. **追问锚点是否真能压住意图漂移**：脚本化模型一定通过；真实模型要看实测（观察点：缺时间 → 回"下午三点到四点" → 是否仍办借教室）；
2. **记忆带槽位后的副作用**：被取消轮现在会把槽位一起注入下一轮（**故意不过滤**，交模型判断）。观察点：改口新轮会不会被旧日期干扰（"不是周三，是周五"）；若体验变差 → 按方案 §五 单独回滚本项（过滤取消轮或降级为只带 intent）；
3. **对话变长**：每轮多两条历史（原话 + 锚点），注入上限（最近 6 轮）不变；观察点：长对话里模型是否被旧上下文带偏；
4. **调用次数未增加**：本次只改"给模型什么材料"，不改调用次数与追问上限（仍 ≤3 轮）。

## 六、回滚

五处代码均为**纯增量**（多给材料 / 多一个字段 / 换一个取值来源）：

- 回滚锚点：`beginResume` 恢复原来的两行 push、删掉 `#anchor`（提示词的纪律 8 可以留着，缺锚点时它不生效）；
- 回滚记忆槽位：`#chatSummary` 的 `tc.slots` 换回 `tc.chat?.slots`（回到"槽位恒空"的旧行为）；
- 回滚 `intentSource`：schema 的枚举校验与 `#decideUnderstand` 的 input 字段是可选增量，删掉不影响链路。

对状态机、判定层、对外接口**零依赖**。

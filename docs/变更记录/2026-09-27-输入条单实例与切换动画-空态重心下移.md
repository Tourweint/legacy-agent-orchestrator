# 输入条单实例与空态↔对话切换动画（2026-09-27）

## 背景

用户连续两轮反馈空态首页"还是太靠上"，并指出上一轮改动方向反了（12vh→10vh 是往上移）。本轮三点要求：
1. **组件合并**：底部 dock 与空态 hero 是两个 Composer 实例（v-if 互斥），有歧义，应合并为一个组件；
2. **位置大幅下移**："多往下移一点"，重心离开"靠中上"；
3. **切换动画**：从新对话 ↔ 之前对话来回切换时，输入条要有平滑动画（不是瞬间跳变）。

## 改动

**`ChatPane.vue`**：
- **单实例**：删除双 `Composer`（hero + dock v-if 互斥）与 `heroComposerRef`，改为**一个** `<Composer :variant="hasAnyTurn ? 'dock' : 'hero'">` 实例，`focusComposer` 单 ref。
- **绝对定位三层**：`hero-heading`（标题）/ `hero-chips`（示例）/ `composer-host`（停止条 + ErrorState + Composer）都改为绝对定位层（`.chat` 加 `position: relative`），top 值成组：
  - 空态：输入条 `top: 34vh`（标题 `34vh-38px`、chips `34vh+86px`，间距 8/16px 不变）；
  - 有对话（`.chat.has-turns`）：`composer-host` `top: calc(100% - 62px - var(--stop-h))`（底部 18px 留白；停止按钮出现时 `--stop-h: 34px` 整体上移）、宽度 `min(820px, calc(100% - 48px))`；
  - 标题/chips：`opacity` 220ms 淡出（`has-turns` 时 `opacity: 0 + pointer-events: none`，不卸载 DOM 才能过渡）。
- **过渡**：`composer-host` `transition: top 300ms, width 300ms`——空态 ↔ 对话态来回切换时输入条**平滑移动**（下移/上移）且宽度同步变化。
- `messages` 底 padding 改 96px（输入条不再占流，滚动到底不被遮）。

**`Composer.vue`**：
- **宽度上移**：`.composer.hero` 的 `width: min(64vw, 780px)` 删除（改 `width: 100%` 撑满），宽度由 `.composer-host` 控制——这样宽度才能和 top 一起过渡。
- **形态过渡**：`.composer` 加 `padding/border-radius/box-shadow 300ms` 过渡、`.input` 加 `line-height/font-size 300ms`、`.btn` 加 `width/height/padding 300ms`——hero（14px 内边距/大圆角/36px 行高/40px 按钮）↔ dock（6px/12px 圆角/32px 行高/32px 按钮）的形态变化与位置移动同步，无跳变。

## 验证

- 前端 `npm test` 10/10、`npm run lint:check`、`npm run build` 全绿。
- 浏览器 rAF 逐帧采样（26 帧）：
  - **下移**（空态→对话）：top 356→726px 连续推进、width 780→820 同步、标题 opacity→0；
  - **上移**（对话→新对话）：top 821→432px 连续推进、width 820→780 同步、标题 opacity 0→1（淡入）；
  - 全程无跳变、无两个输入条并存（`document.querySelectorAll('.composer')` 恒为 1）。
- 空态重心：输入条顶 40%、标题 36%、chips 底 57%、组重心 47%（此前 31%——大幅下移，接近正中偏下）。

## 尚存说明

- 34vh 的重心 47% 是否合适请用户过目；要再上/下一点改 `.composer-host`/`.hero-heading`/`.hero-chips` 的 `34vh` 三处（或抽成变量）即可。
- 480px 窄屏断点：hero 形态 padding 收窄逻辑保留；dock 宽度由 `calc(100% - 48px)` 兜底。

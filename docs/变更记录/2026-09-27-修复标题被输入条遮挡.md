# 修复标题被输入条遮挡（2026-09-27）

## 背景

用户澄清上一轮"对话栏把'预约教室，从这里开始'挡上了"的具体所指：**是输入条本身把标题挡住了**（不是左栏）。上一轮误判为"hero 输入条太厚太贴的观感"，只做了形态统一；本轮实测发现**真重叠**。

## 根因（实测）

- `.hero-title` 是 `<h2>`，**浏览器默认上下 margin 各 18.26px 未重置**；
- flex 容器 `.hero-heading` 的 `align-items: center` 对齐的是含 margin 的 h2 盒子，而 h2 的 `margin-top` 把标题文字往下推了 18px；
- 实测（1239×883）：heading 元素高 70px（= 标题 33px + 上下 margin 36.5px），`top: calc(34vh - 38px)` 只留 38px → **文字底边 367px 压进输入条顶边 356px 之下 11px**——输入条确实把标题文字盖住了。

## 改动（`ChatPane.vue`）

1. `.hero-title` 加 `margin: 0`（+ 显式 `line-height: 33px`）——h2 默认 margin 不再破坏 flex 垂直对齐；
2. `.hero-heading` top `calc(34vh - 38px)` → `calc(34vh - 50px)`——重置后标题元素高 33px，-50px 使**文字底边到输入条顶净距约 17–19px**（不再贴、不再压）。

## 验证

- 前端 `npm test` 10/10、`npm run lint:check`（0 error，1 条既有 warning）、`npm run build` 全绿。
- 浏览器实测：标题文字底边 337px、输入条顶 356px → **净距 19px**（修复前 -11px）；heading 元素高 33px（margin 0 生效）；标题 y 310–335、输入条 y 363+，视觉分离清晰。
- 动画与其余布局不受影响（chips 仍 34vh+62px）。

## 经验

绝对定位层的"元素顶部间距"不等于"文字到目标元素的间距"——`<h2>`/`<p>` 默认 margin 会把文字在元素内下推，必须显式 `margin: 0` 或按文字底边（Range rect）实测校准。

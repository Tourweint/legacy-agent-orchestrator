## 三、Gate 2 实测结果（2026-09-25，复位基线上的真实调用 + 源码核对）

环境：JDK 17.0.8 + MariaDB 12.1 + Redis 8.10（本机），复位至种子基线（classroom=7 / seat=247 / reservation=86 / maintenance_window=2 / user=15 / system_config=23）。全部结论有 HTTP 调用与源码双证据；测试后已复位，`mock-legacy/` 源码 0 改动。

### 3.1 J3：预约记录有效状态集合与记录类型过滤（影响查证/补偿两条链路）

| 问题 | 实测结论 |
|---|---|
| 状态枚举 | 仅 **`ACTIVE / CANCELLED / EXPIRED`**（`ReservationStatus.java`）。EXPIRED 由定时任务每 60s 把 `end_time` 已过的 ACTIVE 置位（实测短时预约 #117 到期自动变 EXPIRED） |
| 有效集合 | **生效中 = 仅 ACTIVE** |
| 全量列表 | `GET /admin/reservations` 无参返回**全部状态全部类型**：复位态 86 = CLASSROOM 23（12 取消/11 过期）+ SEAT 63（50 取消/13 过期），ACTIVE=0；支持 `?status=ACTIVE` 过滤 |
| mine | `GET /reservations` **只返 ACTIVE**（复位态 0 条）；另有 `/reservations/history` 返非 ACTIVE（**登记为存在但不纳管**） |
| 撤销记录留存 | **留存**：撤销后全量列表条数不减（86→建 2 条变 88→撤销后仍 88，CANCELLED）；mine 不可见 |
| 类型归并 | CLASSROOM 行按 `resource_id`、SEAT 行按 `classroom_id`（SEAT 行 100% 带该字段）参与教室级占用判定（决策 C9） |
| 占用谓词 | 与存量 SQL 对齐：`status='ACTIVE' AND start_time < 申请end AND end_time > 申请start` |
| keyword | 实测 `keyword=4` 命中 **16 条**——`user_id/resource_id/reason` 三字段 CAST 模糊匹配，禁止精确过滤（原有结论强化） |
| **更正旧载** | 基线文档与第 08 章原称"86 条预约中**混有 20 签到、15 用量**"——**错误**：签到 20 / 用量 15 在**独立表**（`reservation_attendance`/`reservation_usage`），预约表 86 行全部是预约，**不会混入任何列表接口** |
| 87/86 之谜 | 87（2026-09-24 旧载）= 86 种子 + 当次创建并撤销、仍留存的 #115。阈值余量论证统一以 **86** 为复位基数 |

### 3.2 J4：单次/单日预约时长上限

- 配置：单次 A/B/C = **360/180/120 分钟**，单日 720/540/480；A≥80 分、B≥50；可预约时段 07:00–22:30。
- **关键：TEACHER 在服务层豁免全部时长校验**（单次直接放行、单日取 `Integer.MAX_VALUE`）；实测教师 7 小时预约成功（#118，已清理）。
- → **主链路（TEACHER 教室预约）归一化不做时长截断、提交前不做时长校验**（第 08 章新增 §7.5）。学生座位预约才受限，超限返 `200+400`。
- 附带规则：预约不得跨**北京自然日**（`reserve_date` 按 UTC+8）、开始时间必须在未来；座位预约另有 24h 提前窗口，教室预约无此限制。

### 3.3 D10：撤销接口"不可撤销"返回码

| 场景 | 实测返回 |
|---|---|
| 撤销有效预约 | `200 + code 200`（SQL 条件 `status='ACTIVE' AND end_time >= UTC_TIMESTAMP()`） |
| 重复撤销（已 CANCELLED） | **`200 + code 400`**"该预约已取消" |
| 结束时间已过 | **`200 + code 400`**"历史预约不能取消"（实测：95 秒短时预约到期后取消） |
| 记录不存在 | **`200 + code 404`** |
| 并发状态竞争 | `200 + code 409` |

补偿收到 400/404 均非"撤销技术失败"：按 `recordId` 查证，CANCELLED/EXPIRED/查无此 id 一律判"撤销已生效"；仅查不清或 id 未知落三级处置。

### 3.4 C19：节次与钟点映射

**存量系统无节次表、无节次枚举**；预约时间是自由 `OffsetDateTime` 区间。前端仅统计页有"上午 7–12 / 下午 12–18 / 晚上 18–22"三分口径。→ 归一化简化为三段区间（K2 拍板值），不精确到节。

### 3.5 顺带实测项

| 项 | 结论 |
|---|---|
| **C8** 重叠边界 | **不含边界**：13:00–14:00 存在时 14:00–15:00 紧邻预约成功（#116），13:30–14:30 返 409；全部冲突 SQL 为严格不等号（新增第 06 章 §6.4） |
| **C1** 教室 status | 7 间全 `ENABLED`、无空值；"空值视为启用"保留为防御口径 |
| **C4** 维修状态 | 枚举仅 ACTIVE/CANCELLED（无过期作业）；失效集实测 `{CANCELLED}`，防御扩展保留 |
| **C2** 候选上限 | 数智楼 5 间（48/48/55/32/9），扣除主角候选池 ≤4 → **K=5**，降级 3 轮足够 |
| **B3** 响应时间 | admin 列表（86 行）本机 10 次 avg **14ms**/max 17ms → 写超时初值 3s（约 150 倍余量），实现期复标 |

| 维修窗口链路 | ADMIN 创建 ACTIVE 窗口成功后，该时段 `reserved_seats` 返全量 55 座位；DELETE 置 CANCELLED——第 3 幕数据构造路径走通 |
| **L-404** 资源不存在码分叉 | GET 详情不存在=**400**；创建时教室不存在、撤销时记录不存在=**404**（同语义两码）→ W 表新增 W13 |

### 3.6 ⚠️ 实测推翻演示第 4 幕前提（三审最重要的收口之一）

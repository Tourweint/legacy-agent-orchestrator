## 一、评审背景与方法

一审（`2026-09-25-架构一审-方案评审与回填修订.md`）问的是"**照着现文实现会不会卡住**"，结论是"方案成熟，但 6 处规格缺口已回填"。二审的问题换了：

> **现在能不能直接开工？如果不能，缺的是"写文档"还是"做决定/做实测"？**

这个区别很重要：一审之后方案不再有"设计错误"，但可能存在**回填引入的新矛盾**、**一审未覆盖的实现级契约缺失**，以及**只能靠实测或拍板才能定的项**。二审要把后两类**与文档缺陷明确分开**——因为它们的处置方式完全不同（前者改文档，后者要么拍板、要么先跑起来）。

方法：以"实现者视角"精读一审回填后的全部文本，并做三类专项推演：

1. **三条链路的终态可达性**——幂等查证、补偿、命题校验，各自的每一个出口是否都有明确定义的终态？有没有"卡在半路"的路径？
2. **状态转移表的闭合性**——对每个非终态，是否每种**理论上会发生**的事件都有落点？"未列出的边一律非法"这条规矩下，有没有"实际会触发但表上无路"的组合？
3. **契约完备性**——阶段 0（配置数据与证据层）与阶段 4（对接前端）的交付物，是否已经细到"可以开始建文件"？

同时逐条核对一审的 6 处回填是否**自洽**（回填常常只改一处、漏改引用它的另一处）。

## 二、总体结论

**方案主干依然站得住，可以进入实施——但必须先完成 §八 的"开工 Gate"。**

三点结论：

1. **一审未发现的设计错误，二审也未发现。** 六命题逼出的分层、三值语义、查证消解歧义、"目的"第三维、事实/命题解耦、可控混沌，这几条主干在实现视角下依然自洽。
2. **问题集中在"一审回填的后半段"**：一审把决策落进了文档，但有几处只落了**一半**——决策落了、事件没落；事件落了、引用它的那一处没改；改了内容、没改计数。二审发现 **5 处回填不完整或引入新矛盾**（§三，含 2 处 P0）与 **9 处一审未覆盖的实现级缺口**（§四，含 1 处 P0、6 处 P1），其中 P0 是"不修则无法编码"。
3. **"还有一些没办法处理的问题"被二审核实为三类，且都不是文档缺陷**：需实测（20+2 条）、需拍板（J1–J7 + K1–K6）、环境与外部依赖。**二审已为每一条给出"实测前的占位口径"或"倾向值"**，因此它们**不阻塞开工**，只需要在 §八 的 Gate 里安排执行时机。

## 三、发现 A：一审回填不完整或引入的新矛盾（5 处，已全部修正）

### A1（P0）★ 决策 C17 的"I1 豁免"在状态机上没有落脚点，且两章口径互相矛盾

一审把 C17（`P-NOT-ALREADY-MINE` 事实不可得时继续提交）落到了基线文档的"I1 显式豁免条款"与第 08 章的命题卡，**但没有落到状态机**：

- 第 04 章 §5.2 的 `VALIDATING` 行只有 `PROPOSITIONS_OK / FAILED / DEGRADABLE_CONFLICT / CHECK_ONLY / ALREADY_DONE` 五列——"命题不可得"这一判定结果**没有列、也没有边**；
- 第 08 章 §三 又写着"不可获得 → 结论是'无法确认'……**前者是 `UNRESOLVED`**"——而 §5.1 的 `P-NOT-ALREADY-MINE` 卡片写的是"**继续提交**"。

于是实现者面对一个真二选一：全部落 `UNRESOLVED`（违反 C17），或全部继续提交（违反 F3/F6 的"必须中止"）。

**修正**：判定阶段（`VALIDATING`）**尚未发出任何副作用**，此时"查不到某份事实"不构成"状态未知"，落 `UNRESOLVED` 过重。据此统一为三分（第 08 章 §三 新表）：

| 命题声明的事实不可得处置 | 结论 | 落点 |
|---|---|---|
| 保守拒绝（F1 / F3 / F6 类） | 无法确认 | `REJECTED`（**新事件** `PROPOSITIONS_UNCONFIRMED`，第 04 章 §5.2 新增列） |
| 可继续 + 显式豁免（**仅** `P-NOT-ALREADY-MINE`，C17） | 无法确认（豁免继续） | `SUBMITTING`，**经 `PROPOSITIONS_OK` 的豁免载荷**（不新增入边，保住自检项 5） |
| 降级交叉印证（F4 不可得 → F5+F3） | 仍不确定则回到第一行 | 同第一行 |

**唯一落 `UNRESOLVED` 的"无法确认"只在收敛阶段**（`VERIFYING` 查不清）——二者的分界就是"有没有已经发出、状态未知的副作用"。

### A2（P0）★ 用户取消的"无边"与"空格即非法"直接冲突

一审回填的第 04 章 §5.9 写 `SUBMITTING / JUDGING / VERIFYING` 的取消去向是"**无边（取消不生效）**"，而 §5.6 明定"**转移表中该格为空 = 非法转移 → 抛错并落 `UNRESOLVED`**"。实现者按哪一条都错：用户在提交中点取消，应当**忽略并继续**，却会落 `UNRESOLVED`。

**修正**：引入**"忽略型无边"**这一显式分类（§5.6 新增判例行 + §5.9 逐格标注）：忽略型无边**不属于非法转移**，处置是"记录一条审计条目、不改状态、继续流程"。同时 §5.9 明确"**未列出的其他事件仍然是非法转移**"。第 13 章 §十 补红线第 30 条（把忽略型无边判成非法转移）。

### A3（P1）§3.1 的"唯一入边来源 / 允许的出路"与转移表三处不符

一审给 `IDLE` 加了 `START_STRUCT → RESOLVING`、给 `VERIFY_FOUND` 拆了载荷，但 §3.1 的**索引列**没跟上：

| 状态 | §3.1 原文 | 与实际转移表不符之处 |
|---|---|---|
| `RESOLVING` | 入边 = `UNDERSTANDING` | 漏记一审新增的 `IDLE --START_STRUCT-->` |
| `GATHERING` | 入边 = `RESOLVING`、`DEGRADING` | 表中**没有** `DEGRADING → GATHERING` 这条边（只有 `DEGRADE_ACCEPTED → VALIDATING`）——即"降级后直接重验命题、事实沿用旧的" |
| `VERIFYING` | 入边 = `JUDGING`、`SUBMITTING` | `CALL_UNKNOWN` / `CALL_CONFLICT` **从 `SUBMITTING` 直达**，`JUDGING` 行没有这条边 |
| `JUDGING` | 出路含"不确定" | 三值的"不确定"在 `SUBMITTING` 层就分流到 `VERIFYING`，`JUDGING` **只见二值** |
| `COMPENSATING` | 入边 = `JUDGING` | 漏记"补偿目的下的成功收敛"（§5.7），也漏记 `VERIFY_FOUND`（补偿语境） |

**修正**：四行全部对齐，并新增一条维护规则——**§3.1 是索引、§五 是权威，加边/改边必须同时改两处**。

**连带修正（这一处比"索引不同步"严重）**：`GATHERING` 的来源列早就含 `DEGRADING`，第 08 章 §6.3 也写着"降级换教室时会对**每个候选**重复收集一轮"，但 §5.4 的边却写成 `DEGRADE_ACCEPTED → VALIDATING`（**只重验命题、沿用旧事实**）。换教室时部分事实与教室无关、勉强能用；**换时段时必然是错的**——F3/F4/F6 都随时间变化，等于"用上午的事实回答下午的问题"。故改为 **`DEGRADING --DEGRADE_ACCEPTED--> GATHERING`**（先重取事实、再全量重验），并同步第 08 章 §8.2 的标题与规格。

### A4（P1）"换时段必须由用户确认"没有落点

第 08 章 §8.1 规定降级可"换时段"且**必须由用户确认**，但第 04 章 §5.4 的 `DEGRADING` 只有 `DEGRADE_ACCEPTED → VALIDATING` 与 `DEGRADE_EXHAUSTED → REJECTED` 两条出边——**没有任何一条边能让系统"停下来问用户"**。

**修正**：新增事件 `TARGET_CONFIRM_NEEDED`，边为 `DEGRADING → AWAIT_CLARIFY`；用户确认后走已有的 `AWAIT_CLARIFY → UNDERSTANDING` 重新理解（**新时段的事实因此由常规收集路径自然取得**，不需要额外机制）。同时明确：**换时段确认不消耗"追问 3 轮"的额度**（它不是槽位不全）——见 §5.5 新增注。换教室**不经过**此边。

### A5（P1）补偿重试上限（决策 D8 = 1 次）没有落表，且与"查证 2 次"的关系未定义

`COMPENSATING → SUBMITTING → JUDGING / VERIFYING` 在补偿语境下是**成环**的，仅靠 40 步兜底；D8 的"1 次"只写在决策汇总里。

**修正**：§七 循环表**新增"补偿重试（目的 = 补偿撤销）：1 次"一行**，并明确"**与正向的查证 2 次是两个独立计数器**，各自在自己的目的下计数"；§5.7 对照表补两行（正向/补偿各自达上限 → `UNRESOLVED`）。

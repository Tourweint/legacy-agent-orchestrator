# P1 安全与鲁棒性修复（代码审查报告 6 项 P1 闭环）

> **文档性质：变更记录（带日期，追加不改写）。时点：全方位测试之后——依据"竞赛评委 + 资深系统工程师"双重视角的代码审查报告，对 6 项 P1 级问题一次性修复并验证。所有改动均在 `orchestrator/src/access/` 层，未触碰编排核心、判定层、接触层或存量系统。**

---

## 一、背景

全方位测试通过后，依据一份专业代码审查报告（"竞赛评委 + 资深系统工程师"双重视角），识别出 6 项 P1 级问题，集中在接入层（`src/access/`）的运行时治理、安全边界和并发一致性。这些问题不影响核心业务逻辑的正确性，但会导致：异常输入下任务悬空、SSE 偶发丢事件、超大请求内存耗尽、跨时区部署行为不一致、长时间运行内存泄漏、端口暴露后无访问控制。

| # | 问题 | 位置 | 违反的不变量/原则 |
|---|---|---|---|
| P1-1 | 异步任务异常可能悬空（Promise reject 后任务停留在 running） | `http-server.js` POST /api/tasks | I3（每次调用必须有唯一结论） |
| P1-2 | SSE 重放存在竞态丢事件（先重放再订阅，中间事件丢失） | `http-server.js` GET /events | 可追溯性（核心卖点） |
| P1-3 | 请求体没有大小限制（readBody 无限累积） | `http-server.js` readBody() | 资源治理 |
| P1-4 | 结构化时间输入不严格要求时区（new Date() 接受无时区字符串） | `http-server.js` validateTaskBody() | UTC 时间口径（第 06 章） |
| P1-5 | 任务存储无限增长（无 TTL、无最大任务数、无清理） | `task-store.js` | 资源治理 / 隐私 |
| P1-6 | 对外接口没有认证，且 CORS 全开放（`*`） | `http-server.js` / `main.js` | 安全边界 |

## 二、修复内容

### P1-1：后台任务异常统一收敛

- 新增 `runTaskSafely(runner, taskId, chain)` 包装函数，统一捕获后台 Promise 的同步异常与异步 reject。
- 任意异常发生时：① 写入证据链（action=`task-force-unresolved`，含异常 message）；② 生成终态事件（type=`terminal`，status=`unresolved`）；③ 将任务置为 `UNRESOLVED`；④ 关闭 SSE 流；⑤ 避免未处理 Promise rejection。
- 覆盖场景：未知意图、未知身份、编排层同步异常、LLM 客户端异常、配置缺失。
- 新增回归测试：`test/access/http-server.test.js` 中未知意图导致后台异常时必须终态。

### P1-2：SSE 重放与订阅原子化

- 改为"先订阅 → 取当前 seq 快照 → 重放历史"的快照点分界模式。
- 订阅只推送 seq > 快照点的新事件；重放只写 seq ≤ 快照点的历史条目。
- 重放和订阅之间不丢事件、不重复事件。
- 新增回归测试：SSE 重放与实时订阅并发插入事件。

### P1-3：请求体与字段长度限制

- `readBody()` 添加 64 KB 上限，超限立即销毁请求并返回 `413 Payload Too Large`（code=4130）。
- 新增 7 项字段长度限制：intentId≤128、identity≤64、reason≤4096、resources≤10 个、building≤64、roomNumber≤32、text（chat/reply）≤4096。
- 超限返回 HTTP 400 + 对应错误码。

### P1-4：严格 UTC 绝对时刻校验

- 新增 `parseUtcInstant(s)` 函数，只接受带时区的 ISO 8601 字符串（`Z` 或 `+08:00` / `-07:00` 偏移）。
- 拒绝 `2026-09-30T14:00:00` 这类无时区字符串（不同部署环境下可能按本地时区解释，违反 UTC 口径）。
- 统一复用 `canonical/time.js` 的解析函数，业务代码不直接 `new Date()`。
- 新增测试：API 层"无时区输入必须拒绝"。

### P1-5：任务存储 TTL 与内存上限

- `TaskStore` 重写，新增：
  - 最大任务数 1000（超限拒绝新任务，返回 503）
  - 终态任务 TTL 30 分钟
  - 挂起任务 TTL 1 小时
  - 每 5 分钟定期清理过期任务
  - `close()` 方法（停止清理定时器，供测试和优雅退出）
- 证据链随任务一起清理；原始模型输出不单独保存（已在证据链中净化）。
- `/api/health` 的 `tasks` 字段反映当前在册任务数。

### P1-6：安全边界收紧

- CORS 从 `Access-Control-Allow-Origin: *` 改为显式来源 `http://localhost:5173`（`ORCH_CORS_ORIGIN` 环境变量可覆盖）。
- `main.js` 默认绑定 `127.0.0.1`（`ORCH_BIND_HOST` 可覆盖），不监听所有网卡。
- 文档明确声明：8090 端口不可直接暴露公网；生产部署需通过反向代理处理认证。
- 任务访问暂不绑定创建者身份（单用户演示场景，边界文档 §四），但已为后续多租户预留接口。

### 附带修复：SSE 帧去掉 `event:` 行

- 发现 SSE 帧中包含 `event: <type>` 自定义字段时，前端 `EventSource.onmessage` 不触发（浏览器将其视为命名事件，需用 `addEventListener(type, ...)` 监听）。
- 去掉 `event:` 行，使用默认 message 事件，前端 `onmessage` 正常接收。
- 事件类型仍在 `data` JSON 的 `type` 字段中，不影响语义。

## 四、影响范围

- **修改文件**：`orchestrator/src/access/http-server.js`、`task-store.js`、`main.js`、`event-stream.js`
- **未修改**：编排核心（`orchestration/`）、判定层（`judgment/`）、接触层（`contact/`）、理解层（`understanding/`）、混沌模块（`chaos/`）、配置（`config/`）、存量系统（`mock-legacy/`）
- **API 行为变化**：见 `docs/基线文档/对外接口清单.md` 2026-09-26 变更登记
- **向后兼容**：正常路径的请求/响应格式不变；仅异常输入（超大请求、无时区时间、跨域非白名单来源）的行为收紧

## 五、回滚建议

- 所有改动集中在 `src/access/` 层，回滚只需恢复这 4 个文件的修改前版本。
- 不建议回滚 P1-1（异常收敛）和 P1-2（SSE 竞态）——这两项直接影响 I3 和可追溯性，是竞赛演示的核心卖点。
- P1-3/P1-4/P1-5/P1-6 为安全与资源治理，回滚后系统功能正常但存在已知风险。

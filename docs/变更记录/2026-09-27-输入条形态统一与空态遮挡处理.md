# 输入条形态统一与空态遮挡处理（2026-09-27）

## 背景

用户验收单实例+切换动画后提出三点：① "对话栏把'预约教室，从这里开始'挡上了"；② "开启对话之后，它的对话框不一般大……本来相同的事物它变成不同了，非常奇怪"；③ "右边这个发送按钮太大了"。

浏览器实测（1239×883）确认根因：
- **问题 ②③ 是同一件事**：hero（空态中央）与 dock（底部）是同一个 Composer 实例，但形态差一大截——hero 高 70px / 按钮 40×40 / 内边距 14px 18px / 圆角 14px / 输入行高 36px / 图标 16px，dock 高 46px / 按钮 32×32 / 内边距 6px 12px / 圆角 12px / 行高 32px / 图标 14px。切换后"同一个输入框"变了样，用户直觉上无法接受。
- **问题 ① 的真相**：测量确认标题（left 629–879）居中于对话区（chat 268–1239），与左栏（0–268）**无任何重叠**；"挡"的观感来自 hero 输入条**太高太厚**（70px + 14px 内边距 + 大圆角），标题（318px）与输入条（356px）间距仅 8px，看起来像被"顶"着/压着。

## 改动

**`Composer.vue`（形态统一）**：
- 删掉全部 `.composer.hero` 覆盖块（padding 14px 18px / 圆角 14px / 行高 36px / 按钮 40×40 / 图标 16px / 阴影覆盖 / 窄屏 hero 规则）——hero 与 dock 共用一套：
  - padding `6px 6px 6px 12px`、圆角 12px、输入行高 32px；
  - 按钮**显式 32×32 圆**（`width/height: 32px; padding: 0`，hero 不再 40px）、图标统一 14px；
  - 阴影统一为**上下对称均匀淡影** `0 0 18px rgba(16,24,40,0.07)`（dock 不再用纯下沉的 `--shadow-xs`）。
- `variant` prop 保留（类名还在），但**形态已无差异**——切换动画 = 纯位置移动 + 标题淡出。

**`ChatPane.vue`（定位层适配）**：
- `.composer-host` 宽度统一 `min(820px, calc(100% - 48px))`（hero 不再 780px），删除 `width 300ms` 过渡（宽度不再变化）；`transition` 只留 `top 300ms`。
- `.hero-chips` top `calc(34vh + 86px)` → `calc(34vh + 62px)`（输入条矮 24px 后 chips 间距 16px 不变）。
- 标题 top `34vh - 38px` 不变（标题→输入条 8px 间距保持，用户此前口径"离太远"）。

## 验证

- 前端 `npm test` 10/10、`npm run lint:check`（0 error，1 条既有 warning：ThinkingBlock.vue 的 suspended 未用，非本轮引入）、`npm run build` 全绿。
- 浏览器实测 hero ↔ dock 逐项对比（**全部一致**）：

| 项 | hero（空态） | dock（对话态） |
|---|---|---|
| 组件高 | 46px | 46px |
| 按钮 | 32×32 圆 | 32×32 圆 |
| 宽度 | 820px | 820px |
| 内边距 | 6/6/6/12 | 6/6/6/12 |
| 圆角 | 12px | 12px |
| 输入行高 | 32px | 32px |
| 阴影 | 均匀淡影 | 均匀淡影 |

- 动画 rAF 逐帧采样：下移 356→707+px、上移 821→455+px 连续平滑无跳变；空态标题 opacity 1、`.composer` 恒 1 实例。

## 尚存说明

- 标题与左栏经测量**无重叠**（居中于对话区）；若用户说的"挡"是另一种状态（如左栏收起动画中、或窗口较窄），请指出具体场景再处理。
- hero 与 dock 形态一致后，切换时只剩位置移动 + 标题淡出（宽度/形态不再变）——这正是用户要的"同一个东西在移动"。

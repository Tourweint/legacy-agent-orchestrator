# 思考"书式展开"：分组、动画与标题（2026-09-27）

## 背景

用户反馈思考块的展开"太突兀"：点一下内容瞬间全部弹出（`v-show` 硬切换），且中间过程没有分类，挤成一串。用户给的改法方向：保留"思考"二字 + 显示耗时秒数；箭头放右侧；点击后平滑展开；中间过程"思考一条出来一条、执行一条出来一条"，按类型分成两个小节（"像书一样展开"）。

## 改动

1. **标题**：`ThinkingBlock.vue` 收起/展开统一为"**思考 · N 秒**"（`formatDuration` 实时耗时，运行中随事件流入秒数上涨；不再显示阶段名/失败数/步数——具体步骤展开后直接可见，标题保持简短）。无耗时数据（旧版历史会话缓存的事件缺 `at`）时只显示"思考"，不出现"思考 · 0 秒"。
2. **箭头移右侧**：标题与运行中脉冲点在左，chevron 殿后（原在最左）。
3. **展开/收起动画**：body 用 Vue `<Transition name="expand">` + `grid-template-rows: 0fr ↔ 1fr` 过渡（200ms + 标准缓动，配淡入淡出）。grid 方案对内容高度不固定也自适应——再展开"其余 N 步/完整留痕"不会跳变；`prefers-reduced-motion` 时关闭动画。
4. **中间过程按类型分组**（书式第二层）：
   - 新建 `ThinkingGroup.vue`：小节容器（小标题 + 行列表 + TransitionGroup 逐条淡入——"思考一条出来一条"的节奏感）。
   - `useThinking.js` 的 line 增加 `type` 字段（keyLine 取事件 type；summaryLine 显式传 `'proposition-judged'` / `'call'`）；分组语义**由阶段改为类型**：`call` → "执行了什么"，其余（decision / proposition-judged / uncertain）→ "思考了什么"。查询类调用常发生在判定阶段（P2），按阶段分会把"调用 3 次"错误归入思考组。
   - 执行组行隐藏阶段名（`ThinkingLine.vue` phaseName 为空时不渲染）："判定 ✔ 调用 3 次"既重复又违和，改为"✔ 调用 3 次，全部成功"。
5. **兜底**：`visibleLines` 焦点行为空时（旧版历史会话缓存的事件无 focus 行）退回全部行，避免"展开后只见按钮不见内容"。

## 验证

- 前端 `npm test` 10/10、`npm run lint:check`、`npm run build` 全绿（useThinking 仅加字段，单测按 text/phase/focus 断言，不受影响）。
- 浏览器端到端：查询任务运行中"思考 · 0.1 秒"逐条浮现（理解行 → 调用行）、两组合适分列；终态自动收起；点开平滑展开，"思考了什么"（理解 ✔ 识别为…）与"执行了什么"（✔ 调用 3 次，全部成功）分节清晰；"其余 N 步 / 查看完整留痕"正常。

## 尚存说明

- 历史会话（localStorage 缓存）耗时缺 `at` 时标题仅"思考"；属旧数据兼容预期。
- 秒数依赖事件自带 `at`；单机演示任务通常 < 1 秒，显示"0.1 秒"为真实值。

## 二、G-登录 开工小 Gate：实测结论（三审 §八 要求"不实测不许写"）

实测方式：`orchestrator/scripts/gate-login.mjs`（可复跑；只做登录/登出/查会话，不改业务数据，结束撤销自建设备会话）。原始输出见 §四。

| # | 待验（三审 §八 G-登录 + 能力清单 §六） | **实测结论** |
|---|---|---|
| 1 | 存量登录接口返回结构 | `data = { accessToken, refreshToken, userInfo }`；`userInfo` 含 `role / creditLevel / maxSingleReservationMinutes / dailyReservationLimitMinutes / seatReservationAdvanceHours`；access token 255–257 字符、**默认有效期 30 分钟** |
| 2 | 是否存在刷新令牌接口 | **存在**：`POST /auth/refresh` 可用，**刷新令牌轮换**（返回新 refreshToken），**旧的一次性作废**（再用返回 `code 401 refreshToken 无效或已过期`） |
| 3 | 同一账号重复登录是否会踢掉前一个 | **同 deviceId 重登：旧 access token 仍然可用**（不失效、不占新名额）——录制时重复登录不会打断已在跑的任务 |
| 4 | 设备会话上限与被踢表现 | 上限 3 生效：连续 4 个不同 deviceId 后，**最早的 2 个令牌被淘汰**，被踢后调用返回 **HTTP 401 + 业务码 401「未登录」**；`GET /auth/devices` 只剩 3 条 |
| 5 | 缺 `X-Device-Id` 会怎样 | 登录**照样成功**，deviceId 回落 `unknown-device`——多个无头登录会共享同一设备名额，是隐性坑（已登记注册表 `legacyNotes`） |
| 6 | 密码错误的表现 | **HTTP 200 + 业务码 401「用户名或密码错误」**（注意：不是 HTTP 401）；被踢则是 HTTP 401——两者形态不同，上游映射必须分别处理 |
| 7 | 登出后 access token 是否立即失效 | `POST /auth/logout` → 200；**原 access token 立即 401** |
| 8 | 教师个人时长上限字段 | 教师登录也返回 `maxSingle=360 / daily=720 / seatAdvanceH=24`（**不是 null/0**）→ "教师豁免时长校验"是**业务校验层面的豁免**，不是"字段为空"；C9/C12 的解释话术不能拿字段值当依据，须另找判据（已登记给 G-C9/C12） |

**由此推翻的两条既有文档结论**（诚实登记）：
1. 一/二审结论"存量系统**没有**刷新令牌接口"——**错的**。该结论正是三审"会话内存保存明文密码"的唯一理由；实测既然有刷新令牌且会轮换，实现改为**刷新令牌续期**，密码不落内存。
2. 对外接口清单原写"登录响应含 `user`、无刷新令牌"——已按实际契约修订。

## 三、与评审方案的两处偏离（需作者知悉）

| # | 方案原文 | 实现 | 为什么 |
|---|---|---|---|
| 1 | 三审拍板：**会话内存保存密码**用于自动重登（因"无刷新令牌接口"） | **不存密码**，改用刷新令牌续期一次；续期失败 → `4011 登录已失效，请重新登录` | 实测刷新令牌存在且轮换。存明文密码是"为了稳定性牺牲安全"，而真实约束并不存在——按 P1（展示是唯一得分项）也更好讲："我们不存你的密码" |
| 2 | 决定 6 提"令牌过期自动重登" | 会话续期 = 刷新令牌；**单飞**（同一用户并发续期只发一次刷新请求），避免轮换令牌被并发用掉 | 轮换令牌一次性作废，并发刷新会让后到者拿到失效令牌 |

## 十、C8 改期（同日续做，第 1 组第二项能力）

**它为什么比 C7 贵**：改期是**两次写入**（先建新、后撤旧），而引擎此前一次运行只有一个提交步。

| # | 改动 | 位置 |
|---|---|---|
| 1 | 提交态支持**写步骤序列**：`role: submit`（正向写入，成功即进补偿清单）与 `role: finalize`（收尾写入，如"撤旧"），按声明顺序执行 | `run-engine.js` SUBMITTING |

## 六、踩坑登记（写给后来的自己）

1. **Gate 脚本死循环**：`gate-login.mjs` 清理段"遍历 `createdDevices` 的同时又往该数组 push"，`for...of` 边遍历边追加 → 永不结束，输出文件涨到 1.8 MB、连滚 40 分钟，只能人工杀进程。**已修**（遍历快照 + 登录时留存 token 不再重登），并给脚本加了**全局看门狗**（默认 90 秒硬超时、打印"卡在哪一步"、非零退出）与**逐步骤打印**。纪律：跑脚本一律带超时包装，不允许无声长跑。
2. **Windows PowerShell 5.1 读 `.ps1` 按 ANSI 解**：无 BOM 的 UTF-8 脚本里中文注释会变乱码并导致语法错误。新增的 `engine-smoke.ps1` 已加 UTF-8 BOM；以后加 `.ps1` 必须带 BOM。
3. **抓凭证的正则别按裸 `NAME=` 匹配**：`start-all.bat` 顶部注释里也出现 `ORCH_LEGACY_ADMIN_PASSWORD=...` 的说明文字，裸匹配会先命中注释、取到说明文字而不是口令（实测因此得出"管理员登录失败"的错误结论）。已收紧为只认 `set "NAME=值"`。

# 2026-09-24 存量系统本地化接入与零侵入运行

> 类型：大改动（涉及运行方式、部署流程、认证与环境依赖）
> 关联基线文档：`docs/基线文档/存量系统改造说明.md`

## 一、变更背景

`mock-legacy/`（第三方开源项目 CampusClassroomReservationSystem）已放置到位并搭好仓库骨架，但**从未在本机成功运行过**：源码编译、数据库、缓存、运行配置全部未验证。

本作品的核心主张是「零侵入对接存量系统」。若不能先把这一点用实测钉死，后续所有关于"防腐网关""跨系统编排"的论述都缺少事实基础——因为一旦"偷偷改了"被指出来，作品的立论就塌了。

因此本次变更的目标有两个，且**优先级排序**为：

1. 先证明"不改动它也能跑起来"（零侵入可验证）
2. 再摸清它的真实接口行为（为接口注册表提供素材）

## 二、核心设计决策（需用户确认的项）

| 决策点 | 备选方案 | 选定 | 理由 |
|---|---|---|---|
| 运行配置怎么给 | ① 补一个 `application-local.yaml` 进仓库<br>② 用环境变量注入 | **②环境变量** | ①会在第三方仓库内新增文件，破坏"0 改动"的可验证性；②借用的是它自带 `docker-compose.yaml` 已有的同一套变量名 |
| 数据库选型 | ① 装 MySQL 8<br>② 用本机已有 MariaDB 12.1 | **②MariaDB** | 实测可零改动承接 MySQL 5.7 导出的建库脚本，省一次安装 |
| 是否装 Docker 一键起 | ① `docker compose up`<br>② 本机原生跑 | **②本机原生** | 本机 Docker 守护进程未运行；且本机 JDK 17、MariaDB、Node 已就位，原生启动更快、可控性更高 |
| 故障注入放哪 | ① 改被测后端加故障开关<br>② 网关层故障代理 | **②网关代理** | ①破坏零侵入；②既能造出"响应丢失"这一真实网络故障，又完全不碰它的进程 |
| 是否补上缺失的查询能力 | ① 给它加"按教室+时段查预约"的接口<br>② 不改，由编排层跨接口聚合 | **②不改** | ①把本作品最核心的命题（跨接口聚合才有答案）改没了 |

## 六、暴露的问题

1. **上游文档不可信**：`部署文档.md` 至少 6 处与实现不符（Base URL 前缀、默认账号密码、JDK 版本、配置文件位置等）。→ 已立为接口注册表的信息来源原则：**以代码与运行时实测为准，不采信自述文档**。
2. **早期设计假设错误**：曾假设"重复提交会产生重复记录"，实测被推翻。→ 已更正为"409 是歧义信号"，幂等命题由"防重复"调整为"消解歧义"，详见改造说明 §7.3。
3. **演示场景需重新对齐真实数据**：不存在"302 教室"；两条维护窗口均为 `CANCELLED`。→ 演示台词与数据准备方案需调整。

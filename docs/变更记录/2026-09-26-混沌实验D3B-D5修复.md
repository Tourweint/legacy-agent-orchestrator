# 混沌实验 D3-B / D5 修复（实验脚本设计缺陷修正）

> **文档性质：变更记录（带日期，追加不改写）。时点：全方位测试中发现混沌实验 D3-B 和 D5 失败/不稳定之后——经根因分析，两项均为**实验脚本的设计/参数 bug**，而非系统功能问题。修复后混沌实验 8/8 全部通过，失败项 0。**

---

## 一、背景

全方位测试中运行 `npm run experiment`，发现两项异常：

| 实验 | 期望 | 实际 | 性质 |
|---|---|---|---|
| **D3-B**（409 之他人占用） | REJECTED ×3（命题层检测到他人占用，拒绝任务） | DONE ×3（任务正常完成，未检测到占用） | 确定性失败 |
| **D5**（补偿失败登记） | UNRESOLVED ×3（补偿撤销两次失败 → 人工介入） | 第 1 次 REJECTED，第 2/3 次 UNRESOLVED | 不稳定 |

## 二、根因分析

### D3-B：时段超出座位预约 24h 可预约窗口

**实验设计**：用学生身份预置一个座位占用（`edu.reservation.seat.create`），然后用教师身份申请同一时段的教室，期望命题层 P-SLOT-FREE 检测到占用并 REJECTED。

**问题**：实验脚本使用 `beijingSlot(1, 13, 14)` = 明天 13:00 北京时间 ≈ 当前时间后 **24.5 小时**。

存量系统的**座位级预约可预约上限为 24 小时**（J4 实测确认）。该时段超出范围，学生预置座位预约返回：

```json
{"code": 400, "message": "当前预约时间超出可预约范围", "data": null}
```

**预置占用根本没创建成功**，命题层自然检测不到占用，任务正常 DONE。

**验证系统功能正常**：将时段改为当天 15:00（2.5h 后，在 24h 窗口内），学生预订座位成功后，教师查询 `reserved_seats` 返回被占座位 id=309，命题层 P-SLOT-FREE 正确拦截，任务 REJECTED。

### D5：第二间教室不存在，在 P2 被拦截，走不到补偿路径

**实验设计**：申请两间教室，期望第一间创建成功 → 第二间创建失败 → 触发补偿（撤销第一间）→ 补偿撤销两次失败（注入 400）→ UNRESOLVED。

**问题**：实验脚本使用两间教室：123（存在，classroomId=5）+ **999（不存在，classroomId=999）**。

第二间教室 999 不存在，在 P2 事实收集阶段调用 `edu.classroom.detail` 返回 404，F1（教室存在）不可得，命题层在 P2 直接 **REJECTED**，**永远走不到 P3 创建→补偿的预期路径**。

第 2/3 次因 999 查询偶发超时（而非 404）被降级处理，才侥幸走到 UNRESOLVED——本质是**依赖网络随机性的不稳定实验**。

## 三、修复内容

### D3-B：时段调整到可预约范围内

- `beijingSlot(1, 13, 14)` → `beijingSlot(0, 15, 16)`（当天 15:00–16:00，距当前约 2–3h，在 24h 窗口内且非即刻过期）
- 更新注释说明：学生座位预约可预约上限为 24h，day+1 13:00 距当前常 >24h 会被拒

### D5：第二间教室改为存在但创建失败，确保走到 P3 补偿路径

1. 将第二间教室从 999（不存在）改为 **222（存在，classroomId=4）**，确保 P2 不被拦截
2. 新增注入：`edu.reservation.classroom.create` 第 2 次调用返回业务码 400（第二间创建失败）
3. 保留原有的 `edu.reservation.cancel` 两次 400 注入（补偿撤销失败）

修复后的路径：
- 第一间 123 创建成功（第 1 次 create，无注入）
- 第二间 222 创建失败（第 2 次 create，注入 400）
- 触发补偿（撤销第一间 123）
- 撤销第 1 次失败（注入 400）→ 查证（verify-compensate）→ 撤销第 2 次失败（注入 400）
- 最终 **UNRESOLVED**（符合 I6：补偿失败必须登记人工介入）

## 一、变更背景

阶段 0–4 交付了确定性内核与对外入口（8090）。阶段 5 按 L5 契约交付理解层：自然语言 → 结构化意图（意图 + 原始槽位片段 + 置信度 + 超域标记 + 追问话术），并把第 04 章的 UNDERSTANDING / AWAIT_CLARIFY 两个状态真正接入运行引擎（此前仅有表与自检，运行引擎不产生这些状态的事件）。

**自测与烟测发现并修正的缺陷（5 个）**：
1. 聊天运行未播种资源目标时 `#doResolving` 读空对象 → 名字解析缺 building 崩溃（测试拦截）；
2. 教室名归一化丢弃裸房间号片段（"数智楼123和222"只解析出第一间）→ 增加楼栋继承；
3. 追问轮次耗尽误发 `CLARIFY_LIMIT`（表上该事件只从 AWAIT_CLARIFY 出）→ 非法转移自检语义拦下 → 改 UNDERSTAND_FAILED；
4. schema 与少样本自相矛盾（超域输出 intent: null 被拒）→ outOfDomain 豁免 intent 检查；
5. 查询意图 `degrade: null` 使聊天名字解析崩溃 → **resolution.candidatesFrom 与降级解耦**（意图计划与引擎同步修正）。

**烟测环境注意事项（登记）**：Windows Git Bash 的 curl 发送中文请求体时编码损坏（模型收到乱码）——烟测必须用 Node 脚本发送 UTF-8 请求，不是引擎缺陷。

**未验证项（如实登记）**：
- 置信度阈值 0.55 的样本标定（E1）与模型结构化输出稳定性的大样本验证（E4）——按三审 §七 留给实现期对应阶段；本阶段真实烟测样本量不足以标定。
- 换时段确认（TARGET_CONFIRM_NEEDED → AWAIT_CLARIFY 的"换时段"分支）仍留待阶段 8 演示定稿（当前聊天降级只换教室，时段时间不由系统改写）。
- 少样本集合的覆盖面（钟点解析"两点到四点"等表达）取决于演示脚本（E2），已留 slotHints 扩展位。
- D7 提示词对照实验（E6：提示词含接口 vs 不含）属阶段 6 实验。

## 五之二、模型对比实测（同日追加，E4 回填）

用户要求验证低成本模型可替换性。方法：同一提示词（从意图计划生成）× 4 用例（查询意图 / 借教室多间 / 缺槽位 / 超域）× 2 轮，对 `ORCH_LLM_MODEL` 注入的三个模型执行并按输出契约校验。

| 模型 | 通过 | 平均延迟 | 结论 |
|---|---|---|---|
| qwen-plus（默认） | 8/8 | ≈1.8s | 稳定 |
| deepseek-v4-flash | 8/8 | ≈2.6s | **稳定，可替换**（另经 runner 级聊天全流程验证：查询 DONE / 超域 REJECTED） |
| qwen3.8-flash | 8/8 | ≈3.7s | 稳定，可替换（延迟最高） |

**结论（E4 回填至决策汇总）**：结构化输出对"提示词零接口信息 + schema 校验 + 格式重试"这套契约不敏感——三个模型全部稳定，**换模型问题不大**；模型经 `ORCH_LLM_MODEL` 环境变量切换，默认 qwen-plus。E1（置信度阈值跨模型标定）与 E4 的大样本验证仍按三审 §七 留给实现期对应阶段。

# 2026-09-26 对话工作台界面重构（思考过程折叠 + 核心输出优先）

> **文档性质：变更记录（带日期）**。依据 [对话工作台界面方案](../设计方案/2026-09-26-对话工作台界面方案.md) 实现。
> **发起**：演示后的界面反馈——右侧轨迹面板与对话割裂、界面显挤；要求"像普通 IDE 那样：**思考过程默认隐藏、点开才看；结束后只展示核心输出；输出要区分重要与非重要**"。

## 一、一句话改动

**把"一屏塞满步骤"改成"先说结论，过程按需展开"**，并把界面收敛成单列对话工作台：

```text
┌──────────┬────────────────────────────────────────────┐
│ ＋ 新对话 │  校园教室代办        [教师] [☾] [退出登录]     │

│ · 借123   │   帮我借明天下午两点到四点数智楼123   ← 用户   │
│ · 查空闲  │   ▸ 思考过程 · 6 步 · 2.4 秒      ← 默认收起   │
│ 昨天      │   已办成                                     │
│ · 占座位  │   已为您订好数智楼123：2026-09-27 14:00–16:00， │
│          │   预约号 #120                      ← 核心输出   │
│          ├────────────────────────────────────────────┤
│          │  [ 继续说点什么，或接着办下一件…… ]   [ 发送 ]  │
└──────────┴────────────────────────────────────────────┘
```

**右侧轨迹面板整个去掉**（`TrajectoryPane` / `PhaseSection` / `ResultCard` 删除），步骤内联进对话。

## 二、三层信息的判据（本次改动的核心）

> **这条信息会不会改变用户下一步的动作？**

| 层级 | 判据 | 内容 | 默认 |
|---|---|---|---|
| **L1 核心输出** | 会 | 结论（含预约号与时段）· 拒绝理由与备选 · 追问 | **可见**（`AnswerBubble`） |
| **L2 关键过程** | 不会，但解释"为什么能/不能办" | 判定结论 · 调用结果 · 不确定 · **理解结果** | 折叠（`ThinkingBlock` 展开后的要点行） |
| **L3 留痕明细** | 只有审计价值 | 事实收集 · 内部决策 · 审计 | 再点一层"查看完整留痕" |

配套两条归并规则（**"输出结构化"的落点**）：**成功的只报计数**（`判定 5 项全部通过 ✓`）、**失败的逐条展开**；`fact-collected` 这类过程不进要点。

## 三、做法

### 1. 归并规则写成纯函数（唯一有逻辑的新代码）

`frontend/src/composables/useThinking.js` + `frontend/test/use-thinking.test.mjs`（**8 条单测**）：
把一轮事件折成 `{ lines（L2 要点，带 focus 标记）, details（L3 明细）, failCount, defaultMode, durationMs }`。

- **文案一律取自事件自带的 `text`**（引擎已产出人话）；本模块只做选择与归并，**不新造句子**——否则界面会长出第二份"阶段 → 文案"映射，和引擎的规则表必然漂移；
- **步数与耗时不依赖 `phase-start/phase-end`**（这两个事件在接口清单里标注"预留，尚未产出"）：步数＝事件条数，耗时＝首末事件 `at` 之差；
- 前端首次有测试基建：`frontend/package.json` 加 `npm test`（`node --test`，纯函数不需要浏览器环境）。

### 2. 默认展开状态（写死，避免"抖动"）

| 任务状态 | 折叠块默认 | 理由 |
|---|---|---|
| 运行中 / 挂起 | **全展开** | 用户要知道它在干什么、才好回答追问 |
| 办成（DONE） | **收起** | 结论已回答全部问题 |
| **办不成（REJECTED / FAILED）** | **部分展开**（失败链路 1–3 行） | 用户第一个疑问是"为什么不行" |
| 不确定 / 需人工（UNRESOLVED） | **部分展开** | 让用户知道系统在核对什么 |
| 被取消 | **部分展开** + `已停止 · 完成 N 步` | 如实说明停在哪，未做的步骤不假装完成 |

"部分展开"的显示集合 = `status ∈ {failed, uncertain, unavailable}` 的行 + **它们同阶段的上一条**（"判定 5 项，其中 1 项没通过"才是失败项的来处）+ 理解行。
**用户手动操作优先**：手动展开/收起过之后不再自动变化——读着读着界面自己动了，比"默认不展开"更糟。

### 3. 新增 / 改造 / 删除

| 动作 | 文件 |
|---|---|
| 新增 | `composables/useThinking.js`、`components/ThinkingBlock.vue`、`components/ThinkingLine.vue`、`components/AnswerBubble.vue`、`components/ConversationList.vue`、`stores/conversations.js`、`constants/display-names.js` |
| 改造 | `components/ChatPane.vue`（每轮改为 用户气泡 → ThinkingBlock → 追问 → AnswerBubble）、`components/TrajectoryItem.vue`（降级为 L3 明细行 + 文案常量改为共享）、`components/Composer.vue`、`App.vue`（双栏 shell） |
| 删除 | `components/TrajectoryPane.vue`、`components/PhaseSection.vue`、`components/ResultCard.vue` |

**`INTERFACE_NAMES` / `IDENTITY_NAMES` 从 `TrajectoryItem.vue` 提升为 `constants/display-names.js`**：它们现在同时被要点行、答案气泡、明细行用到，放一处才不会长出两份互相漂移的映射。

### 4. 左栏会话列表与本地留存

`stores/conversations.js`（Pinia + `localStorage`）：

| 决定 | 说明 |
|---|---|
| 存**轮次快照**（用户原话 + 事件 + 结果） | 不存这些，切过去的会话就是空的——与"切换方便"的初衷矛盾 |
| **不存证据链明细** | 体积最大且可重拉；拉不到时界面如实说"留痕已不在" |
| 按**登录用户名**隔离 | 同一浏览器换了人，不该看到上一个人的对话；退出登录只清视图、磁盘记录保留 |
| 上限：会话 30 / 每会话 20 轮 / 每轮 150 条事件 | 防 `localStorage` 撑爆；写盘 400ms 节流（一轮任务会持续吐事件） |

## 五、实现中修正的两处设计疏漏

1. **方案 §3.1 的"默认展开"判据有误**：若按"有重点行"判定，会把**办成**也判成部分展开（理解行永远是重点）→ 改为按**失败链行数**判定，并加测试盯住"办成不能被误判成没办成"。
2. **方案写"localStorage 只存元信息"与"切换方便"矛盾**（切过去是空的）→ 改为存轮次快照，并回头修正方案 §七 风险 3。

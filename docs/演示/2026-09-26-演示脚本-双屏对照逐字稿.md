# 演示脚本：双屏对照逐字稿（2026-09-26 重写版）

> **文档性质：演示脚本（docs/演示）。取代 [`2026-09-25-演示脚本-七幕逐字稿.md`](2026-09-25-演示脚本-七幕逐字稿.md)（旧版按"六项能力、无登录"的口径写，已被本版取代，留档）。**
> **本版相对旧版的三处变化**：
> 1. **双屏对照**成为标准动作——左侧是引擎的对话与轨迹，右侧是**存量系统自己的界面**（5174）。每幕的"办成了/没办成"都在存量系统里有一眼可查的对应物；
> 2. 能力面升级——新增**账号登录**、**管理我的预约（查/退/改期）**、**学生占座**；界面**零术语**（不再出现 P-xxx / R1 / F4 这类内部编号）；
> 3. 补进两条**实测硬约束**（座位预约只能提前 24 小时；座位号形如 `2-3`），话术按真实约束写，不赌运气。

## 演示前准备（按序执行）

```bash
# ① 复位数据（每次演示前与连续演示之间必跑；也保证第 10 项检查过）
bash deploy/scripts/reset-legacy-data.sh

# ② 一键起四个进程：存量后端 8080 / 编排引擎 8090 / 对话前端 5173 / 存量界面 5174
start-all.bat            # （或 start-all.bat legacyui 单独起存量界面）
#   存量界面若首次启动要先装依赖，那个窗口会自动 npm ci —— 稍等片刻

# ③ 演示前检查清单（15 项自动 + 1 项人工；含"存量界面在线"）
bash deploy/scripts/demo-checklist.sh

# ④ 幕间预置（走业务接口，不插库）：
bash deploy/scripts/demo-prepare.sh maintenance   # 幕 4 前：给 123 创建维修窗口
bash deploy/scripts/demo-prepare.sh occupy        # 幕 5 前：占用 123 下午时段
```

**开演前手动过一遍双屏**：
1. 左屏：教师 `233` 登录引擎（登录页有角色徽章；登录失败先看引擎窗口）。
2. 右屏：用 `233` 登录存量系统 →「我的预约」→ 此时应为 **0 条**（复位脚本保证）。
3. 幕间每跑完一幕，右屏点「刷新」即可看到最新状态（无需重新登录）。

## 第 0 幕 · 开场（30 秒）

**操作**：不操作系统。右屏停在存量系统的登录页；另开终端跑 `git status --short mock-legacy`，展示**空输出**。

> **逐字稿**：
> "这是我们的存量业务系统——Spring Boot + Vue 的校园教室预约系统，右边就是它自己的界面。**我们对它的改动量是零个文件**——git status 是干净的。我们没有改它一行代码，却让它长出了一个自然语言的接口。左边是我们做的编排引擎。接下来七分钟，左边每办成一件事，右边都能对上。"

**锚点**："不改它一行代码，让它长出自然语言接口；办成的事，右边对得上。"

## 第 1 幕 · 登录与身份（45 秒）【新增】

**操作**：左屏教师 `233` 登录引擎（右上出现角色徽章）；右屏用 `233` 登录存量系统 →「我的预约」（0 条）。

> **逐字稿**：
> "先说身份。引擎不替任何人办任何事——**你必须先用存量系统的账号登录**，你是什么角色，就有什么能力。所有写操作都以登录者本人身份发出；这是记录可追、责任可归属的前提。"

**讲解动作**：指左屏右上角的角色徽章；指右屏"教师 233"。

## 第 2 幕 · 正常链路 + 双屏对照（60 秒）

**操作**：左屏输入「帮我借下周三下午数智楼 123」。

**期望（引擎侧）**：
- 理解卡片显示 **"识别为「借教室」；条件：教室=数智楼123、日期=下周三、时段=下午"**（零术语——不再出现 intentId / 英文槽位键）；
- 轨迹 P1→P4 依次实时出现；P2 的依据芯片是**人话**（"判定 · 这个时段是空的"），身份徽章可见——查维修窗口时是**管理端身份**；
- 终态绿卡，**带预约记录号**。

**期望（存量侧）**：右屏「我的预约」点「刷新」→ **有效预约从 0 变 1**：「数智楼 123｜2026-09-30 13:00–17:00」。

> **逐字稿**：
> "注意右边的执行轨迹。判定『这间教室能不能借』需要三处事实——教室状态、时段占用、维修窗口，第三处只有管理员身份读得到——看轨迹里的身份徽章，收集事实时系统换了管理员身份。看结果卡，有记录号。现在切到右边——**存量系统自己的界面里，这条预约真实存在**。这不是我们造的假象，是它自己的数据库、它自己的界面在说这件事。"

**锚点**："办成的事，右边对得上。"

## 第 3 幕 · 幂等命中（45 秒）

**操作**：**原样再发一次**第 2 幕的请求。

**期望（引擎侧）**：终态绿卡（幂等命中）："已为您办妥：此事此前已办成（预约 #X），未重复提交。"

**期望（存量侧）**：右屏**仍是 1 条**——不是 2 条。

> **逐字稿**：
> "我原样再说一遍。注意它没有说『教室不可用』——占用者就是用户自己，那样说会误导用户去换教室。这是第一版踩过的坑：遇到重复申请就报『不可用』，用户真去换了。**设计是在真实反馈里收敛的**。再看右边——还是一条，不是两条。"

## 第 4 幕 · 跨域事实不可替代（60 秒）【智力高点】

**预置**：`demo-prepare.sh maintenance`（管理接口创建维修窗口）。**顺手在右屏展示**：管理端 `admin` 登录 → 维护管理 → 那个窗口**真实存在**。

**操作**：左屏输入「帮我借下周三下午数智楼 123」。

**期望**：终态红卡："该教室在这段时间处于检修安排中（起止时间），请改选其他教室"——**精确说出了原因与时间**。

> **逐字稿**：
> "刚才我用管理接口给这间教室登记了一个维修窗口——右边管理端里看得到它。现在再借它，系统没有笼统说『不可用』，它**精确说出原因：在检修，还给出窗口时间**。为什么做得到？因为**『整间被预约』和『教室在检修』，在它的源码里返回的是同一个值**。要区分这两者，只能换管理员身份去后勤域查——**跨权限域聚合不是我们的设计偏好，是不聚合就做不出正确判断**。"

**锚点**："『整间被预约』和『教室在检修』，它返回的是同一个值。"

**幕间**：`demo-cleanup.sh` 清掉维修窗口（脚本会撤销预约并清理生效窗口）。

## 第 5 幕 · 降级：它在替你试（45 秒）

**预置**：`demo-prepare.sh occupy`（占用 123 下午时段）。

**操作**：再输入「帮我借下周三下午数智楼 123」。

**期望**：终态"已办成：数智楼 222"，话术含尝试清单。**存量侧**：右屏「我的预约」→ 多出一条「数智楼 222」。

> **逐字稿**：
> "现在 123 被占了。它**没有直接失败**——自动尝试同楼栋、容量不降的候选：123 被占，试 222，55 座，可用，改订完成。**注意它没有降低容量要求——只换更大的，不换更小的；那不是降级，那是违背诉求。** 右边对得上一条 222。"

**锚点**："只换更大的，不换更小的。"

---

## 第 6 幕 · ★ 响应丢失（90 秒）【本场的核心】

**操作序列**：
1. `demo-cleanup.sh` 清掉第 5 幕的 222（也恢复 123 空闲）；
2. 布防一次 T5 注入：`node deploy/scripts/inject-once.mjs`（生成布防命令；**注入生效时轨迹条目带 ⚠ 注入徽章**）；
3. 输入「帮我借下周三下午数智楼 123」。

**期望（分三段指着轨迹讲）**：
① P3 出现**琥珀脉冲**："结果待确认，正在核对……"——不是失败、不是成功；
② P4：换管理端身份拉全量列表 → 按业务键比对 → **命中**（我写的、时段重叠）；
③ 终态绿卡："已确认此前提交成功（预约 #X），未重复提交"。

**当场取证（双屏）**：右屏管理端 `admin` → 预约管理 → 该时段 **恰好 1 条**（不是 2 条）。

> **逐字稿**：
> "刚才那次提交，请求真实到达了服务端、真实写进了库——但响应被我丢掉了。看界面：它显示的是**『结果待确认，正在核对』**——不是失败，也不是成功。然后它换了管理员身份去查证——命中一条，是我写的。最后它说：已办成，未重复提交。右边管理端里**只有一条**。**超时只说明『我不知道』，不说明『我没成功』。它没有重试，它先去查证了。** 一个只做接口封装的系统，这里会报错让用户重试——库里就是两条。"

**锚点**："超时只说明『我不知道』，不说明『我没成功』。" / "它没有重试，它先去查证了。"

**演示后**：立即撤防（重启引擎），清单复核。

## 第 7 幕 · 学生通道：占座与越权（60 秒）【新增】

**操作序列**：
1. 左屏右上角**退出登录**，改用学生 `abc` 登录——左栏的示例话术变了：出现**占座**，且**没有**"借整间教室"。
2. 输入「帮我借下周三下午数智楼 123」→ 红卡："整间教室的预约只能由教师提交，您的账号是学生身份。我可以帮您查这间教室的空闲情况，或者帮您排这个时段的座位候补。"（**拒绝发生在任何调用之前**——轨迹里零次调用）
3. 输入「帮我占今天下午数智楼 123 的 2-3 号座位」→ 绿卡"已为您占好座位（记录 #X）"。

**期望（存量侧）**：右屏退出、用 `abc` 登录存量系统 →「我的预约」→ 出现「**数智楼 123 2-3｜座位｜** 今天 13:00–17:00」，状态"待签到"。

> **逐字稿**：
> "换学生登录。第一句被拒绝了——不是报错，是**有依据的拒绝，还给了两条替代方案**，并且这次拒绝没有发出任何一次调用。第二句，学生通道：占一个座位。看右边存量系统——座位 2-3，今天下午，待签到。**同一个存量系统，教室是教师的能力，座位是学生的能力，权限边界来自它自己，不是我们发明的。**"

**实测约束（必须遵守，否则现场翻车）**：
- **座位预约只能提前 24 小时** → 演示话术必须用"**今天**下午"，说"明天"会得到真实拒绝（`当前预约时间超出可预约范围`）——那也是诚实行为，但没有可看的镜头；
- 座位号形如 **`2-3`（行-列）**，不是 "A3"；
- 学生 `abc` 是 A 档（单次 ≤360 分钟）："下午"（240 分钟）可行。

**锚点**："权限边界来自存量系统自己，不是我们发明的。"

**幕间**：`demo-cleanup.sh`（会把学生的座位预约一并撤掉）。

## 第 8 幕 · 管理我的预约：退与改期（60 秒）【新增】

**操作序列**（教师 `233` 已登录）：
1. 输入「我订了哪些教室」→ 只读回答，列出名下生效预约（含记录号与时段）。
2. 输入「把数智楼 222 那条改到周四上午 8 点到 12 点」→ 轨迹可见**先建新、后撤旧**两步写入；终态"已改期"，**名下仍是两条**（没有重复记录）。
3. 输入「把刚才那条退了」→ 若多命中，系统给出**候选清单**追问退哪条；唯一命中则直接撤销 + 复验。

**期望（存量侧）**：右屏「我的预约」同步刷新——改期后那条的时间变了、且**没有**残留旧记录；撤销后那条**消失**。

> **逐字稿**：
> "管理自己的预约——查、退、改。改期是两次写入：先建新、后撤旧，任何一步出问题都会被查证和补偿接住。**右边存量系统始终和左边说的对得上**——这就是可解释：每一步都能在两个屏幕上指给你看。"

**锚点**："每一步都能在两个屏幕上指给你看。"

## 风险预案（§六）

| 风险 | 预案 |
|---|---|
| 大模型不通/限流 | 切预置结构化任务（对话栏底部调试入口），说明一句"我们切到确定性输入" |
| Redis 没起 | 清单第 2 项拦截；开场后遇到 → 起 Redis → 重跑探活 |
| 数据被污染 | `reset-legacy-data.sh`（约一次执行时间） |
| 教室/时段与脚本不符 | 清单对应项拦截；现场遇到 → **当成第 5 幕降级演示** |
| 学生占座说成"明天" | 得到真实拒绝（24h 窗口）→ **顺势讲实测发现的约束，改说"今天下午"再来** |
| 座位号说成 "A3" | 得到有依据拒绝（布局里没有这个座位）→ 按界面提示改用 `2-3` |
| 注入忘撤防 | 清单复核 + 轨迹 ⚠ 注入徽章能当场发现 |
| 意图识别偏差（非确定性） | **先看"识别为…"卡片再继续**；不对就重说一遍——识别过程本来就摊开给观众看 |
| 双屏少了 5174 | 清单第 15 项拦截；`start-all.bat legacyui` 单独补起（首次要装依赖，稍等） |
| 超时 | 按序砍：第 8 → 6 → 4 → 5 → 3 幕（0/1/2/7/9 不砍；第 6 幕是核心尽量保留） |

# 对外接口清单（编排引擎 API）

> **文档性质：基线文档（长期维护，不带日期）。**
> **来源：Gate 3（架构二审开工 Gate 之三）要求"对外接口清单（端点 / 方法 / 请求响应结构 / 错误码）必须在实现时登记"（第 10 章 §6.3 规格 5）。本文件即该登记，随阶段 4（接入层）实现产出。**
> 变更本清单必须走变更记录；事件 type/status 为**闭集**，新增取值必须先在此登记。

---

## 一、总则

| 项 | 规格 |
|---|---|
| 基址与端口 | `http://localhost:8090`（决策 A2；环境变量 `ORCH_PORT` 可覆盖——端口是我们自己的东西，被占就改它，第 11 章 §二） |
| 统一返回结构 | `{ code, message, data }`（研发规范 §4.4）；`code = 0` 表示成功 |
| 错误码段 | `40xx` 参数/形状错误（HTTP 400/404）；`50xx` 内部错误（HTTP 500） |
| 身份与鉴权 | 无（单用户演示场景，边界文档 §四）；存量系统凭证由引擎内部持有，**永不出现在任何响应中** |
| 跨源 | 开发期放行 `Access-Control-Allow-Origin: *`（前端 5173 跨源；生产同源部署时可收紧） |
| 两条入口路径 | 结构化任务（本清单，已可用）与自然语言（`POST /api/chat`，阶段 5 接入理解层后开放）——**汇入同一段编排逻辑**（第 03 章 §十） |

## 二、端点

### 1. `GET /api/health` — 存活探针

响应：`{"code":0,"message":"ok","data":{"status":"ok","tasks":<在册任务数>}}`

### 2. `POST /api/tasks` — 提交结构化任务（无 LLM 路径，G5）

请求体：

```json
{
  "intentId": "borrow-classroom",          // 意图标识（闭集，与理解层同源）
  "identity": "TEACHER",                    // 业务身份（ADMIN/TEACHER/STUDENT）
  "slot": {                                 // 申请时段（绝对时刻，ISO 8601；可办性由判定层校验）
    "start": "2026-10-07T05:00:00Z",
    "end": "2026-10-07T06:00:00Z"
  },
  "reason": "可选：申请理由",
  "resources": [                            // D7：多资源合法，顺序执行
    { "classroom": { "classroomId": 5 } },
    { "classroom": { "building": "数智楼", "roomNumber": "123" } }
  ]
}
```

响应（任务**异步执行**；结果由事件流的终态事件给出，§6）：

```json
{"code":0,"message":"accepted","data":{"taskId":"T-1790321756606-1","eventsPath":"/api/tasks/T-1790321756606-1/events"}}
```

### 3. `GET /api/tasks/{taskId}` — 任务结果快照

响应：`data: { taskId, status: "running"|"terminal", result, createdAt }`。
`result` 为编排层任务结果：`{ terminal, steps, results[], compensations[], conclusion, evidenceRef }`。
主通道是事件流；本端点供调试与兜底轮询。

### 4. `GET /api/tasks/{taskId}/events` — 事件流（SSE）

- `Content-Type: text/event-stream`；每帧 `id: <seq>` + `event: <type>` + `data: <事件 JSON>`。
- **终态事件到达后服务端关闭流**（终态事件唯一，§6.3 规格 2）。
- **断线续传**：请求头 `Last-Event-ID` 或查询参数 `?lastSeq=<n>`——只重放 seq 大于 n 的条目（§6.3 规格 3）。

### 5. `GET /api/tasks/{taskId}/evidence` — 证据链导出

响应：`data: { taskId, entries: [证据条目...] }`。每个事件的 `evidenceRef`（格式 `<taskId>:<seq>`）必须能在此解析；解析不到按缺陷上报（§6.3 规格 4）。条目不含凭证（写入时已净化）。

### 6. `POST /api/chat` — 自然语言入口（**阶段 5 开放**，本阶段未注册路由）

规划契约：请求 `{ text, identity }` → 理解层产出结构化意图 → **同一 TaskRunner**。事件流与结果结构与 `/api/tasks` 完全一致。

## 三、错误码

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功（含任务已受理） |
| 4000 | 400 | 请求体不是合法 JSON |
| 4001 | 400 | 缺少/未知 intentId |
| 4002 | 400 | resources 缺失或形状非法 |
| 4003 | 400 | slot 缺失、不可解析或起止颠倒 |
| 4004 | 400 | 缺少 identity |
| 4040 | 404 | 任务不存在（任务态不跨会话，A6） |
| 4044 | 404 | 未知路由 |
| 5000 | 500 | 内部错误 |

## 四、事件 schema（第 10 章 §6.3 的落地登记）

每条事件：`{ seq, taskId, type, phase, status, evidenceRef, text, at }`。

- `seq` 单调递增、任务内唯一；前端按 seq 排序去重，不依赖到达顺序。
- `evidenceRef` = `<taskId>:<seq>`，指向 `/evidence` 中同 seq 的条目（可解析性由测试保证）。
- `at` 为绝对时刻（ISO 8601 UTC）；展示层单向转本地（第 06 章 §六）。
- `text` 为人可读摘要；**不含接口 URL、参数名、状态机状态名、凭证**（测试断言覆盖）。

### type 闭集（§6.2 + 本次登记新增 ★）

| type | 语义 | 对应证据动作（同源映射） |
|---|---|---|
| fact-collected | 事实获取 | `collect-fact:F#` |
| proposition-judged | 判定结论 | `judge:P-*` |
| call ★ | 一次对存量系统的业务调用（P3 展示"业务语义名 + 身份"） | `contact:*`（verdict ≠ UNKNOWN） |
| decision ★ | 编排决策（命题→事件、查证结论、降级/补偿选择） | `decide:*` |
| uncertain | 进入"待确认"形态（结果未知，正在查证） | `contact:*`（verdict = UNKNOWN） |
| audit ★ | 系统审计（忽略型无边 / 非法转移 / 步数预算） | `audit:*` |
| terminal | 终态（每任务唯一一条） | `task-terminal` / `task-force-unresolved` |
| phase-start / phase-end | 阶段开始/结束（预留：阶段 5 理解层接入后用于 P1 段） | —— |
| input-required | 需要用户输入（预留：追问/换时段确认，阶段 5） | —— |
| cancel-result | 取消结果（预留：取消 API，B8） | —— |
| pending-item | 待处理项（预留：UNRESOLVED 人工处置工作流，K6） | —— |

### status 闭集（§6.3 + 本次登记新增 ★）

`running`（进行中）/ `done`（已完成）/ `failed`（失败）/ `uncertain`（不确定）/ `unavailable`（不可得）/ `not-applicable`（不适用 ★）

### phase 与同源映射

| phase | 来源 |
|---|---|
| P1 理解 | 预留（阶段 5） |
| P2 判定 | 事实收集、命题判定、实体消解（判定层全部证据条目） |
| P3 调用 | 正向提交调用 |
| P4 结果 | 正向查证及其结论 |
| P5 恢复 | 降级选择、补偿撤销及其查证 |
| P6 留痕 | 任务终态、机器审计 |

phase 由证据条目在**写入时**携带（`record({ phase })`），事件映射不推断——这正是"要补的是证据链"（§6.1）的落地。

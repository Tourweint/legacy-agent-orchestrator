# 对外接口清单（编排引擎 API）

> **文档性质：基线文档（长期维护，不带日期）。**
> **来源：Gate 3（架构二审开工 Gate 之三）要求"对外接口清单（端点 / 方法 / 请求响应结构 / 错误码）必须在实现时登记"（第 10 章 §6.3 规格 5）。本文件即该登记，随阶段 4（接入层）实现产出。**
> 变更本清单必须走变更记录；事件 type/status 为**闭集**，新增取值必须先在此登记。
>
> **登记变更（2026-09-25，阶段 5）**：新增两条路由——`POST /api/tasks/{taskId}/reply`（追问回复）与 `DELETE /api/tasks/{taskId}`（取消挂起任务），并新增错误码 `4090`；`POST /api/chat` 已开放。
>
> **登记变更（2026-09-25，拓展方案三审拍板，待实现）**：账号登录三件套——`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`；"全部已读"非编排专用端点 `POST /api/notifications/read-all`；新增错误码 `4010`；会话鉴权走 `orch_session` Cookie（SSE 同）；`POST /api/tasks` 与 `POST /api/chat` 的 `identity` 参数标记 **deprecated**（传了忽略，以会话为准）；`POST /api/tasks/{taskId}/reply` 新增"两段式确认"语义（C14）。依据：[`../变更记录/2026-09-25-拓展方案三审-验收标准与拍板销项.md`](../变更记录/2026-09-25-拓展方案三审-验收标准与拍板销项.md) §二/§六。
>
> **登记变更（2026-09-26，登录三件套已实现，实际契约以此为准）**：`login / logout / me` 三端点上线的同时，**实测推翻了原登记的两条假设**——① 存量系统**有**刷新令牌接口（`POST /auth/refresh`，且刷新令牌轮换、旧的一次性作废），因此续期走刷新令牌，**不在会话里保存明文密码**；② 登录响应的用户信息字段名是 `userInfo`，返回结构为 `data: { userInfo, role }`。另新增错误码 `4011`（登录已失效，需重新登录）、`4013`（账号或密码不正确）、`4041`（任务不属于当前登录用户）；会话令牌除 Cookie 外**也接受** `Authorization: Bearer <会话令牌>`（供脚本/接口测试，不改变浏览器的 HttpOnly 语义）。依据：[`../变更记录/2026-09-26-登录会话与权限实现登记.md`](../变更记录/2026-09-26-登录会话与权限实现登记.md)。下列条目中"**（待实现）**"标注者＝尚未实现（如"全部已读"端点与 C14 两段式确认语义）。

## 一、总则

| 项 | 规格 |
|---|---|
| 基址与端口 | `http://localhost:8090`（决策 A2；环境变量 `ORCH_PORT` 可覆盖——端口是我们自己的东西，被占就改它，第 11 章 §二） |
| 统一返回结构 | `{ code, message, data }`（研发规范 §4.4）；`code = 0` 表示成功 |
| 错误码段 | `40xx` 参数/形状错误（HTTP 400/404）；`50xx` 内部错误（HTTP 500） |
| 身份与鉴权 | **已实现（2026-09-26）**：除 `/api/health` 与 `POST /api/auth/login` 外，全部端点要求有效引擎会话（Cookie `orch_session`（HttpOnly/SameSite=Lax）；SSE 因 `EventSource` 不能带自定义头，同走 Cookie，经 `/api` 同源代理携带；脚本与接口测试可用 `Authorization: Bearer <会话令牌>`）；未登录返回 `4010`。登录后调用身份从会话派生，请求体 `identity` 字段 deprecated（**传了忽略、缺省不报 4004**）。存量系统凭证由引擎内部持有，**永不出现在任何响应中**（登录响应实测不回带任何令牌） |
| 跨源 | 开发期放行 `Access-Control-Allow-Origin: *`（前端 5173 跨源；生产同源部署时可收紧） |
| 两条入口路径 | 结构化任务（`POST /api/tasks`，无 LLM 路径）与自然语言（`POST /api/chat`，阶段 5 已开放）——**汇入同一段编排逻辑**（第 03 章 §十） |

## 二、端点

### 1. `GET /api/health` — 存活探针

响应：`{"code":0,"message":"ok","data":{"status":"ok","tasks":<在册任务数>}}`

### 2. `POST /api/tasks` — 提交结构化任务（无 LLM 路径，G5）

请求体：

```json
{
  "intentId": "borrow-classroom",          // 意图标识（闭集，与理解层同源）
  "identity": "TEACHER",                    // 【deprecated·三审，待实现生效】业务身份；登录会话上线后传了也忽略，以会话为准，缺省不再报 4004
  "slot": {                                 // 申请时段（绝对时刻，ISO 8601；可办性由判定层校验）
    "start": "2026-10-07T05:00:00Z",
    "end": "2026-10-07T06:00:00Z"
  },
  "reason": "可选：申请理由",
  "resources": [                            // D7：多资源合法，顺序执行
    { "classroom": { "classroomId": 5 } },
    { "classroom": { "building": "数智楼", "roomNumber": "123" } }
  ]
}
```

响应（任务**异步执行**；结果由事件流的终态事件给出，§6）：

```json
{"code":0,"message":"accepted","data":{"taskId":"T-1790321756606-1","eventsPath":"/api/tasks/T-1790321756606-1/events"}}
```

### 3. `GET /api/tasks/{taskId}` — 任务结果快照

响应：`data: { taskId, status: "running"|"terminal", result, createdAt }`。
`result` 为编排层任务结果：`{ terminal, steps, results[], compensations[], conclusion, evidenceRef }`。
主通道是事件流；本端点供调试与兜底轮询。

### 4. `GET /api/tasks/{taskId}/events` — 事件流（SSE）

- `Content-Type: text/event-stream`；每帧 `id: <seq>` + `event: <type>` + `data: <事件 JSON>`。
- **终态事件到达后服务端关闭流**（终态事件唯一，§6.3 规格 2）。
- **断线续传**：请求头 `Last-Event-ID` 或查询参数 `?lastSeq=<n>`——只重放 seq 大于 n 的条目（§6.3 规格 3）。

### 5. `GET /api/tasks/{taskId}/evidence` — 证据链导出

响应：`data: { taskId, entries: [证据条目...] }`。每个事件的 `evidenceRef`（格式 `<taskId>:<seq>`）必须能在此解析；解析不到按缺陷上报（§6.3 规格 4）。条目不含凭证（写入时已净化）。

### 6. `POST /api/chat` — 自然语言入口（**阶段 5 已开放**）

契约：请求 `{ text, identity }` → 理解层产出结构化意图 → **同一 TaskRunner**。事件流与结果结构与 `/api/tasks` 完全一致。
`identity` 字段与第 2 条同为 **deprecated（三审）**：会话上线后传了忽略、缺省不报错，身份从会话派生。
槽位缺口或换时段确认时任务进入**挂起**（`status: "suspended"`，`clarify` 字段带追问内容），由第 7 条路由恢复。

### 7. `POST /api/tasks/{taskId}/reply` — 追问回复（阶段 5；三审扩展"两段式确认"语义，待实现）

请求体：`{ text }`（用户对追问的自然语言回复）。
仅**挂起中**（`suspended`）的任务可回复；其余状态返回 `409 + 4090`。恢复后任务继续推进，事件与结果仍走同一事件流。

**三审补（C14 两段式确认，待实现）**：挂起分两类语义——
① **槽位追问**（现状）：挂起点在理解层之前，回复文本重新走理解层；
② **影响面确认**（`confirmBeforeWrite`，C14 新增）：挂起点在事实收集之后、第一个写入步之前，任务上下文保存"待撤销列表 + 事实快照"。回复不经过理解层，按**直控指令**解释：`{ "text": "确认" }`（或等价 `{ "confirm": true }`）→ 直接进入写入；`{ "text": "取消" }`（或 `{ "confirm": false }`）→ 直接终止，终态 REJECTED，话术"已取消，未做任何改动"。
任务快照须能区分两类挂起（前端据此渲染"追问卡"或"影响面确认卡"）。

### 8. `DELETE /api/tasks/{taskId}` — 取消任务（阶段 5，决策 B8）

**只在写请求发出前生效**（挂起/收集中）；进入提交后取消不生效，返回 `409 + 4090`，结果由查证收敛给出（不制造不确定态）。
取消本身不新开事件类型：结果与终态事件仍由同一事件流给出（§6.3 规格 2）。

### 9. `POST /api/auth/login` — 登录（**已实现 2026-09-26**）

引擎用同一套凭据去调存量系统登录；存量令牌（access + refresh）只留引擎内。
请求体：`{ "username": "233", "password": "***" }`。
成功：`200 { code: 0, message: "登录成功", data: { userInfo: { id, username, nickname, email, role, creditScore, creditLevel, seatReservationAdvanceHours, maxSingleReservationMinutes, dailyReservationLimitMinutes }, role } }`，并经 `Set-Cookie: orch_session=<引擎会话令牌>; Path=/; HttpOnly; SameSite=Lax; Max-Age=...` 下发引擎自己的会话。`userInfo` 直接来自存量登录响应（实测字段名就是 `userInfo`）。
失败：账号或密码不正确 → `401 + 4013`（不区分"账号不存在/密码错"，不给枚举探测的口子）；存量系统不可达等运行故障 → `401 + 4013` 且消息说明是运行故障。
**凭证纪律（实测修订）**：存量 access token 默认有效期 30 分钟；过期时引擎用**刷新令牌**续期一次（实测该接口存在且令牌轮换），**密码不落内存、不落盘、不进日志**。

### 10. `POST /api/auth/logout` — 登出（**已实现 2026-09-26**）

清除引擎会话与 Cookie，并调用存量 `POST /auth/logout` 撤销该设备会话（不留残会话占设备名额）。
幂等：无有效会话时仍返回 `200 { code: 0, data: { loggedOut: false } }`；有会话时为 `loggedOut: true`。

### 11. `GET /api/auth/me` — 我是谁（**已实现 2026-09-26**）

返回当前会话用户：`data: { userInfo, role, cookieName }`；无有效会话返回 `401 + 4010`。录制前检查用它断言两个浏览器画像的会话均有效（G-登录 结论：被踢后调用返回 HTTP 401 + 业务码 401）。

### 12. `POST /api/notifications/read-all` — 全部通知标已读（**三审登记，待实现；非编排端点**）

"全部已读"**不做意图、不创建任务、不发 SSE**（不可撤销，注册表 `autoOrchestration: false`，结构自检第 8 条禁止意图引用；三审拍板）。
语义：用**会话本人令牌**同步调用存量 `PATCH /notifications/read-all` 一次，返回 `data: { unreadBefore, unreadAfter }`（未读数经复核接口取得）；引擎留访问日志（who/when/result，含 initiator，凭证脱敏）。
需有效会话（`4010`）；连续两次调用的行为以待实测项 G-C11 结论回填（幂等性）。前端仅由通知区手动按钮触发；自然语言"都标已读"不调用本端点，由对话固定话术引导用户点按钮。

## 三、错误码

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功（含任务已受理） |
| 4000 | 400 | 请求体不是合法 JSON |
| 4001 | 400 | 缺少/未知 intentId |
| 4002 | 400 | resources 缺失或形状非法 |
| 4003 | 400 | slot 缺失、不可解析或起止颠倒 |
| 4004 | 400 | 缺少 identity（**三审：会话鉴权上线后退役**——identity 已 deprecated，缺省不再报错） |
| 4010 | 401 | 未登录（无会话或会话不存在）；前端按 N5 给"请先登录"人话提示，不向观众展示数字码 |
| 4011 | 401 | 登录已失效，需重新登录（存量会话被撤/被踢，或刷新令牌续期失败） |
| 4013 | 401 | 账号或密码不正确（登录端点专用；不区分账号不存在与密码错） |
| 4040 | 404 | 任务不存在（任务态不跨会话，A6） |
| 4041 | 404 | 任务不属于当前登录用户（不暴露其内容；对外与 4040 同样"查不到"） |
| 4044 | 404 | 未知路由 |
| 4090 | 409 | 任务不处于挂起态：reply / 取消均只对挂起任务生效（B8） |
| 5000 | 500 | 内部错误 |

## 四、事件 schema（第 10 章 §6.3 的落地登记）

每条事件：`{ seq, taskId, type, phase, status, evidenceRef, text, at }`。

- `seq` 单调递增、任务内唯一；前端按 seq 排序去重，不依赖到达顺序。
- `evidenceRef` = `<taskId>:<seq>`，指向 `/evidence` 中同 seq 的条目（可解析性由测试保证）。
- `at` 为绝对时刻（ISO 8601 UTC）；展示层单向转本地（第 06 章 §六）。
- `text` 为人可读摘要；**不含接口 URL、参数名、状态机状态名、凭证**（测试断言覆盖）。

### type 闭集（§6.2 + 本次登记新增 ★）

| type | 语义 | 对应证据动作（同源映射） |
|---|---|---|
| fact-collected | 事实获取 | `collect-fact:F#` |
| proposition-judged | 判定结论 | `judge:P-*` |
| call ★ | 一次对存量系统的业务调用（P3 展示"业务语义名 + 身份"） | `contact:*`（verdict ≠ UNKNOWN） |
| decision ★ | 编排决策（命题→事件、查证结论、降级/补偿选择） | `decide:*` |
| uncertain | 进入"待确认"形态（结果未知，正在查证） | `contact:*`（verdict = UNKNOWN） |
| audit ★ | 系统审计（忽略型无边 / 非法转移 / 步数预算） | `audit:*` |
| terminal | 终态（每任务唯一一条） | `task-terminal` / `task-force-unresolved` |
| phase-start / phase-end | 阶段开始/结束（**预留，尚未产出**：P1 段由证据条目自带的 `phase` 表达，未单独发首尾帧） | —— |
| input-required | 需要用户输入（**阶段 5 已产出**：追问/换时段确认） | `ask:*` |
| cancel-result | 取消结果（**预留，尚未产出**：取消结果由 `DELETE` 响应与终态事件给出） | —— |
| pending-item | 待处理项（**预留，尚未产出**：UNRESOLVED 人工处置工作流，K6） | —— |

### status 闭集（§6.3 + 本次登记新增 ★）

`running`（进行中）/ `done`（已完成）/ `failed`（失败）/ `uncertain`（不确定）/ `unavailable`（不可得）/ `not-applicable`（不适用 ★）

### phase 与同源映射

| phase | 来源 |
|---|---|
| P1 理解 | 阶段 5 落地：澄清追问（`ask:clarify`）等理解层证据条目 |
| P2 判定 | 事实收集、命题判定、实体消解（判定层全部证据条目） |
| P3 调用 | 正向提交调用 |
| P4 结果 | 正向查证及其结论 |
| P5 恢复 | 降级选择、补偿撤销及其查证 |
| P6 留痕 | 任务终态、机器审计 |

phase 由证据条目在**写入时**携带（`record({ phase })`），事件映射不推断——这正是"要补的是证据链"（§6.1）的落地。

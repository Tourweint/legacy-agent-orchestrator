## 文档分工原则

| 目录 | 回答的问题 | 生命周期 |
|---|---|---|
| `基线文档/` | **现在是什么规则** | 长期维护，不带日期 |
| `设计方案/` | **当时是怎么想的 / 打算怎么做** | 带日期，留档不改写 |
| `变更记录/` | **什么时候改成了这样** | 带日期，追加 |
| `实验/` | **凭什么说它有效** | 带日期，可重跑 |
| `演示/` | **怎么演示、演示什么** | 带日期，随分镜定稿 |
| `研发规范/` | **写代码要守什么** | 长期维护，不带日期 |

**约定**：修改架构或流程时优先更新 `基线文档/`；大型改造必须新增一条 `变更记录/`；避免在根目录堆放零散文档。

**降级件已删除**：2026-09-24 的降级件（原 `_prototype/`）已整份移除；它留下的"方案不得引用代码结构、不得先写代码再补方案"这条纪律仍写入 [AGENTS.md](../AGENTS.md) 与第 13 章 §九。处置与核验见 [交付物越界与降级处置](./变更记录/2026-09-24-交付物越界与降级处置.md)。

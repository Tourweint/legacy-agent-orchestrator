# 前端全方位系统性优化方案

> **项目**
>
> ：legacy-agent-orchestrator 对话前端（Vue 3 + Pinia + Vite）
> **版本**
>
> ：v1.0（2026-09-26）
> **范围**
>
> ：视觉设计系统、用户体验、响应式、性能、可访问性、交互设计、代码架构
> **参考基准**
>
> ：Stripe Design System、Linear.app、Vercel Design、Ant Design 5、Material Design 3、WCAG 2.1 AA



***

## 现状诊断摘要

当前前端采用 "极简手写" 路线（无 UI 库、无 CSS 预处理器、无 TypeScript），核心功能完整（对话 + 执行轨迹三视图、SSE 实时流、深浅双主题），但在以下维度存在系统性差距：



| 维度     | 现状评分   | 核心差距                                                        |
| ------ | ------ | ----------------------------------------------------------- |
| 视觉设计系统 | 6/10   | 令牌不完整（缺字号层级 / 阴影 /z-index/ 断点 / 动效曲线）、图标用 Unicode 字符、组件样式分散 |
| 用户体验   | 6.5/10 | 空状态单薄、加载态单一、错误处理简陋、固定高度不自适应、缺键盘快捷键                          |
| 响应式设计  | 5/10   | 仅 1 个断点（900px）、移动端未精细适配、触摸优化缺失                              |
| 性能优化   | 7/10   | 单 bundle 86KB 尚可，但缺代码分割 / 虚拟滚动 / SSE 指数退避 / 字体优化            |
| 可访问性   | 4/10   | ARIA 标签缺失、键盘导航不完整、焦点样式弱、颜色对比度可能不足                           |
| 交互设计   | 5.5/10 | 微交互不足、动画简单、缺骨架屏、消息出现无过渡、滚动条未美化                              |
| 代码架构   | 6/10   | 无 TypeScript、常量硬编码、缺 composables、无测试、无 ESLint/Prettier      |

## 一、视觉设计系统优化

### 1.1 设计令牌体系升级

**现状问题**：`tokens.css` 仅有基础色彩、间距、圆角、字体，缺少完整的设计令牌层级。

**优化方案**：建立五层令牌体系（Primitives → Semantic → Component → Utility → Motion）。

#### 1.1.1 字号层级（Type Scale）

采用模块化比例（1.25  Major Third），建立 7 级字号：



```
:root {

&#x20; --text-xs:   11px;   /\* 辅助标签、时间戳 \*/

&#x20; --text-sm:   12px;   /\* 次要说明、hint \*/

&#x20; --text-base: 14px;   /\* 正文（当前基础） \*/

&#x20; --text-md:   15px;   /\* 强调正文、按钮 \*/

&#x20; --text-lg:   18px;   /\* 面板标题、品牌名 \*/

&#x20; --text-xl:   22px;   /\* 页面标题 \*/

&#x20; --text-2xl:  28px;   /\* 结果大标题 \*/

&#x20; --text-3xl:  36px;   /\* 英雄区数字 \*/

&#x20; /\* 字重 \*/

&#x20; --weight-regular:  400;

&#x20; --weight-medium:   500;

&#x20; --weight-semibold: 600;

&#x20; --weight-bold:     700;

&#x20; /\* 行高 \*/

&#x20; --leading-tight:   1.3;

&#x20; --leading-normal:  1.5;

&#x20; --leading-relaxed: 1.7;

}
```

#### 1.1.2 色彩系统扩展

在现有基础色上，建立语义色的完整色阶（参考 Stripe/Linear 的 10 级色阶），并确保 WCAG AA 对比度：



```
:root {

&#x20; /\* Accent 色阶（紫色系，当前 #5b5bd6 为 500） \*/

&#x20; --accent-50:  #f3f3fc;

&#x20; --accent-100: #e8e8f9;

&#x20; --accent-200: #d1d1f3;

&#x20; --accent-300: #b0b0e9;

&#x20; --accent-400: #8b8bf0;

&#x20; --accent-500: #5b5bd6;  /\* 主色 \*/

&#x20; --accent-600: #4a4ab8;

&#x20; --accent-700: #3d3d96;

&#x20; --accent-800: #33337a;

&#x20; --accent-900: #2a2a63;

&#x20; /\* 中性色阶（替换当前的 text/text-muted/text-faint 三级） \*/

&#x20; --gray-50:  #f7f8fa;

&#x20; --gray-100: #eef0f4;

&#x20; --gray-200: #e3e8ee;

&#x20; --gray-300: #d1d7e0;

&#x20; --gray-400: #9aa4b8;

&#x20; --gray-500: #697386;

&#x20; --gray-600: #4a5268;

&#x20; --gray-700: #363d4f;

&#x20; --gray-800: #252a38;

&#x20; --gray-900: #1a1f36;

&#x20; /\* 状态色阶（success/danger/uncertain 各 10 级） \*/

&#x20; --success-50:  #e3f5ee; --success-500: #0e9f6e; --success-700: #0a7d56;

&#x20; --danger-50:   #fdeceb; --danger-500:  #d92d20; --danger-700:  #b42318;

&#x20; --warning-50:  #fdf1e2; --warning-500: #b54708; --warning-700: #93370d;

}
```

**对比度验证**（WCAG AA 要求正文 ≥4.5:1，大字 ≥3:1）：



* `--gray-500` (#697386) on `--bg` (#f7f8fa)：对比度约 4.6:1 ✅（刚好达标，建议用 `--gray-600` 用于次要正文）

* `--gray-400` (#9aa4b8) on `--bg`：对比度约 2.8:1 ❌（仅可用于禁用态 / 装饰性文字，不可用于正文）

* 深色主题同理验证

#### 1.1.3 阴影层级（Elevation）

当前完全无阴影（"细描边优先于阴影" 是正确方向，但完全没有阴影会导致层级感不足）。建立 4 级阴影，仅用于悬浮元素和模态层：



```
:root {

&#x20; --shadow-xs: 0 1px 2px rgba(16, 24, 40, 0.04);

&#x20; --shadow-sm: 0 1px 3px rgba(16, 24, 40, 0.08), 0 1px 2px rgba(16, 24, 40, 0.04);

&#x20; --shadow-md: 0 4px 8px -2px rgba(16, 24, 40, 0.10), 0 2px 4px -2px rgba(16, 24, 40, 0.06);

&#x20; --shadow-lg: 0 12px 16px -4px rgba(16, 24, 40, 0.12), 0 4px 6px -2px rgba(16, 24, 40, 0.05);

&#x20; --shadow-xl: 0 20px 24px -4px rgba(16, 24, 40, 0.15), 0 8px 8px -4px rgba(16, 24, 40, 0.04);

}
```

使用原则：卡片默认无阴影（仅描边），hover 时加 `--shadow-xs`；下拉菜单 / 弹出层用 `--shadow-md`；模态框用 `--shadow-lg`。

#### 1.1.4 断点系统（Breakpoints）



```
:root {

&#x20; --bp-sm:  640px;  /\* 手机横屏 / 小平板 \*/

&#x20; --bp-md:  768px;  /\* 平板 \*/

&#x20; --bp-lg:  1024px; /\* 小桌面 / 大平板 \*/

&#x20; --bp-xl:  1280px; /\* 桌面 \*/

&#x20; --bp-2xl: 1536px; /\* 大桌面 \*/

}
```

#### 1.1.5 动效曲线（Easing）



```
:root {

&#x20; --ease-standard:   cubic-bezier(0.4, 0, 0.2, 1);   /\* 标准（进入/退出） \*/

&#x20; --ease-decelerate: cubic-bezier(0, 0, 0.2, 1);       /\* 减速（进入） \*/

&#x20; --ease-accelerate: cubic-bezier(0.4, 0, 1, 1);       /\* 加速（退出） \*/

&#x20; --ease-emphasized: cubic-bezier(0.34, 1.56, 0.64, 1); /\* 强调（弹性） \*/

&#x20; --dur-instant: 80ms;

&#x20; --dur-fast:    120ms;  /\* 现有 \*/

&#x20; --dur-base:    200ms;  /\* 新增：标准过渡 \*/

&#x20; --dur-slow:    240ms;  /\* 现有 \*/

&#x20; --dur-slower:  360ms;  /\* 新增：复杂过渡 \*/

}
```

#### 1.1.6 Z-Index 层级



```
:root {

&#x20; --z-base:     0;

&#x20; --z-dropdown: 100;

&#x20; --z-sticky:   200;

&#x20; --z-overlay:  300;

&#x20; --z-modal:    400;

&#x20; --z-toast:    500;

&#x20; --z-tooltip:  600;

}
```

### 1.2 图标系统

**现状问题**：使用 Unicode 字符（✓ ✗ ⚑ ⚠・–）作为图标，存在三个问题：① 不同平台渲染不一致；② 屏幕阅读器无法正确朗读语义；③ 无法统一控制大小 / 颜色 / 描边宽度。

**优化方案**：引入 SVG 图标系统，建立 `src/icons/` 目录，使用 Vue 组件封装。

#### 1.2.1 图标集选择

推荐使用 **Lucide Icons**（MIT 协议，300+ 图标，描边风格，与当前 "细描边优先" 设计取向一致）。不引入完整图标库，仅按需导入使用到的图标：



```
src/icons/

&#x20; index.js          # 统一导出

&#x20; IconCheck.vue     # ✓ 成功

&#x20; IconX.vue         # ✗ 失败

&#x20; IconFlag.vue      # ⚑ 待处理

&#x20; IconAlert.vue     # ⚠ 警告/注入

&#x20; IconChevronDown.vue  # 折叠箭头

&#x20; IconChevronRight.vue # 展开箭头

&#x20; IconSend.vue      # 发送

&#x20; IconRefresh.vue   # 再办一件

&#x20; IconSun.vue       # 浅色主题

&#x20; IconMoon.vue      # 深色主题

&#x20; IconSpinner.vue   # 加载（动画）

&#x20; IconTerminal.vue  # 调试

&#x20; IconCopy.vue      # 复制 taskId

&#x20; IconSearch.vue    # 搜索
```

#### 1.2.2 图标组件规范



```
\<!-- IconCheck.vue -->

\<script setup>

defineProps({

&#x20; size: { type: \[Number, String], default: 16 },

&#x20; strokeWidth: { type: Number, default: 2 },

})

\</script>

\<template>

&#x20; \<svg

&#x20;   :width="size" :height="size"

&#x20;   viewBox="0 0 24 24" fill="none"

&#x20;   stroke="currentColor" :stroke-width="strokeWidth"

&#x20;   stroke-linecap="round" stroke-linejoin="round"

&#x20;   aria-hidden="true"

&#x20; \>

&#x20;   \<path d="M20 6 9 17l-5-5" />

&#x20; \</svg>

\</template>
```

**关键规范**：



* 所有图标使用 `currentColor`，颜色由父元素 `color` 控制

* `aria-hidden="true"` 隐藏装饰性图标，有语义的图标配合 `aria-label`

* 统一 24x24 viewBox，描边宽度默认 2px

* 加载动画图标使用 CSS `animation`，不使用 GIF

### 1.3 组件样式统一

**现状问题**：组件样式分散在各 `.vue` 文件的 `<style scoped>` 中，缺少统一的组件类设计，重复代码多（如 button 样式在 base.css 定义但各组件又覆盖）。

**优化方案**：建立三层样式架构：



```
src/styles/

&#x20; tokens.css       # 设计令牌（已有，升级）

&#x20; base.css         # 全局重置 + 元素默认样式（已有，升级）

&#x20; utilities.css    # 工具类（spacing/typography/color/display 等）

&#x20; components.css   # 通用组件类（.btn / .card / .chip / .input / .badge）

&#x20; animations.css   # 动画关键帧（pulse/spin/slide-in/fade 等）
```

## 二、用户体验优化

### 2.1 信息架构与导航

**现状问题**：单页双栏布局（对话 360px + 轨迹自适应），无全局导航，用户在任务进行中缺乏全局状态感知。

**优化方案**：

#### 2.1.1 顶部状态栏增强

当前顶栏仅有品牌名 + 主题切换。增加全局状态指示器：



```
┌─────────────────────────────────────────────────────────┐

│ 校园教室代办          \[连接状态] \[当前任务]  ☀/🌙    │

│ 每一步都看得见依据 · 可解释可恢复                        │

├──────────────────┬──────────────────────────────────────┤

│                  │                                      │

│   对话面板        │         执行轨迹面板                  │

│   (360px)        │         (自适应)                      │

│                  │                                      │

└──────────────────┴──────────────────────────────────────┘
```



* **连接状态**：显示引擎连接状态（已连接 / 重连中 / 已断开），SSE 状态驱动

* **当前任务**：显示当前任务 ID 和状态（进行中 / 挂起 / 已完成），点击可复制

* 任务进行中时，顶栏底部显示细进度条（按阶段 P1-P6 推进）

#### 2.1.2 空状态设计

当前空状态仅一行文字。优化为结构化空状态：



```
┌─────────────────────────────────┐

│         \[图标]                  │

│    开始一次可解释的办理          │

│                                 │

│  用一句话描述你要办的事，        │

│  系统会展示每一步的依据与结论。  │

│                                 │

│  ┌───────────────────────────┐ │

│  │ 帮我借下周三下午数智楼222 │ │ ← 快捷示例（可点击填充）

│  └───────────────────────────┘ │

│  ┌───────────────────────────┐ │

│  │ 查明天上午数智楼123有没有空│ │

│  └───────────────────────────┘ │

│  ┌───────────────────────────┐ │

│  │ 帮我预约本周四下午的会议室  │ │

│  └───────────────────────────┘ │

└─────────────────────────────────┘
```



* 图标使用 SVG（如 `IconSparkles`）

* 快捷示例点击后自动填充到输入框并聚焦

* 示例定期轮换或根据使用频率排序

#### 2.1.3 任务生命周期引导



| 阶段       | 用户可见引导                                 |
| -------- | -------------------------------------- |
| 空闲       | 空状态 + 快捷示例                             |
| 理解中 (P1) | 输入框禁用 + "正在理解你的需求…" + 骨架屏              |
| 判定中 (P2) | 轨迹面板 P2 段实时出现事实收集 / 命题判定               |
| 调用中 (P3) | 显示 "正在以 XX 身份调用 XX 接口" + 取消按钮（如未发出写请求） |
| 查证中 (P4) | 显示 "结果不确定，正在查证收敛…" + uncertain 状态高亮    |
| 恢复中 (P5) | 显示 "正在尝试恢复 / 补偿…"                      |
| 终态       | ResultCard 突出展示 + "再办一件" 按钮            |
| 挂起       | 输入框变为 "补充信息" + 候选按钮 + 取消按钮             |

### 2.2 加载与错误状态

#### 2.2.1 骨架屏（Skeleton）

替换当前的 "进行中……" 文字，使用骨架屏：



```
.skeleton {

&#x20; background: linear-gradient(90deg, var(--surface-2) 25%, var(--gray-100) 50%, var(--surface-2) 75%);

&#x20; background-size: 200% 100%;

&#x20; animation: skeleton-shimmer 1.5s infinite;

&#x20; border-radius: var(--radius-small);

}

@keyframes skeleton-shimmer {

&#x20; 0% { background-position: 200% 0; }

&#x20; 100% { background-position: -200% 0; }

}
```

应用场景：



* 理解阶段：对话面板显示 2-3 行骨架气泡

* 轨迹面板：每个阶段显示 2-3 行骨架条目

* 结果加载：ResultCard 位置显示骨架

#### 2.2.2 错误状态设计

当前错误仅显示一行红色文字。优化为结构化错误：



```
┌─────────────────────────────────────┐

│ ⚠ 连接中断                           │

│ 与编排引擎的连接已断开，正在重连…    │

│ \[重试] \[查看详情]                    │

└─────────────────────────────────────┘
```



* 错误分类：网络错误 / 引擎错误 / 业务错误 / 超时

* 每种错误有对应的图标、标题、建议操作

* 可展开查看技术详情（错误码、请求 ID、时间戳）

### 4.2 运行时性能优化

#### 4.2.1 SSE 重连指数退避

当前 SSE 断线后 EventSource 浏览器自动重连，但没有指数退避。优化：



```
// api/sse.js

export function openTaskStream(taskId, handlers) {

&#x20; let retryDelay = 1000

&#x20; const maxRetryDelay = 30000

&#x20; let es = null

&#x20; let closedByUser = false

&#x20; function connect() {

&#x20;   es = new EventSource(\`/api/tasks/\${encodeURIComponent(taskId)}/events\`)

&#x20;   es.onopen = () => {

&#x20;     retryDelay = 1000  // 连接成功后重置退避

&#x20;     handlers.onState?.('open')

&#x20;   }

&#x20;   es.onerror = () => {

&#x20;     if (closedByUser) return

&#x20;     handlers.onState?.('reconnecting')

&#x20;     es.close()

&#x20;     // 指数退避 + 随机抖动（避免惊群效应）

&#x20;     const jitter = Math.random() \* 1000

&#x20;     setTimeout(connect, Math.min(retryDelay + jitter, maxRetryDelay))

&#x20;     retryDelay = Math.min(retryDelay \* 2, maxRetryDelay)

&#x20;   }

&#x20;   es.onmessage = (msg) => { /\* ... \*/ }

&#x20; }

&#x20; connect()

&#x20; return {

&#x20;   close: () => {

&#x20;     closedByUser = true

&#x20;     es?.close()

&#x20;     handlers.onState?.('closed')

&#x20;   },

&#x20; }

}
```

#### 4.2.2 轮询优化

当前轮询固定 1200ms 间隔。优化为自适应轮询：



```
// stores/task.js

\_refreshWhileRunning() {

&#x20; let interval = 800

&#x20; const maxInterval = 3000

&#x20; let consecutiveSameStatus = 0

&#x20; const tick = async () => {

&#x20;   if (!this.taskId || this.taskStatus === 'terminal') return

&#x20;   const prevStatus = this.taskStatus

&#x20;   const snap = await apiGetTask(this.taskId)

&#x20;   // ... 处理快照 ...

&#x20;   // 状态不变时增加轮询间隔（减少无效请求）

&#x20;   if (this.taskStatus === prevStatus) {

&#x20;     consecutiveSameStatus++

&#x20;     if (consecutiveSameStatus > 3) {

&#x20;       interval = Math.min(interval \* 1.5, maxInterval)

&#x20;     }

&#x20;   } else {

&#x20;     consecutiveSameStatus = 0

&#x20;     interval = 800  // 状态变化时恢复快速轮询

&#x20;   }

&#x20;   if (this.taskStatus !== 'terminal') {

&#x20;     setTimeout(tick, interval)

&#x20;   }

&#x20; }

&#x20; setTimeout(tick, 500)

}
```

#### 4.2.3 虚拟滚动（事件列表）

当任务事件很多时（如混沌实验可能产生数十条），全量渲染可能影响性能。引入虚拟滚动：



* 推荐使用 `vue-virtual-scroller` 或自定义 `useVirtualList` composable

* 仅渲染视口内可见的事件条目（约 10–15 条）

* 应用于轨迹面板的事件列表和对话面板的消息列表

* 阈值：事件数 > 50 时启用虚拟滚动

#### 4.2.4 事件去重优化

当前 `_applyEvent` 使用 `Array.some()` 线性查找去重，O (n) 复杂度。优化为 Set：



```
// stores/task.js

state: () => ({

&#x20; events: \[],

&#x20; \_eventSeqs: new Set(),  // 新增：seq 集合，O(1) 去重

}),

\_applyEvent(event) {

&#x20; if (this.\_eventSeqs.has(event.seq)) return

&#x20; this.\_eventSeqs.add(event.seq)

&#x20; this.events.push(event)

&#x20; // 不再需要每次 sort（SSE 事件按 seq 顺序到达，仅在乱序时插入排序）

&#x20; const last = this.events\[this.events.length - 2]

&#x20; if (last && last.seq > event.seq) {

&#x20;   this.events.sort((a, b) => a.seq - b.seq)

&#x20; }

},

\_reset() {

&#x20; // ...

&#x20; this.\_eventSeqs = new Set()

}
```

### 4.3 内存与资源管理



* **SSE 流关闭**：组件卸载时确保 `EventSource.close()`（当前已实现，但需检查所有使用点）

* **轮询清理**：任务终态后清除 `setTimeout`（当前已实现）

* **事件列表上限**：单任务事件数超过 500 时警告，超过 1000 时截断（保护内存）

* **证据链懒加载**：当前点击展开时才拉取证据链（已实现，正确）

# 2026-09-26 对话工作台界面方案（思考过程折叠 + 核心输出优先）

> **文档性质：设计方案（带日期）**。**2026-09-26 已按本文实现完毕**（见[对话工作台界面重构](../变更记录/2026-09-26-对话工作台界面重构.md)）；本文保留为设计依据，实现与本文的差异集中在文末 §十。
> **发起**：演示后的界面反馈——右侧"执行轨迹"面板与对话割裂、界面显挤；要求改成"像 IDE 那样：**思考过程默认隐藏、点开才看；结束后只展示核心输出；输出要区分重要与非重要**"。
> **范围**：**只动前端展示层**。事件模型、证据链、接口契约、编排与判定逻辑**一律不改**——UI 只是换一种方式呈现已经有的数据。

## 一、目标与判据

### 1.1 一句话目标

**把"一屏塞满步骤"改成"先说结论，过程按需展开"。**

用户看一眼对话就应该知道：**办成了什么 / 没办成为什么 / 我还需要说什么**。至于"系统内部走了哪几步、依据了哪条规则"——写在折叠起来的思考过程里，想深究的人点开看。

### 1.2 分层判据（唯一的取舍标准）

> **这条信息会不会改变用户下一步的动作？**

| 层级 | 判据 | 内容 | 默认 |
|---|---|---|---|
| **L1 核心输出** | 会 | 结论（办成了什么，含预约号与时段）· 拒绝理由与替代动作 · 追问（要补什么信息）· 需要确认的推算 | **可见**，就是"助手的那句话" |
| **L2 关键过程** | 不会，但解释"为什么能/不能办" | 判定结论（这个时段是空的 ✓）· 调用结果（提交教室预约 ✓）· 不确定与收敛 · 补偿动作 | 折叠在"思考过程"里，点开可见 |
| **L3 留痕明细** | 只有审计价值 | 事实收集明细 · 内部决策留痕 · 阶段边界 · 待办项 | 再点一层"查看完整留痕" |

**这条判据同时解决"输出结构化"**：不是把 12 种事件等权重地平铺，而是按它先分层，再按层决定显隐与样式权重。

### 1.3 明确不做的事

| 不做 | 为什么 |
|---|---|
| 终端日志风格（等宽字体 + `●`/`⎿` 符号满屏） | 已明确否决：那是给工程师看的运行日志，不是给办事的人看的回答 |
| 引入 markdown 渲染引擎 / 代码高亮库 | 我们的输出是**短句 + 结构化字段**，不需要；引依赖会带来体积与安全面 |
| 改事件类型或新增事件 | 闭集已在接口清单登记，UI 不该倒逼后端；若确实缺信息，先改契约再改界面 |
| 服务端存储会话历史 | 本轮仍用 `localStorage`（演示期足够）；引擎侧的 `ConversationStore` 已具备列举能力，将来要跨设备再开 `GET /api/conversations` |

## 三、一轮对话的渲染结构

一轮（turn）= 用户说的话 → 思考过程折叠块 → 核心输出。顺序按**真实时间顺序**，因为步骤确实发生在回答之前。

### 3.1 思考过程折叠块（`ThinkingBlock`）

**收起态**（办成时的默认）：

```text
▸ 思考过程 · 6 步 · 2.4 秒                    ← 单行，弱化（小字、灰、无边框）
```

- 运行中标题动态变化：`正在办理 · 第 3 步（调用）`，并带呼吸点；
- **办不成时不完全收起**：标题换成 `▾ 为什么没办成 · 2 项没通过`，并自动**部分展开**失败链路（见 §3.1 末表）；
- 中断时：`已停止 · 完成 3 步`（**如实说明停在哪**，后面的步骤不假装跑过）；
- 有故障注入时带一枚 `注入` 角标（保留现有能力，演示答辩要用）。

**步数与耗时从哪来**：事件自带 `phase` 与 `at`（`event-stream.js` 的 `mapEntryToEvent` 逐条带上），
所以**不依赖** `phase-start/phase-end` 这两个事件——步数＝事件条数，总耗时＝首末事件 `at` 之差。
（`phase-start/phase-end`、`cancel-result`、`pending-item` 当前均**未产出**，接口清单 §四 标注为"预留"；映射见 §四。）

**展开态**：先给 L2 **要点**，再给一层 L3 入口。

```text
▾ 思考过程 · 6 步 · 2.4 秒
    理解   识别为「借教室」· 教室=数智楼123 · 日期=明天 · 时间=下午两点到四点
    判定   这个时段是空的 ✓ · 这间教室不在检修 ✓ · 我没有重复提交过 ✓
    调用   提交教室预约 ✓
    完成   
    ▸ 查看完整留痕（12 条）
```

**部分展开**（办不成 / 需人工时的默认）：**只展开导致这个结果的那几行**，其余仍收起。

```text
▾ 为什么没办成 · 2 项没通过
    判定   这个时段是空的 ✖（这个时段已被别人占了）
    调用   提交教室预约 ✖（系统拒绝了这次提交）
    ▸ 其余 4 步与完整留痕（12 条）
```

要点行的生成规则（**这就是"输出结构化"的落点**）：

| 规则 | 说明 |
|---|---|
| **按阶段归并，不逐条平铺** | 同一阶段的多条事件合成一行：`判定 5 项全部通过` / `判定 2 项未通过：这个时段是人占的 ✖、…` |
| **成功的只报计数，失败的逐条展开** | 全通过 → `判定 5 项全部通过 ✓`；有失败 → 每条失败单独一行，附人话名（来自术语对照表） |
| **只列"改变结论的"事件** | `call`（调用）与 `proposition-judged`（判定）为要点；`fact-collected`（事实收集）不进要点 |
| 每行结构 | `阶段名（6 字宽，等宽）` + `一句话` + `行尾状态符号` |

**L3 完整留痕**：再点开才是逐条流水（现有 `TrajectoryItem` 的渲染能力直接复用：状态图标 + 文本 + 依据 chips + 点开看原始证据 JSON）。

**默认展开状态（按任务状态决定，写死，避免"抖动"）**：

| 任务状态 | 折叠块默认 | 理由 |
|---|---|---|
| 运行中 | **全展开**（L2 全部要点） | 用户需要知道它在干什么 |
| 办成（DONE） | **收起**（一行摘要） | 结论已回答了全部问题，过程不必占地方 |
| **办不成（REJECTED / FAILED）** | **部分展开**：只展开失败链路（通常 1–3 行） | 用户第一个疑问是"为什么不行"——把原因摆出来，但不把整块摊开 |
| **不确定 / 需人工（UNRESOLVED）** | **部分展开**：展开"结果存疑 · 正在核对"相关行 | 让用户知道系统在核对什么、自己要等什么 |
| 被取消 | **部分展开**：已完成部分 + `已停止` 标记 | 如实说明停在哪，未做的步骤不假装完成 |

**"部分展开"的实现口径**：展开的事件集合 = `status ∈ {failed, uncertain, unavailable}` 的那些行，
外加**它们紧邻的上一条 `call`**（"谁拒绝了这次提交"通常就在那里）。其余要点与 L3 明细仍收起，
入口分别是"其余 N 步"与"完整留痕"。

**用户手动操作优先**：用户手动展开或被收起过之后，**不再自动变化**（本轮内持久，切走再回来仍保持）——
否则用户正在读的时候界面自己动了，比"默认不展开"更糟。

### 3.2 核心输出（`AnswerBubble`）

这是 L1，**唯一默认可见的助手内容**，按终态分四种形态（文案全部来自现有 `terminal` 事件与结果卡，不新造）：

| 情形 | 展示 |
|---|---|
| 办成 | `已为您订好数智楼123：2026-09-27 14:00–16:00，预约号 #120` + 淡色附注"推算依据：今天周X → 明天；14:00–16:00 按你说的钟点" |
| 办不成 | `这个时段已被占用` + `我已帮您找了同楼的 2 个备选 ▸`（点开列出候选，一点即改约） |
| 需要补充 | 追问句（现有 `input-required` 的 text）+ 意图候选按钮（现有能力） |
| 不确定 / 需人工 | `提交结果没能确认，已登记待人工核对` + `▸ 看查证过程` |

**结构化要求**：结论行用**较大字号 + 强调色**；附注用弱化小字；可操作项（候选、按钮）紧跟结论下方。一个气泡里不超过三个视觉层次。

## 四、事件 → 层级映射（实现依据）

事件 `type` 为闭集（接口清单 §四），逐一归档：

| event type | 层级 | 展示 |
|---|---|---|
| `input-required` | **L1** | 追问句（助手气泡）+ 候选按钮 |
| `terminal` | **L1** | 核心输出（按 §3.2 四形态） |
| `proposition-judged` | L2 | 归并为"判定 N 项…"，失败项逐条列出 |
| `call` | L2 | 归并为"调用 N 次"，逐条列接口的**业务语义名**（来自共享常量 `constants/display-names.js`，不出现路径） |
| `uncertain` | L2 | `结果存疑 · 正在核对` |
| `fact-collected` | L3 | 事实收集明细（术语表人话名） |
| `decision` | L3 | 内部决策留痕 |
| `audit` | L3 | 系统审计 |
| `phase-start` / `phase-end` | L3 | **当前未产出**（接口清单 §四 标注"预留"）——阶段边界由事件自带 `phase` 表达；若将来产出，归入留痕即可，**本方案不依赖它** |
| `cancel-result` | L2 | **当前未产出**（预留）——"已撤销"从 `decision` + `call`（补偿动作）推导，**不依赖本事件** |
| `pending-item` | L3 | **当前未产出**（预留）——UNRESOLVED 人工处置工作流（K6）尚未实现 |

**一处例外（重要）**：`decision` 里 `phase === 'P1'` 的那条（理解结果，"识别为「借教室」· 教室=…"）归 **L2**——
用户最关心"它到底听懂了什么"，把它压进 L3 会让"为什么它以为我要借 123"变得不可回答。

**零术语纪律不变**：界面文案里的命题/事实/规则名一律来自 `GET /api/meta/glossary`（现有 `useGlossaryStore`）；**任何情况下不出现接口路径、参数名、内部编号**。

## 七、影响面与风险

| 项 | 评估 |
|---|---|
| 后端 | **零改动**（事件与证据链已是现成数据） |
| 接口契约 | **零改动** |
| 前端文件 | 新增 7 / 改造 4 / 删除 3——是本轮主要工作量 |
| 风险 1 | 归并规则若写成"硬编码阶段名→文案"，会与引擎的规则表漂移 → **约束**：文案一律取自事件自身的 `text`（已是人话），`useThinking.js` 只做**选择与归并**，不新造句子 |
| 风险 2 | 折叠动画与 SSE 高频事件叠加会抖 → **约束**：运行中不做高度过渡，只在终态收起时做一次 |
| 风险 3 | `localStorage` 存会话有隐私面 → **实际做法**：存**轮次快照**（用户原话 + 事件 + 结果——不存这些，切过去的会话就是空的），**不存证据链明细**（可重拉，拉不到就如实说）；按**登录用户名**隔离；上限：会话 30 / 每会话 20 轮 / 每轮 150 条事件 |
| 演示影响 | 双屏逐字稿里**各幕**的轨迹讲解都需同步改写（**尤其第 1 幕**——"注意右边的执行轨迹……看轨迹里的身份徽章"是最依赖右栏的一处；第 3 幕讲的是幂等命中）。改法：步骤现在在对话里，"点开这一行就能看到身份徽章"。逐字稿在实现后一并更新 |

## 十、实现结果（2026-09-26）

# 13 · 开发手册

> **本章不是方案，是规格。** 前面十二章回答"为什么这么设计"，本章回答"实现时守什么"。
>
> **本章不含代码。** 它规定的是**模块边界、契约、禁止项与验收标准**；具体写法由实现者决定。
>
> **阅读方式**：动手前通读一遍；每完成一个阶段，回到 §六 的验收清单对照自检。

---

## 一、开发顺序：从确定性底座往上，理解层放最后

**决定：按下列顺序开发，不跳步。**

```text
阶段 0  规范口径 + 证据层           ← 一切的基础
阶段 1  接触层（协议适配 + 身份池）   ← 先能真实调通一个只读接口
阶段 2  判定层（事实 + 命题）        ← 先能回答"能不能办"
阶段 3  编排层（状态机）             ← 先跑通正常链路
阶段 4  接入层（对外入口）           ← 对外可调用
阶段 5  理解层（接上自然语言）        ← 此时才引入非确定性
阶段 6  混沌（故障注入 + 实验）       ← 才开始验证
阶段 7  前端
阶段 8  演示脚本与实景演练
```

> **计数口径（二审统一）**：阶段 0 是底座，**计入总数**——因此本手册的完整开发顺序是 **9 个阶段（0–8）**。此前索引页（方案总纲 / `docs/README.md`）写作"8 阶段"，指的是阶段 1–8；两种写法并存易误读，已统一为"9 阶段（0–8）"。

### 1.1 为什么是这个顺序

| # | 理由 |
|---|---|
| 1 | **底座错了，上面全错**：时间口径（第 06 章 §六）与证据链（I4）如果一开始没定，后面每一处都会各写一套 |
| 2 | **先能调通再谈判定**：接触层先行，可以让"存量系统到底怎么响应"这个事实尽早被撞到，而不是等架构写完才发现 |
| 3 | **理解层放最后，因为它可替换**：把它放前面，会诱使先做"看起来像 AI 的东西"，而那是本项目最不核心的部分 |
| 4 | **混沌在开发完成后、前端之前**：此时链路已完整可跑，注入才有意义；而在前端之前，是因为**前端要展示的实验结果得先存在** |

### 1.2 每个阶段必须有可验收的产出

**禁止"写完了但看不出来"。** 每阶段的验收方式见 §六。

## 二、模块规格

**每个模块给出四件事**：职责、对外契约、禁止项、验收标准。

---

### 阶段 0 · 规范口径

| 项 | 内容 |
|---|---|
| **职责** | 集中定义被多层共用的口径：**时间语义**（按 UTC 解释出参、显式构造入参）、命名映射、常量集合（失效状态值等） |
| **契约** | 对上层只暴露**语义化**的操作（如"把这个时间字符串变成绝对时刻""把这个范围变成人可读的文字"），**不暴露时区概念** |
| **禁止** | ① 在业务逻辑里出现"本地时区"这一概念 ② 各处自行解析时间字符串（**只允许一处**） |
| **验收** | 构造一个"只在两种时区解释下结论不同"的用例，验证结果正确（第 06 章 §6.2） |

---

### 阶段 0 · 证据层

| 项 | 内容 |
|---|---|
| **职责** | 记录每一步的**输入、依据、结论**（I4）；产出可导出、可复核的证据链 |
| **契约** | ① 每个有后果的动作**必须**携带依据引用，缺失即报错 ② 证据链可独立导出，**不含任何凭证** ③ 分两档：**结构化结果**（进证据链）与**模型原始输出**（单独留档，不进证据链） |
| **禁止** | ① 把模型的原始输出写进证据链 ② 记录凭证 ③ 让证据链成为"只写不读"的东西（必须能被界面消费，第 10 章 §6.1） |
| **验收** | 任取一次拒绝，能回答"依据哪条事实、哪条命题、什么时刻"；导出内容中不含凭证 |

---

### 阶段 0 · 交付物清单（二审补齐）

**问题**：本阶段此前只有职责与字段规格，没有说"要产出哪些文件"；而"配置数据格式"已在决策汇总 A1 定为 **YAML**。实现者据此无法建文件。以下是**阶段 0 的验收对象**（文件名可按实现习惯微调，但**三份配置数据必须各自独立成文件**）：

| # | 交付物 | 形式 | 最小内容 |
|---|---|---|---|
| 1 | 时间口径模块 | 代码模块 | 出参按 UTC 解释、入参构造带 `Z` 的时刻、内部一律用绝对时刻、展示层单向转本地；**模糊时间表达按部署地时区（UTC+8）解释**；三段常量**上午 08:00–12:00 / 下午 13:00–17:00 / 晚 18:00–22:00**；同北京自然日、开始时间在未来（三审 K2/J4，第 08 章 §7.2/§7.5） |
| 2 | 常量集合 | YAML | 预约有效集 `{ACTIVE}` 与失效集 `{CANCELLED,EXPIRED}`；维修失效集（实测 `{CANCELLED}` + 防御扩展）；时段严格不等号；安全阈值 500；候选上限 K=5；各循环上限（追问 3 / 降级 3 / 正向查证 2 / 补偿重试 1 / **任务总步数 60**，三审 K1）；写接口 3s / 读接口分级超时（B3 初始样本 avg 14ms） |
| 3 | 接口注册表 | YAML（**独立文件，K4 拍板**） | 第 01 章 §四 的 **13 个字段** × 12 条接口；自动编排标志：classroom.create=是、cancel=是、seat.create=**否**（D2）、maintenance.create=**否**（M8） |
| 4 | 意图计划 | YAML（**独立文件，K4 拍板**） | 每个意图：必填/可选槽位、步骤链、所需命题、降级策略、是否只读 |
| 5 | 身份声明 | YAML（**独立文件，K4 拍板**） | 身份标识 → 环境变量名（**只写变量名**）+ 绑定的具体账号（TEACHER=233 等） |
| 6 | 证据层 | 代码模块 + 导出格式 | 每步的输入/依据/结论；可独立导出；结构化结果与模型原始输出分档 |
| 7 | 结构自检入口 | 可执行入口 | 第 04 章 §十一 的 8 条自检，一键跑出；输入是交付物 3 与 4 |

**共同纪律**：交付物 1–6 不得含任何凭证；交付物 3–5 **三份配置各自独立成文件**（K4 三审拍板）且支持注释（A1 选 YAML 的理由）。

### 阶段 1 · 接触层

| 项 | 内容 |
|---|---|
| **职责** | ① **唯一**能发起对存量系统请求的地方 ② 按注册表选择身份、注入凭证 ③ 吸收协议异构（字段命名、时间格式、错误语义） ④ **执行三值判定**（第 05 章规则表） |
| **契约（对上层）** | 输入：逻辑调用名 + 参数（语义化）。输出：**三值结论 + 原因分类 + 依据**。**不输出 HTTP 状态码、不输出原始响应体、不输出凭证** |
| **契约（对下层）** | 按注册表声明的身份取凭证；凭证**只在本模块内流转** |
| **禁止** | ① 做业务判定（"能不能借"不属于它） ② 决定要不要重试 ③ 把原始信号泄漏给上层 ④ 让判定规则散落到本模块之外 |
| **验收** | ① 全仓库搜索：除本模块外无对存量系统的请求发起 ② 三值判定的每一种情形在规则表里都有对应行 ③ 凭证不出现在日志/证据链/界面 |

**本模块的三处必须写死的行为**：

| # | 行为 | 依据 |
|---|---|---|
| 1 | 判定必须**先看业务码、最后看 HTTP 状态码** | 第 05 章 §5.2；否则会产生假成功 |
| 2 | 只读与写在**超时/5xx/401** 上处置不同（读可重试、写须查证） | 第 05 章 §4.1 vs §4.2 |
| 3 | 查证**不带 `keyword`**，拉全量后内存比对 | 第 06 章 §五；实测其匹配范围与名字不符 |

---

### 阶段 2 · 判定层

| 项 | 内容 |
|---|---|
| **职责** | ① 按命题声明的依赖**驱动事实收集** ② 逐条判定命题 ③ 输出**判定结论 + 依据引用 + 是否可降级** |
| **契约** | 输入：结构化意图。输出：命题判定结果集合（每条含结论、依据、可降级性）。**不发任何写请求**（只读也统一经接触层） |
| **禁止** | ① 自己发 HTTP ② 把"事实不可得"当作"命题不成立"（第 08 章 §三） ③ 在命题里引用接口路径/字段名 ④ 只验"失败的那一条"就进入降级（第 08 章 §8.2） |
| **验收** | ① 新增一条只依赖已有事实的命题，**代码零改动** ② 事实不可得时，结论是"无法确认"而非"不成立" ③ 降级后新方案全部命题被重验 |

**本模块的三条必须写死的口径**：

| # | 口径 | 依据 |
|---|---|---|
| 1 | 占用座位数 > 0 → 视为整间不可用；返回全量座位 → **必须标记歧义** | 第 08 章 §2.2 |
| 2 | 维修窗口失效状态用**排除法**（保守优先） | 第 08 章 §五 |
| 3 | 时段比较用**重叠**而非相等，且按 UTC 解释 | 第 06 章 §2.2、§六 |

---

### 阶段 3 · 编排层

| 项 | 内容 |
|---|---|
| **职责** | 状态推进、分支、重试决策、降级决策、补偿决策；产出**唯一确定的终态** |
| **契约** | 输入：结构化任务。输出：终态 + 证据链 + 用户可读结论 |
| **禁止** | ① 直接发 HTTP ② 直接调大模型 ③ 直接读注册表数据文件（经记录在册的访问入口） ④ **在数据文件之外硬编码接口名/字段名/身份名/状态值** |
| **验收** | ① §三 的 8 条结构自检全通过 ② 正常链路 + 5 个异常场景全部给出正确终态 ③ 非法转移被显式报错（不是静默通过） |

**本模块的三条结构性约束（来自第 04 章 §六）**：

| # | 约束 | 检查方式 |
|---|---|---|
| 1 | 副作用只能从**提交态**发出，且其入边恰好三条、每条可追溯到一次显式决策 | 自检项 5 |
| 2 | `UNKNOWN` 无直通成功终态的边 | 自检项 6 |
| 3 | 被标记"禁止自动编排"的接口不被任何计划引用 | 自检项 8 |

---

### 阶段 4 · 接入层

| 项 | 内容 |
|---|---|
| **职责** | 对外入口：参数形状校验、调用编排层、响应包装；**事件流**（执行步骤实时推送，第 10 章 §六） |
| **契约** | ① 对外统一返回结构；**事件消息的字段与顺序规格见第 10 章 §6.3**（`seq` / `taskId` / `type` / `phase` / `status` / `evidenceRef` / `text` / `at`），**且对外接口清单（端点 / 方法 / 请求响应结构 / 错误码）必须在实现时登记**（二审补齐：此前只写"统一返回结构"，没有形状） ② 步骤事件与**证据链同源** ③ 允许**结构化任务**入口（无大模型路径，第 03 章 §十） |
| **禁止** | ① 任何业务判断 ② 自行补全或推断执行步骤 ③ 输出凭证 |
| **验收** | ① 事件流内容与证据链逐条一致 ② 结构化任务入口不经过理解层 ③ 两条路径汇入**同一段**编排逻辑（第 03 章 §十 纪律） |

---

### 阶段 5 · 理解层

| 项 | 内容 |
|---|---|
| **职责** | 自然语言 → 结构化意图（意图 + 原始槽位片段 + 置信度 + 超域标记 + 追问话术） |
| **契约** | ① 输出过 Schema 校验 ② `intent` 取自**闭集** ③ 槽位存**原话片段**，禁止出现换算后的时间 ④ **不进入证据链**，单独留档 |
| **禁止** | ① 决定调哪个接口 ② 做时间换算 ③ 做实体消解 ④ 做业务判定 ⑤ **提示词中出现任何接口信息** |
| **验收** | ① 输出去掉理解层后链路完整可跑 ② 提示词中零接口信息 ③ 模型输出 ISO 时间时**被契约校验拒绝** |

**本模块的三道闸门必须实现**（第 03 章 §五）：

| 闸门 | 内容 |
|---|---|
| 一 | 意图必须属于已登记闭集，**不允许"最接近的意图"兜底** |
| 二 | 置信度达标；不达标则**列出候选意图让用户选**，不是"请再说一遍" |
| 三 | 槽位缺口**由注册表机械计算**，**不采信模型给的缺口** |

### 阶段 6 · 混沌

| 项 | 内容 |
|---|---|
| **职责** | 在接触层出站管道上注入**可控、可重放、命令式**的故障；采集实验证据 |
| **契约** | ① **默认撤防** ② 撤防时与"没有这套机制"**完全一致** ③ 注入生效时**在所有输出上显式标注** ④ 注入按"接口 + 第 N 次调用"粒度 |
| **禁止** | ① 随机比例注入 ② 伪造响应代替真实转发（第 09 章 §3.1） ③ 在演示路径上保持开启 ④ 修改存量系统 |
| **验收** | ① D0 撤防对照通过（与"无注入"行为逐项一致） ② D1–D6 全部跑通且**连续 3 次结果一致** ③ **D7（提示词对照）按已定样本量跑完并留档**（样本量未定时可标记为"可选"，见第 09 章） ④ 每次实验产出 §八 的 7 项证据 |

### 阶段 7 · 前端

| 项 | 内容 |
|---|---|
| **职责** | 把"可解释性"外化为可看见的三视图（对话 / 轨迹 / 结果） |
| **契约** | ① 展示内容**全部来自事件流**，不自行推断 ② 三值有专门形态（含"不确定"） ③ 支持深浅两套主题 |
| **禁止** | ① 组件直连存量系统 ② 组件直接调 `fetch` ③ 展示接口 URL / 参数名 / 状态机状态名 ④ "不确定"状态下提供重试按钮 |
| **验收** | 第 10 章 §八 的四个问题能被一眼回答 |

## 三、状态机的 8 条结构自检

**实现时必须能一键跑出下面 8 项。** 它们检查"结构是否仍符合设计"，而不是"功能是否正常"。

| # | 自检项（三审已与第 04 章 §十一 逐字对齐） |
|---|---|
| 1 | 每个状态都能从初始态到达 |
| 2 | 每个非终态都有出边（**"忽略型无边"不算没有出边，见第 04 章 §5.6/§5.9**——挂起态有出边：用户回复/取消；提交中的取消是忽略型无边，另有审计落点） |
| 3 | 每个 `(状态 × 目的 × 载荷)` 的出边事件不重复 |
| 4 | 终态没有任何出边（**含忽略型无边也不出现**在终态） |
| 5 | 提交态的入边恰好三条，且每条可追溯到一次显式决策事件 |
| 6 | **没有由 `CALL_*` 事件直通 `DONE` 的边**（`VERIFY_FOUND` 经查证落 `DONE` 是刻意的，见第 04 章 §5.3 注三） |
| 7 | 每个终态都至少有一条入边 |
| 8 | 被标记"禁止自动编排"的接口不被任何计划引用 |

> **三审修正**：本表第 2/3/6 项在二审更新第 04 章后未同步（分别残留"挂起态除外""× 目的""补偿语境除外"的旧措辞），三审按第 04 章 §十一 权威文本对齐。

**执行时机**：每次改动后（第 04 章 待决 6）。**自检不过不允许继续开发。**

## 四、配置数据的规格

**与存量系统有关的一切外部知识以数据形式集中存放**（第 02 章 §八）。三份数据各自的必填字段如下。

### 4.1 接口注册表

**每条接口必须声明**（第 01 章 §四 的 **13 个字段**）：

| 字段 | 缺失后果 |
|---|---|
| 标识 | 被编排逻辑引用，缺失则无法引用 |
| 域 | 用错身份 → 静默 403，被当成业务失败 |
| 方法 + 真实路径 | 硬编码散落 |
| 用途 | 接口清单变垃圾场 |
| 所需身份 | 退化到"全用 ADMIN" |
| 是否有副作用 | 把写接口当只读用 → 静默改数据 |
| **是否允许自动编排**（默认**否**） | 不可补偿的写操作进入自动链路 → 制造无法回收的副作用。**不得用"是否有副作用"代替**——第 01 章 §七 M8（二审补齐：此前 12 字段漏了这一维，M8 却要求它） |
| 幂等业务键 | 查证无从比对（补偿动作可豁免） |
| 查证路径 | `UNKNOWN` 无法收敛（**硬门槛**） |
| 补偿动作 或 不可补偿登记 | 半成品留在库里（**硬门槛**） |
| 前置命题 | 漏查条件 → 脏数据 |
| 适配器 | 判定规则散落 |
| 实测注意事项 | 后人按直觉改 |

### 4.2 意图计划

| 字段 | 说明 |
|---|---|
| 意图标识 | 与理解层输出闭集同源 |
| 必填槽位 / 可选槽位 | **槽位缺口的唯一来源**（闸门三） |
| 步骤链 | 每步引用一个接口标识（**只能引用允许自动编排的接口**） |
| 所需命题 | 该意图下必须成立的全部命题 |
| 降级策略 | 可降级的命题 + 候选选择规则 + 轮次上限 |
| 是否只读 | 决定终态是 `DONE` 还是进入提交 |

### 4.3 身份声明

| 字段 | 说明 |
|---|---|
| 身份标识 | 供注册表引用 |
| 凭证来源 | **只写"从哪个环境变量取"，不写值** |
| 业务身份语义 | 用于幂等业务键中的"身份"分量（第 06 章 §2.2）；**一个业务身份必须绑定一个具体账号**（如 TEACHER = 账号 233），凭证池不得在同一业务身份下混用多个账号——否则"我写的"比对漂移（一审澄清） |

**三份数据的共同纪律**：

| # | 纪律 |
|---|---|
| 1 | **不得在业务逻辑里硬编码**接口路径、字段名、身份名、状态值集合 |
| 2 | 数据的**完整性可被自检**（缺必填字段 = 缺陷） |
| 3 | 数据中**不得出现凭证**；凭证只出现在环境变量中 |
| 4 | 支持注释（第 01 章每条接口都带实测注意事项，它们本身是文档） |

## 八、实验证据的规格

**混沌实验的产出不是"通过/不通过"，是一份可被第三人复核的记录**（第 09 章 §八）：

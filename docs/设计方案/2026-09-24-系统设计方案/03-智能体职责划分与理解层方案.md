# 03 · 智能体职责划分与理解层方案

> 本章解决：**大模型在这个系统里到底干什么、它的输出长什么样、它凭什么可信。**
>
> 本章是 `docs/基线文档/智能体设计.md` §7.3（LLM 与状态机的职责切分）的展开。
>
> **本章不含代码。** 文中的字段表是**契约规格**（有哪些字段、什么含义、缺失会怎样），不是实现。

---

## 一、先摆正位置：理解层是全系统唯一的非确定性来源

这句话不是修辞，是一条**结构约束**（第 02 章 §四 约束 C）。

它的推论比它本身重要：

| 推论 | 说明 |
|---|---|
| **它只能出现在开头** | 一件事里最多问一次（追问轮除外）。若允许"执行到中途再问一次"，非确定性就进入了执行链 |
| **它的输出不能被当成事实** | 它说"周三下午"，这只是**用户话里的字符串**，不是日期；它说"数智楼222"，这只是**人名一样的东西**，不是教室 ID |
| **它不可复现，所以不能进证据链** | 同一次输入重跑可能得到不同措辞。证据链里只能记**结构化结果**，它的原始输出单独留档 |
| **去掉它，链路仍须完整可跑** | 这是可验证性前提，也是答辩时的演示保险 |

---

## 二、三种时刻的归属：理解层只负责 A

`智能体设计.md` §一给出了三种时刻。它们**不是同一层的事**，这一点常被混淆：

| 时刻 | 问题 | 归属 | 为什么不能给 LLM |
|---|---|---|---|
| **A 理解** | 用户说的话不全，该问什么？ | **理解层** | —— |
| **B 聚合** | 事实散落多处，怎么拼出可判定结论？ | **判定层** | 这是**跨权限域的事实拼接**，涉及"哪个事实更权威""缺一份事实怎么办"。交给 LLM 等于把正确性交给概率 |
| **C 确定** | 调用发出去了，到底成没成？ | **接触层 + 编排层** | 这类判断必须**穷举且可复现**。同一响应今天判成功、明天判失败，系统就不可信 |

**一句口径**：

> **理解层回答"用户想要什么"，其他一切都由确定性组件回答。**

一个常见的越界冲动：让 LLM"综合判断一下这间教室能不能借"。它看起来很擅长这种事。但它的判断**无法复述依据**——而 I4（可解释）是本项目与"脚本"的分野。

## 三、LLM 能做什么、绝对不能做什么

**能做的（穷举，超出即为越界）**：

| # | 能做 | 输出形态 |
|---|---|---|
| 1 | 判断用户这句话**对应哪个已登记意图** | 意图标识符（取自闭集） |
| 2 | 从原话中**摘出可能相关的字符串**（教室名、日期说法、时段说法） | 原样字符串，**不做换算** |
| 3 | 判断**缺哪些必填信息** | 缺失字段名列表 |
| 4 | 给出**置信度** | 数值 |
| 5 | 在信息不足时，**生成一句追问** | 自然语言（仅用于呈现，不参与判定） |
| 6 | 判断输入**是否超出业务域**（该拒答） | 布尔 + 理由 |

**绝对不能做的**：

| # | 不能做 | 一旦做了会怎样 |
|---|---|---|
| 1 | 决定调用哪个接口 | I4 崩溃；幻觉直落副作用，不可恢复 |
| 2 | 做**时间换算**（"下周三"→具体日期） | 模型处理相对日期不可靠，且无法审计。**换算交给确定性归一化** |
| 3 | 做**实体消解**（"数智楼222"→教室 ID） | 需要查存量系统，且可能重名/不存在。**交给判定层** |
| 4 | 做**业务判定**（能不能借、算不算冲突） | 与 I3 冲突 |
| 5 | 生成接口参数值（时间格式、字段名） | 命名与格式异构由接触层吸收，模型不该知道这些 |
| 6 | 决定是否重试、是否补偿 | 与 I2 / I6 冲突 |
| 7 | 直接回答用户的业务问题（"这间教室周三下午空的"） | 它没有事实依据，答案是编的 |

> **第 7 条要特别小心**。会话式产品里，模型"顺便回答一句"是很自然的。但在这个系统里，**任何业务结论都必须来自事实**。若模型直接答"周三下午空的"，而系统事实显示有人占了座位，用户就会拿到一个假答案，且系统以为自己什么也没做。

## 四、输出的契约

理解层的输出必须是**受约束的结构化数据**。字段如下（这是规格，不是示例）：

| 字段 | 含义 | 类型 | 缺失/不合规时 |
|---|---|---|---|
| `intent` | 意图标识 | 字符串，取自已登记集合 | **必须**属于闭集；不在闭集 → 该次输出作废 |
| `slots` | 从原话中摘出的槽位字符串 | 键值表，键为槽位名 | 允许为空（表示为缺） |
| `missing` | 判定为缺失的必填槽位 | 字符串数组 | 可以为空 |
| `confidence` | 整体置信度 | 0–1 数值 | 低于阈值 → 不进入执行 |
| `outOfDomain` | 是否超出业务域 | 布尔 | 为真 → 拒答，不追问 |
| `clarifyQuestion` | 追问话术 | 字符串，可空 | 仅用于呈现 |
| `reasoning` | 一句话说明判断依据 | 字符串，可空 | **不进入证据链**，仅用于调试与留档 |

**三条格式纪律**：

1. **`slots` 里存的是原话片段，不是换算结果。** 用户说"下周三下午"，槽位就存 `"下周三"` 与 `"下午"`。**禁止**出现 `"2026-09-30"` 这类模型自己算出来的值。
   - 理由：模型算错日期时，系统无法察觉（它看起来是个正常值）；而存原话时，归一化器的规则是**可审计**的。
2. **`missing` 必须与槽位定义一致。** 它不能是模型"感觉还缺点什么"，而必须是"注册表声明的必填槽位里，`slots` 未提供的那些"。**这个计算由编排层做，不由模型做**（见 §五 闸门三）。
3. **`reasoning` 不作为依据。** 它写得再合理也不能支撑任何判定——它是模型的说明，不是事实。

> ### ★ 一处关键决定：槽位的归一化**不在**理解层
>
> **决定**：理解层只摘原话；`"周三"` → 具体日期、`"下午"` → 时段区间，由**第 08 章的归一化规则**完成。
>
> **为什么**：
>
> | 理由 | 说明 |
> |---|---|
> | 模型算日期不可靠 | 相对日期（下周三、这周五、明天）出错时**不报错**，只算错——这比报错危险 |
> | 归一化必须可审计 | "为什么算成了 09-30？"要能回答"因为今天是周四，'下周三'落在下一个周三"。模型的解释不算解释 |
> | 换算规则本身需要被评估 | 用户看到"下午 = 第 7~8 节"时可能不认同（第 08 章）。这条规则要能被单独推翻 |
>
> **备选与被排除的理由**：让模型直接输出 ISO 时间。看起来省一步，代价是**把一个不报错的错误源埋进判定链**——而且它埋在最前端，后面所有基于时间的判定（时段重叠、维修窗口）都会跟着错。
>
> **代价**：归一化规则需要显式定义"周三""下午""明天"等表达，规则集要维护；遇到规则外的表达只能追问。
>
> **可行性评估点**：需要你确认这个切分。我判断不了的是：演示时用户会说什么样的时间表达。**若演示脚本会用"下周三下午两点到四点"这种带具体钟点的说法**，归一化规则集需要覆盖钟点解析；**若只说"周三下午"**，规则集可以很小（相对日 + 半天）。这取决于你打算怎么演。

## 五、三道闸门：模型说了不算

编排层在拿到理解层输出后，**必须**依次过三道闸门。任何一道不过，都不进入执行。

### 闸门一：意图必须已登记

- 模型给的 `intent` 必须属于**已登记的闭集**（当前：借教室、查询教室可用性）
- 不属于 → 该次输出作废，回到**格式重试**（§五.4），重试仍不合规则拒答
- **禁止**用"最接近的意图"兜底。猜错意图会导致用户在**不知情的情况下**办了另一件事，且这件事可能有副作用

### 闸门二：置信度必须达标

- 数值化阈值（当前设想 **0.55**，见待决清单）
- 低于阈值 → **不猜，追问**
- **追问的正确形态**：不是"我没听懂，请再说一遍"（把问题推回用户），而是**列出候选意图让用户选**（"您是想**借这间教室**，还是只想**查它这个时段空不空**？"）

### 闸门三：槽位缺口必须由注册表机械计算

- **禁止**直接采信模型给的 `missing`
- 正确做法：取注册表里该意图声明的必填槽位集合，减去 `slots` 里已提供的键，**差集即缺口**
- **为什么**：模型可能漏报（"我觉得够了"）或误报（"少个备注"）。缺口是**结构信息**，不该由概率组件提供

### 五.4 「格式重试」的规格

| 项 | 规格 |
|---|---|
| 触发 | 输出不合法（字段缺失、类型不符、`intent` 不在闭集） |
| 次数上限 | **2 次**（即最多 3 次总调用） |
| 重试方式 | 把**不合规的具体原因**回灌给模型（"你上次给的 `intent` 不在允许集合内，允许集合是…"），而不是原样重发 |
| 仍失败 | 降级为"系统无法理解该请求"，**如实上报**，不编造意图 |
| 不计入重试 | **网络超时 / 限流**不算格式不合规，走另一条处置（§十） |

## 六、★ 第二处关键决定：提示词里**不含任何接口信息**

**决定**：系统提示词不告诉模型"有哪些接口""接口要什么参数"。

**模型需要知道的只有三样**：① 你是谁 ② 能办哪两件事 ③ 输出什么格式。

**为什么这条如此重要**：

| 若提示词里写了接口 | 后果 |
|---|---|
| 模型会试图**帮忙**决定调哪个接口 | 直接违反"LLM 无权决定调用哪个接口"（§三 禁忌 1） |
| 接口路径/字段名会渗进模型输出 | 命名异构（snake/camel 混用、`resourceType` 之类）会污染理解层，而吸收异构是接触层的职责 |
| 存量系统加一个接口就要改提示词 | 提示词变成需要跟着接口变化的产物，与"理解与执行解耦"背道而驰 |
| **测试无法验证解耦** | 若模型知道接口，就无法证明"去掉模型系统仍能跑" |

**推论**：**理解层对接口的认知量为零。** 它只知道"用户在说借教室还是查教室"，不知道这件事要打几个接口。

> **可行性评估点**：需要你确认这条。我判断不了的是：不给接口信息是否会让模型在某类表达上明显变差。**从原理上不会**——模型的任务是"把中文话拆成意图+槽位"，这件事不需要知道后端有什么接口。但**这需要一次对照实测**才能下定论（提示词含接口 vs 不含接口，各跑一组样本比准确率）。这条实验建议纳入第 09 章。

## 七、提示词的组织

虽然内容不写在这里（它是实现物），但**结构**必须在方案里定死，否则改提示词时会随意增删。

| 段 | 内容 | 纪律 |
|---|---|---|
| **角色段** | 说明它是"校园事务代办助手"，职责是**澄清需求**，不是回答问题 | 不得出现"你是一个全能的助手"这类扩展授权 |
| **业务词表** | 校园场景的术语（教室、时段、节次、楼栋、维修…） | 只给**术语**，不给接口 |
| **意图清单** | 两个意图各自的定义 + 各自需要的槽位 | 与注册表**同源**（从注册表生成，不手抄） |
| **输出契约** | §四的字段表 + 格式要求 | 必须与校验规则一致；改一处必须同步另一处 |
| **少样本** | 若干"原话 → 输出"的例子 | 例子必须**只含原话片段**，不得出现换算后的日期 |
| **拒答边界** | 什么算超域（与第 01 章 §八 的不纳管清单对应） | 与边界文档 §四 速查表对齐 |

**三条纪律**：

1. **意图清单与槽位定义从注册表生成，不手写。** 手写就会出现"提示词说要三个槽位、注册表说两个"的不一致，而这种不一致**不会报错**，只会表现为"有时莫名其妙地追问"
2. **少样本里的错误示范要显式标注。** 例如"❌ 不要输出 `2026-09-30`，要输出 `下周三`"——**只给正例，模型会模仿正例的形式但不理解边界**
3. **提示词改动必须走变更记录。** 它是行为的一部分，不是文案

## 八、多轮追问：问什么、不问什么、问几次

### 8.1 只问"必填且缺失"的

| 情形 | 处置 |
|---|---|
| 必填槽位缺失 | **问** |
| 可选槽位缺失 | **不问**，用默认值，且在结果里**标注"按默认处理"** |
| 槽位有值但系统不认识 | **按规则尝试归一化**；成功则继续，并在结果里**标注"请确认"**；失败则**问**（不要静默丢弃） |
| 输入超出业务域 | **不追问**，直接拒答（追问等于承认我们在处理它） |

> 「标注请确认」这个设计是刻意的：它让系统在"推断错了"的情况下**仍可被发现**。若静默推断，用户只有在事情办砸之后才知道理解错了。

### 8.2 追问次数上限

**决定：不超过 3 轮**（即最多 3 次追问）。

超过则终止，并给出**结构化说明**："要办这件事，我需要知道"（列出还缺什么）。

**为什么设上限**：超过 3 轮说明要么用户表达方式超出系统能力、要么意图本身没识别对。继续问下去只会让用户烦躁，而**系统仍然办不成事**。此时如实承认比无限追问诚实。

### 8.3 追问的话术来源

| 来源 | 用于 |
|---|---|
| 模型的 `clarifyQuestion` | 常规追问（自然语言更自然） |
| **编排层按缺口生成** | 当模型的话术缺失、或缺口很明确时（如"缺哪一天"） |

**纪律**：追问中**禁止出现接口术语**（不能问"请问 `min_capacity` 是多少"）。用户不懂接口，把他当成"没有系统权限的普通学生"（边界文档 §一）。

## 九、失败模式与处置

理解层的每一种失败都必须有明确归宿，**不允许"尽力而为"**。

| 失败模式 | 表现 | 处置 | 依据 |
|---|---|---|---|
| **Schema 不合规** | 字段缺失/类型错/意图不在闭集 | 格式重试 ≤2 次；仍失败 → 如实上报"无法理解" | I4 |
| **意图识别错** | 输出一个合法意图，但用户其实想办另一件事 | **无法在理解层检测**。靠闸门一（闭集）+ 结果呈现时的可读性让用户发现 | —— |
| **槽位漏抽** | 原话里有教室名，`slots` 里没有 | 表现为"多问一轮"，用户体验下降但不致错 | —— |
| **槽位错抽** | 把"数智楼222"抽成"数智楼" | 归一化时解析不到 → 拒绝并列出可用项（用户可自行纠正） | I4 |
| **模型自己算了日期** | `slots` 里出现 ISO 时间 | **契约校验拒绝**（见 §四 纪律 1）；重试；仍出现 → 丢弃该槽位并要求用户重说 | I4 |
| **网络超时** | 未收到响应 | 理解层**无副作用，可安全重试**（与写操作相反）。重试 ≤2 次 | —— |
| **限流 / 配额耗尽** | 模型返回限流错误 | **降级**：不重试，转为"请直接选择要办的事"（给出意图按钮），绕过模型 | I3 |
| **模型服务不可用** | 连续失败 | 走 §十 的"无 LLM 路径" | —— |
| **模型编造业务结论** | 在 `clarifyQuestion` 里说"这间教室周三下午是空的" | **契约上无法拦截**（它是自由文本）→ 因此**追问话术由编排层审核/拼接**，不原样透传给用户 | §三 禁忌 7 |
| **置信度虚高** | 低质量输入给出 0.9 | 靠闸门三（槽位机械计算）兜底；**阈值需实测标定** | —— |

> **注意"模型编造业务结论"这一行**。它是自由文本，格式校验管不到。**唯一可靠的对策是不让它直接面向用户**——追问话术与结果陈述都由编排层组装，模型的话术只作为素材。
>
> 这条代价是话术会略显机械（"请补充：哪一天"）。**这个代价是值得的**：它是"任何业务结论都必须来自事实"这条纪律的落地方式。

## 十、★ 第三处关键决定：没有 LLM 也能跑

**决定**：编排层必须支持**直接接收结构化任务**（意图 + 槽位），完整走通全链路。

**这不是"为了测试方便"的附属能力，有四条独立价值**：

| # | 价值 | 说明 |
|---|---|---|
| 1 | **可测试** | 第 09 章的混沌实验需要确定性输入。若每次实验都要先过一次模型，失败就无法归因（是注入的故障还是模型的发挥？） |
| 2 | **演示保险** | 答辩现场网络不通或模型限流时，切到预置任务继续演示，链路不中断 |
| 3 | **证明解耦** | "LLM 只是可替换的外部依赖"这句话，只有去掉它还能跑，才成立 |
| 4 | **可回归** | 改提示词时，可以用固定输入集比对"结构化任务路径"与"自然语言路径"的结果差异，把回归范围缩到最小 |

**形态**：对外接口上，请求体允许**二选一**——给自然语言，或直给结构化任务。给结构化任务时，理解层**零调用**。

**纪律**：**结构化任务路径与自然语言路径必须汇入同一段编排逻辑。** 不允许为"结构化任务"写一条简化的旁路——那样两条路径的行为会漂移，而漂移是不可测的。

## 十一、明确排除的做法

| # | 排除 | 理由 |
|---|---|---|
| 1 | ~~让 LLM 直接 function calling~~ | §三 禁忌 1；不可解释、不可复现 |
| 2 | ~~让 LLM 输出换算好的时间~~ | §四 关键决定；埋进不报错的错误源 |
| 3 | ~~在提示词里列出接口清单~~ | §六；污染理解层并破坏解耦 |
| 4 | ~~直接采信模型给的 `missing`~~ | §五 闸门三；缺口是结构信息 |
| 5 | ~~让模型做多轮自主决策（Agent Loop 式）~~ | 自主循环会走出闭集。本项目的意图是**闭集**，编排是**确定性的**；一旦允许模型决定下一步做什么，就不再有"可复述的执行路径" |
| 6 | ~~把模型的 `reasoning` 写进证据链~~ | §四 纪律 3；非确定性不可作依据 |
| 7 | ~~微调或自训模型~~ | 边界文档 §四：只调用第三方 API |
| 8 | ~~用模型做超域判断的兜底（"它觉得能办就试试"）~~ | 超域应拒答；"试试"在有副作用的链路上等于赌博 |
| 9 | ~~把追问话术原样透传给用户~~ | §九；模型可能编造业务结论 |

> **第 5 条值得单独强调**：市面上大量"Agent"产品是自主循环的——模型决定调什么工具、看结果、再决定下一步。**本项目明确不做这个。** 理由是它直接摧毁 I4：当模型自主决定下一步时，"为什么这一步"的答案只能是"模型当时觉得应该"。而我们的立论正是"可解释可恢复"。
>
> **这不是能力不足的妥协，是设计选择。** 答辩时若被问"为什么不让 Agent 自主规划"，这就是答案。

# 2026-09-25 界面呈现改造方案

> **文档性质：设计期过程文档，带日期。状态：三轮评审已完成（2026-09-25，三审通过）。**
> **依据**：总纲原则 P1（展示是唯一得分项）＋ 能力档位 14 项 ＋ `2026-09-25-登录身份与权限方案.md`（登录/角色）＋ 演示改版方案（镜头需要）＋ 三审记录（零术语口径与"全部已读"端点化拍板）。
> **一句话**：**界面的唯一任务是让"它能办什么、凭什么这么办、结果确定不确定"这三件事，在录屏里一眼看得见。**

---

## 一、三条改造目标

| # | 目标 | 判据（录屏时能不能一眼看出） |
|---|---|---|
| G1 | **能力可见** | 打开界面就知道"能办哪些事"，不用听讲解 |
| G2 | **过程透明** | 每一步的**依据、身份、规则**在轨迹里可见，且不出现接口术语 |
| G3 | **录屏友好** | 关键信息（对话 + 轨迹 + 结果）同屏；字号与对比度适合压缩后的视频 |

---

## 二、要新增的部分

| # | 新增 | 为什么 | 验收 |
|---|---|---|---|
| N1 | **登录页 + 角色标识** | 作者要求账号登录；且"用的是你们的账号"必须看得见 | 登录后顶栏常显角色，如"学生 · 张三" |
| N2 | **能力入口区（示例话术卡片）** | G1 的直接落地：让"能办什么"不用讲也能看见 | 卡片按角色分组；点卡片即填入输入框（不直接提交） |
| N3 | **"我还能做什么"折叠清单** | 14 项能力的完整索引（视频只演一遍，这一页保证"可办的事"随时可查） | 一屏列出全部能力，标注"已演示/可试" |
| N4 | **成果一页入口**（收尾镜头用） | 把后台实力变成可看见的数据（详见成果看板方案） | 一键切到成果页 |
| N5 | **会话状态提示** | 会话失效/被踢时给人话，不让观众看到 401 | 顶部条提示"登录已过期，请重新登录" |
| N6 | **"本次使用身份"说明条** | 借用管理只读身份读事实时，要**明示**（不越权的证据） | 轨迹身份徽章上带"只读"标记 + 悬停说明（三审口径：徽章文案＝"管理身份·只读"/"管理身份·报修操作"，报修两写操作明示"已确认"；不出现 ADMIN 英文枚举） |
| N7 | **通知区"全部标为已读"按钮（三审新增）** | "全部已读"不做意图、不进状态机（三审拍板 B），必须给用户一个手动落点；第 7 幕加段要拍到未读数清零 | 通知列表/未读数旁一个按钮 → 调引擎专用端点（`POST /api/notifications/read-all`）→ 未读数即时刷新；**无任务、无轨迹、无重试弹窗**；按钮旁一句小字"此操作不可撤销" |

## 三、要改造的既有部分

| # | 位置 | 改什么 |
|---|---|---|
| M1 | 轨迹条目 | 依据小标签、身份徽章、规则——**统一风格**。**三审口径（关键）**：列表层一律用**业务名**（事实已有中文名映射，本轮须为命题、规则补同模式中文名映射）；`P-*`/`R*`/`W*` 编号与接口原始字段只出现在**点开后的折叠详情**（"规则 R1：接口返回成功且业务码正常"这类解释放折叠层，可答"每一步可查"），录制时不展开。现状 `TrajectoryItem.vue` 把原始编号拼进标签，本轮必改 |
| M2 | 结果卡 | 四种形态固定：办成（绿）/ 有依据拒绝（红，附替代建议）/ 待确认（琥珀，无重试按钮）/ 已登记待人工（琥珀） |
| M3 | 对话区 | 追问必须给**可点选项**（列表选择式追问，能力 C7 用）；越权拒绝要带**替代动作按钮**（C14 学生发起同式：拒绝 + "帮查教室状态"替代） |
| M4 | 撤销/改期/报修 | 影响面确认要**列清条目**（改期显示"原时段→新时段"，报修显示"将被撤销的预约"明细，含每条的教室/时段/预订人业务信息）；C14 确认卡提供"确认执行 / 取消"两个按钮，恢复时不重新解析自然语言（三审挂起语义） |
| M5 | 顶部 | 加"能力入口 / 成果 / 主题"三个入口，保持极简 |
| M6 | 错误文案 | 把所有可能出现的错误逐条改成**人话**。**三审补明确清单**：不出现数字状态码、接口名、字段名，也不出现英文状态枚举（如 `suspended`）与内部决策代号（如 `B8`）——现状接入层响应消息里夹带这两类，本轮清掉 |
| M7 | 主题 | **录制统一用浅色**（投影与压缩更稳），深色保留但不录 |

---

## 四、明确不做

| # | 不做 | 理由 |
|---|---|---|
| 1 | "不确定"状态下给重试按钮 | 会让观众以为"重试就能解决"，且违反既有的三值表达纪律 |
| 2 | 任何管理后台（用户管理、教室维护） | 与"代办"定位不符 |
| 3 | 展示接口 URL / 参数名 / 状态机状态名 | 既有话术纪律 |
| 4 | 把"查不清"画成"失败" | 三值语义是本作品的分野 |
| 5 | 动画特效堆砌 | 录屏压缩后糊，且分散注意力 |

---

## 五、录屏友好的布局与视觉

| 项 | 规格 | 理由 |
|---|---|---|
| 布局 | 左对话 / 右轨迹，**同屏不滚动** | 讲解时不用来回切 |
| 分辨率 | 按录屏画布定（建议 1600×900 或 1920×1080 录制、输出 1080p） | 压缩后文字可读 |
| 字号 | 轨迹正文 ≥14px、依据标签 ≥12px | 1080p 压缩后可读 |
| 对比度 | 灰底黑字为主，**颜色只用来表达状态** | 状态颜色是唯一的语义色 |
| 滚动 | 关键镜头前先滚到顶（证据从头看） | 叙事清楚 |
| 主题 | 浅色 | 见 M7 |

## 六、验收（做完怎么算对）

| # | 验收项 |
|---|---|
| 1 | 界面能一眼回答四个问题：① 它能办什么 ② 这一步依据什么 ③ 用了谁的身份 ④ 结果是确定还是不确定（沿用既有验收口径） |
| 2 | 录制画面里**不出现**：接口 URL、接口 id、参数名（含 camelCase/snake_case 字段名）、状态机英文状态名、**命题编号（P-*）、规则编号（R*/W*）、阶段裸编号（P1–P6）**、数字错误码、浏览器控制台、命令行窗口（完整禁词表与检查机制见演示改版方案 §十；折叠详情层不受此限） |
| 3 | 全部错误文案过一遍人话检查（列清单，逐条打勾；清单须含 suspended/B8 两类现状遗留） |
| 4 | 登录 → 越权 → 会话失效三条路径都有明确界面表现；学生发起 C14 报修被拒且有替代按钮 |
| 5 | "能力入口"在不讲解的情况下能被看懂（找个没听过项目的人试一次） |
| 6 | **（三审补）**"全部标为已读"按钮：点击后未读数清零、无任务/轨迹产生；再次点击界面不报错（幂等表现以 G-C11 实测为准） |

## 七、待评审时拍板（三审已销项，2026-09-25）

| # | 待定 | 三审决定 |
|---|---|---|

## 一、问题：两条缺陷，一个根因

| # | 现象（实测） | 根因（已核验，证据） | 谁在替模型判断 |
|---|---|---|---|
| ① | 挂起追问回复"下午三点到四点"被真实模型理解成「查询教室可用性」——用户要**借**，系统去**查** | 追问轮的第二次理解，模型只看得到"追问句 + 用户回复"：`chat-bridge.js:193`（`beginResume` 只 push 这两条）、`:212`（`#clarify` 只 push 追问句，不 push 本轮原话），本轮原话与**已确定的意图/已收槽位**都没进去。而提示词的接续纪律挂在"历史里最后一条**助手摘要**的 intent"（`understanding/prompt.js:56`）——追问轮里没有这条摘要，锚点不存在，纪律不生效 | 系统"代替模型认定"了它的判断材料足够——实际不够 |
| ② | 改口新轮"改成周五下午"接不上上一轮的教室（追问"哪间教室"）；记忆里的槽位恒为空 | `task-runner.js:151` 的 `#chatSummary` 读 `tc.chat?.slots`，**全仓无写入点**（探针实证恒 `{}`）；真正的合并槽位在 `taskContext.slots`（`chat-bridge.js:86`）。记忆实际只注入"上一轮原话 + intent + 终态"。另：`http-server.js:411` 对每轮都 `recordTurn`，被取消轮也以 REJECTED 记入 | 系统"代替模型决定"了哪些上下文值得保留 |

**顺带受损的不变量**：缺陷 ① 会让 P1 的 `decide:understand` 只剩"识别为查询教室可用性"，第一轮的"借教室"意图没有任何结构化留痕——用户问"我让你借，你怎么去查了"，系统答不上来（**I4** 受损）。

**两条缺陷的共同根因**：引擎手里已经有确定下来的意图与槽位，却不肯在下一轮理解时交给模型。

## 二、边界：只钉"极其重要的"，其余默认交给模型

**用户口径（2026-09-27）**：系统的校验边界**不必定死、也无需多**——只有"一旦不守就会损害系统"的才划，划了就不能破；**大多数情况交给模型评判，要给模型更多权限**。

**判据（一条，够用）**：这个边界一旦不守，会不会**损害系统**——越权 / 凭证外泄 / 有副作用的调用绕过前置校验 / 结论脱离事实 / 不确定悬空 / 模型不可用就整条链路死掉。**会 → 钉死（系统强制）；不会 → 默认交给模型判断。**

### 2.1 硬边界清单（保持极简，就这几条）

| # | 硬边界（不可破坏） | 不守会怎样 | 系统怎么强制 |
|---|---|---|---|
| H1 | **有副作用的调用之前，前置事实必须已收集且已满足**（I1） | 先做后想，脏数据进存量系统且不可回收 | 状态机顺序 + 闸门三缺口**机械计算**（`chat-bridge.js:112`） |
| H2 | **只能用具备该接口权限的最小身份调用**（I5） | 越权，损害存量系统与他人数据 | `authorizeIntent` 在任何调用之前（`chat-bridge.js:93`） |
| H3 | **写请求发出后不可中断**（I3/I6） | "已取消"是谎言，而副作用还在飞 | `WRITE_STATES` / `isWrite` 判据 |
| H4 | **业务结论只能来自事实与判定** | 模型编造"这间教室是空的"，立论崩 | 结论由判定层产出，模型产出只作**结构化输入**（03 章 §一） |
| H5 | **意图必须落在闭集内、契约字段必须可校验** | 走出闭集 = 承诺了办不到的事 | `schema.js` 校验 + 格式重试 |
| H6 | **无 LLM 路径仍要能跑通** | 模型不可用时整条链路死掉 | 每次模型判断都要有确定性降级（范式：`chat-bridge.js:37` 限流 → 按钮式选择 E7） |

### 2.2 默认姿态：给材料 → 模型判断 → 系统接住 + 卡硬边界 + 留痕

除上表之外的一切，**默认交给模型**（也给模型更多权限）：

| 权限 | 现在（系统替它做了） | 给模型后 | 系统仍保留（只卡硬边界） |
|---|---|---|---|
| 沿用上一轮意图 / 改主意 | 只喂"追问句 + 回复"，等于替模型认定材料够了 | 拿到锚点后**自己判断**，输出 `intentSource` | H5 闭集校验 + 留痕（I4） |
| 跨轮该沿用哪些信息 | 记忆只送原话 + 意图 + 终态（槽位恒空） | 记忆带上**真实槽位**与上一轮终态，沿用与否**模型判断** | 注入条数上限（`conversation-store.js:14`） |
| 追问问什么、怎么问 | `chat-bridge.js:265 #missingQuestion` 硬编码 hints | 模型出素材（可自己决定问法） | 话术由编排层组装、零术语、不透传自由文本（03 章 §九 禁忌 9） |
| 时间 / 教室表达怎么解析 | 规则集，规则外只能追问（`canonical/time.js`、`canonical/classroom-name.js`） | 模型给归一化解释 | **范围校验**（不可过去 / 不跨自然日 / 窗口内）+ "请确认"标注（§7.3） |
| 拿不准时怎么办 | 系统按机械缺口追问 | 模型可以明确说"我不确定"（而不是硬猜） | 不确定必须收敛、不悬空（I3） |
| 问不问、先问什么、问几次 | 系统写死流程 | 模型按实际要求决定 | 追问 ≤3 轮、调用预算（§六） |
| **决定下一步调什么接口、调几次、失败怎么收场** | 状态机 | **仍然不交**（这不是"理解"，是"编排"） | 03 章 §十二 排除项 5：自主循环会走出闭集，且"为什么这一步"只能答"模型当时觉得应该"——**直接摧毁 I4** |

**一句话口径（答辩可用）**：模型负责**理解**（把它的话变成我们要的结构），系统负责**承诺**（做了什么、凭什么、办不成怎么收场）。判断权尽量外移，但**从不让模型决定"下一步调什么"**、也不把"会不会损害系统"交给它——所以"可复述的执行路径"这条立论不会被稀释，只会更难被"你说的话它没听懂"打回。

## 三、机制：判断点协议（本方案的核心）

只打两个补丁，第三处、第四处还会犯同一个错（材料没给足）。因此先定一个**判断点（judgement point）**规格，每个"要交给模型判断的事"都必须填满六格：

| # | 格 | 要求 |
|---|---|---|
| 1 | **触发时机** | 在哪个状态/哪一步触发（尽量复用既有调用，见 §五"是否需要额外调用"） |
| 2 | **材料** | 模型必须看到什么——**这一格是修复 ① 的通用答案**：本轮原话、上一轮已确定的意图（id + 人话名）、已收槽位（原话片段）、机械算出的缺口、以及"这次是在补哪几个槽位" |
| 3 | **输出契约** | 模型必须回什么字段，且必须是**可校验的结构化字段**（如 `intentSource: resumed \| switched`），不允许自由文本承担判断 |
| 4 | **系统校验** | 闭集 / 置信度 / 机械缺口 / 范围检查——**判定权不下放**（模型说"信息齐了"不作数） |
| 5 | **失败与降级** | 超时 / 限流 / 格式重试耗尽 → 走无 LLM 路径，如实说明，不编造 |
| 6 | **留痕** | 一条 `decision` 证据（含"判断来源"与依据），使 I4 在意图被改掉时仍能回答"为什么换了" |

**决定 3.0（四件套）**：

| # | 决定 | 事实 | 选项 | 决定 |
|---|---|---|---|---|
| 3.0 | 引入"判断点协议"，而不是就事论事打补丁 | 两条缺陷根因同一（材料没给足）；后续还有时间解析、教室解析、候选意图、改口头等待迁移 | a) 只改这两处 b) 先定协议再逐项迁移 | **b**：把"材料清单"变成必填项，避免第三处再犯；代价只是本文档本身 |

## 四、第一批：修两条缺陷（可直接照着做）

### 4.1 追问锚点（缺陷 ①）

| # | 决定 | 事实 | 选项 | 决定 |
|---|---|---|---|---|
| 1 | 追问轮**把锚点材料交足，让模型自己判断"这是在补槽位还是改了主意"** | 现在模型只看到"追问句 + 回复"（`chat-bridge.js:193,212`）；接续纪律的锚点是不存在的助手摘要（`prompt.js:56`） | a) 引擎硬规则"追问轮一律沿用原意图，除非命中改口关键词" b) 注入结构化锚点，交模型判断 c) 追问轮跳过模型，把回复直接当槽位值 | **b**。a 仍是"系统替模型判断"，且关键词表必然漏（"算了不借了""那换个时间吧""顺便看看别的"）；c 会让"改口/超域"失去出口，且违反既有决定 §5.5"追问后重问理解层"。b 只把材料给足，判断归模型，系统的闸门与机械缺口**一点不动** |

**材料清单（第 2 格，逐条都要给到）**：

1. 本轮原话（这次用户到底说了什么，如"下午三点到四点"）；
2. 上一轮**已确定的意图**（id + 人话名，如 `borrow-classroom` / 借教室）；
3. **已收下的槽位**（原话片段，如 `{ classroomName: "数智楼123", datePhrase: "下周三" }`）；
4. 系统**机械算出的缺口**（如 `timeSegment`）——只作为材料告诉模型"我们在等这个"，判定仍在系统（闸门三）；
5. 一句说明：**"如果用户是在补上面问的那几项，就沿用上一轮意图；如果他明显在改主意或换了件事，就按新意图输出。"**

**输出契约（第 3 格）**：在现有 `{ intent, slots, confidence, outOfDomain, clarifyQuestion, reasoning }` 之外新增

```json
{ "intentSource": "resumed" }
```

- 取值只有两个：`resumed`（沿用上一轮意图）/ `switched`（用户改了主意）。**必须是枚举**，不允许用自然语言表达。
- 与 few-shot 同形（`prompt.js` 的少样本里补一对"追问 → 补槽位沿用"的例子，形状与既有例子一致）。

**系统处理（第 4 格，判定权不下放）**：

- `intent` 仍必须属于闭集，否则作废重试（既有 `schema.js`）；
- `intentSource = resumed` 且 `intent` 与上一轮一致 → 合并槽位继续（既有 `chat-bridge.js:86`）；
- `intentSource = switched`（或与上一轮不一致）→ 按新意图走既有路径，**并留痕**；模型自称 `resumed` 但意图确实变了 → 以**模型给的意图**为准（它是闭集内合法值），留痕标注"自称沿用但意图不同"，作为审计线索，不压回原意图（用户真改口不能被系统憋住）；
- 缺口仍机械计算：模型说"齐了"不作数。

**留痕（第 6 格）**：`decide:understand` 增 `intentSource` 与依据摘要，使"为什么从借教室变成查询"可回答（I4）。

**降级（第 5 格）**：模型不可用 → 既有 E7（按钮式选择）/ 无 LLM 路径不变。

**提示词纪律**：改提示词必须走变更记录（`prompt.js:9` + 03 章 §七 纪律 3）。

**验证**：

- 脚本化模型：断言**第二次理解的输入消息里含锚点**（本轮原话 + 上一轮意图 + 已收槽位 + 缺口）——这条断言要卡在**注入的那一条**消息上（不要重蹈 §4.2 的假绿）；
- 真实模型端到端：缺时间 → 回"下午三点到四点" → **仍是借教室**，且"下周三/数智楼123"被沿用；
- 反例端到端："算了不借了，帮我查一下明天上午有没有空" → 正确切到查询意图，且留痕说明"用户改主意"。

### 4.2 记忆槽位与取消轮（缺陷 ②）

| # | 决定 | 事实 | 选项 | 决定 |
|---|---|---|---|---|
| 2 | 记忆带上**合并后的真实槽位**与**上一轮的终态**，取消轮**不过滤**，沿用与否交给模型 | `#chatSummary` 读从未写入的 `tc.chat.slots`（探针实证 `{}`），真值在 `tc.slots`（`chat-bridge.js:86` 合并后）；`recordTurn` 无取消过滤（`http-server.js:411`） | a) 带槽位 + 保留取消轮（标注 REJECTED，模型自己判断沿用哪些） b) 带槽位 + 过滤取消轮 c) 维持现状 | **a**。b 等于系统替模型决定"被取消的一律不算数"，而改口场景恰恰要**沿用教室、丢掉旧日期**（"不是周三，是周五"）——这与 §4.1 同一条原则：**把材料给对，让模型判断**。既有记忆上限不变（每会话 20 轮 / 注入最近 6 轮，`conversation-store.js:14`） |

1. `task-runner.js:151 #chatSummary`：`slots` 取自 `tc.slots`（合并后），并保留 `intent`；未解析出时给中立值（不变）；

3. 假的端到端断言收紧：`access.test.mjs` 那条"assistant 消息含 数智楼123"改为断言**注入的那一条**摘要（现在命中的是提示词自带的少样本例子，不是记忆）。

## 五、第二批及以后：判断点迁移清单

每行都是"现在系统写死的判断"→"把材料给模型，判断归它，校验留在系统"。**是否需要额外调用**一栏是成本口径：多数只需在既有调用里加材料，不增加延迟。

| 优先级 | 判断点 | 现在谁判（证据） | 要补的材料 | 系统保留什么 | 需要额外调用 | 风险 | 状态 |
|---|---|---|---|---|---|---|---|

**验证**

1. `cd orchestrator && npm test`（新增：锚点在输入消息里、`intentSource` 契约、记忆注入含槽位、REJECTED 语义）；`npm run check`；真起进程（`ORCH_PORT=8091 node src/access/main.js`）；

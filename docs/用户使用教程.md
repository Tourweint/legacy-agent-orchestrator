## 一、系统简介

### 1.1 这是什么

本系统是一个**面向存量业务系统的 AI 任务编排平台**。它允许你用自然语言（或结构化表单）与系统对话，由系统自动编排、调度存量业务系统的多个 API，完成跨接口、跨权限域的业务办理。

**核心特点**：
- **零侵入**：不修改存量业务系统的任何代码
- **可解释**：每一步操作都有证据链记录，可追溯"为什么做了这一步"
- **鲁棒**：接口超时、响应丢失、业务冲突等异常情况下，系统会先查证再决定，不盲目重试
- **不确定就说不确定**：当系统无法确认操作结果时，会如实告知并进入人工介入状态，而不是假装成功

### 1.2 系统架构

```
你（浏览器）
    ↓ http://localhost:5173
对话前端（Vue 3）
    ↓ /api 代理
编排引擎（Node.js，端口 8090）
    ↓ 防腐网关
存量业务系统（Spring Boot，端口 8080）
    ↓
MySQL（3306）+ Redis（6379）
```

### 1.3 支持的功能

| 功能 | 角色 | 类型 | 说明 |
|---|---|---|---|
| 借教室 | 教师 | 写 | 预约整间教室，支持多间同时预约 |
| 查询教室可用性 | 任意 | 只读 | 查询某间教室在某时段是否空闲 |
| 查我的预约 | 登录用户 | 只读 | 查看自己名下的所有预约记录 |
| 退预约 | 登录用户 | 写 | 撤销自己名下的预约 |
| 改期 | 登录用户 | 写 | 将已有预约改到新时段（先建新后撤旧） |
| 占座位 | 学生 | 写 | 预约教室内的具体座位（需提前 24 小时） |

## 二、快速开始

### 2.1 一键启动（推荐）

在项目根目录下运行：

```bat
start-all.bat
```

这会自动启动以下 5 个服务：

| 服务 | 端口 | 说明 |
|---|---|---|
| Redis | 6379 | 缓存（自动拉起） |
| 存量系统 | 8080 | 校园预约系统后端 |
| 编排引擎 | 8090 | AI 编排核心 |
| 对话前端 | 5173 | 你使用的界面 |
| 存量系统界面 | 5174 | 旧系统自带界面（双屏对照用） |

等待所有服务启动完成（约 30 秒），然后在浏览器中打开：

```
http://localhost:5173
```

### 2.2 手动启动（如果一键启动失败）

按以下顺序逐个启动：

**第 1 步：启动 MySQL**

```bat
net start MySQL80
```

**第 2 步：启动 Redis**

```bat
D:\legacy-agent-orchestrator\redis-5\redis-server.exe
```

**第 3 步：启动存量系统**

```bat
cd D:\legacy-agent-orchestrator\mock-legacy\backend
set JAVA_HOME=C:\Program Files\ojdkbuild\java-17-openjdk-17.0.3.0.6-1
mvn spring-boot:run
```

> ⚠️ 必须使用 JDK 17，默认的 Java 24 与 Lombok 不兼容。

**第 4 步：启动编排引擎**

```bat
cd D:\legacy-agent-orchestrator\orchestrator
set ORCH_LEGACY_ADMIN_PASSWORD=admin
set ORCH_LEGACY_TEACHER_PASSWORD=233
set ORCH_LEGACY_STUDENT_PASSWORD=abc
npm start
```

**第 5 步：启动前端**

```bat
cd D:\legacy-agent-orchestrator\frontend
npm run dev
```

### 2.3 验证服务就绪

打开浏览器，分别访问：

| 地址 | 预期结果 |
|---|---|
| http://localhost:5173 | 显示登录页面 |
| http://127.0.0.1:8090/api/health | `{"code":0,"message":"ok","data":{"status":"ok"}}` |
| http://localhost:8080/ | `{"code":401,"message":"未登录或令牌无效"}`（401 是正常的） |

### 2.4 大模型配置（可选）

自然语言对话需要阿里云百炼（DashScope）的 API Key。如果未配置，自然语言输入会提示"理解层不可用"，但**结构化功能（表单输入）始终可用**。

配置方法：

```bat
set DASHSCOPE_API_KEY=sk-你的密钥
```

然后重启编排引擎。

## 三、登录与用户角色

### 3.1 登录

1. 打开 http://localhost:5173
2. 在登录页面输入用户名和密码
3. 点击"登录"按钮

**演示账号**：

| 角色 | 用户名 | 密码 | 可执行操作 |
|---|---|---|---|
| 教师 | `233` | `233` | 借教室、查可用性、查/退/改自己的预约 |
| 学生 | `abc` | `abc` | 占座位、查可用性、查/退/改自己的预约 |
| 管理员 | `admin` | `admin` | 系统管理（不通过本平台办理业务） |

### 3.2 角色权限说明

系统严格遵循**最小权限原则**：

- **教师**可以预约整间教室，但**不能**预约座位
- **学生**可以预约座位，但**不能**预约整间教室
- 如果你用学生账号尝试借教室，系统会在**任何接口调用之前**就拒绝，并给出替代建议（如"我可以帮您查空闲情况，或者帮您排座位候补"）
- 所有写操作（借/退/改/占）都以**你本人的身份**执行，系统不会用高权限身份替你操作

### 3.3 登出

点击页面右上角的用户头像/用户名，选择"退出登录"。

### 4.2 会话列表（左侧栏）

**助手回复**：显示在左侧，包含以下部分：

1. **核心结论**（大字显示）：
   - 办理成功："已为您办妥：数智楼 123（预约 #184，2026-10-01 14:00–16:00）"
   - 办理失败："无法办理：该时段已有安排"
   - 需要追问："请问您想借哪间教室？"
   - 不确定："操作结果无法确认，已登记人工处理"

2. **思考过程**（默认收起，点击展开）：
   - 显示系统执行的每一步：事实收集、命题判定、接口调用、决策
   - 每一步都有中文说明（如"收集到：这间教室的详情"、"判定：这个时段是空的"）
   - 办理失败时，失败链路会**部分展开**，帮助你理解为什么没办成

   - 展开/收起思考过程

- **文本输入框**：输入自然语言指令（如"帮我借明天下午数智楼222"）

## 五、功能一：借教室（教师）

### 5.1 适用场景

你是一名教师，需要预约一间教室用于上课、开会或活动。

### 5.2 自然语言方式

在输入框中输入：

```
帮我借明天下午数智楼222
```

系统会自动理解：
- 意图：借教室
- 教室：数智楼 222
- 日期：明天
- 时段：下午（14:00–18:00）

如果信息不完整（如没说教室名），系统会追问：

```
请问您想借哪间教室？
```

你可以回复：

```
数智楼123
```

系统会继续执行。

### 5.3 支持的时间表达方式

系统支持多种中文时间表达：

| 表达方式 | 示例 | 解析结果 |
|---|---|---|
| 相对日期 | "明天"、"后天"、"下周三" | 对应日期 |
| 中文日期 | "10月1日"、"九月三十号" | 对应日期 |
| 时段词 | "下午"、"上午"、"晚上" | 上午=08–12，下午=14–18，晚上=18–22 |
| 精确区间 | "14点到16点"、"下午两点到四点" | 14:00–16:00 |
| 组合 | "明天下午两点到四点" | 明天 14:00–16:00 |

### 5.4 执行过程

系统会自动执行以下步骤（你可以在"思考过程"中看到）：

1. **收集事实**（5 项）：
   - 这间教室的详情（确认教室存在）
   - 这些座位在这段时间的占用情况
   - 全量预约记录（跨身份查看，用管理员只读身份）
   - 我名下的预约（确认没有重复提交）
   - 这间教室的检修安排（确认不在维修期）

2. **判定命题**（5 项）：
   - 找到了这间教室 ✓
   - 这间教室现在可以预约 ✓
   - 我没有重复提交过同一时段 ✓
   - 这个时段是空的 ✓
   - 这间教室这段时间不在检修 ✓

3. **决策**：所有前置条件满足，提交预约

4. **提交预约**：以你本人（教师）身份调用存量系统的预约接口

5. **终态**：
   - 成功：显示预约编号和详情
   - 时段被占：显示"该时段已有安排"，并建议其他时段
   - 重复提交：显示"此事此前已办成（预约 #XXX），未重复提交"

### 5.5 多间教室同时预约

你可以一次说多间教室：

```
帮我借明天下午数智楼123和222
```

系统会按顺序为每间教室执行完整的预约流程。

### 5.6 添加事由

```
帮我借明天下午数智楼222，事由是研究生组会
```

## 六、功能二：查询教室可用性

### 6.1 适用场景

你想知道某间教室在某个时段是否空闲，但不一定需要预约。

### 6.2 使用方式

```
数智楼222明天下午有空吗？
```

或：

```
查一下数智楼123下周三上午的可用性
```

### 6.3 执行过程

系统会：
1. 收集教室详情和该时段的占用情况
2. 判定该时段是否空闲
3. 返回查询结果

### 6.4 结果说明

- **空闲**："数智楼 222 在 2026-10-01 14:00–18:00 空闲，可以预约"
- **被占用**："数智楼 222 在该时段已有预约（预约 #XXX），不可用"
- **维修中**："数智楼 222 在该时段处于检修期，不可用"

> 💡 查询可用性是**只读操作**，不会产生任何副作用，任何角色都可以使用。

## 七、功能三：查我的预约

### 7.1 适用场景

你想查看自己名下有哪些预约记录。

### 7.2 使用方式

```
查一下我的预约
```

或：

```
我最近借了哪些教室？
```

### 7.3 执行过程

系统会：
1. 以你本人身份调用"我的预约"接口
2. 汇总所有有效预约记录
3. 按时间排序展示

### 7.4 结果说明

系统会列出你名下的所有预约，每条包含：
- 预约编号
- 教室/座位
- 日期和时段
- 状态（有效/已取消/已过期）

示例：

```
您共有 3 条有效预约：
1. 数智楼 123（预约 #180），2026-10-01 14:00–16:00
2. 数智楼 222（预约 #184），2026-10-02 09:00–11:00
3. 座位 2-3（数智楼 222），2026-09-28 15:00–17:00
```

## 八、功能四：退预约

### 8.1 适用场景

你有一条预约不再需要，想取消它。

### 8.2 使用方式

```
帮我退掉预约 #180
```

或：

```
取消我明天下午数智楼222的预约
```

### 8.3 执行过程

系统会：
1. 查找你名下的预约记录（确认是你本人的预约）
2. 定位到目标预约
3. 以你本人身份调用撤销接口
4. 验证撤销结果

### 8.4 结果说明

- **撤销成功**："已撤销：数智楼 123（预约 #180，2026-10-01 14:00–16:00）"

- **记录不存在**："未找到预约 #180"

> ⚠️ 退预约是**写操作**，只能撤销你本人名下的预约。

## 九、功能五：改期

### 9.1 适用场景

你有一条预约，想把它改到另一个时段。

### 9.2 使用方式

```
把预约 #180 改到后天下午
```

或：

```
我明天下午数智楼222的预约，改成下周三上午
```

### 9.3 执行过程（先建新，后撤旧）

改期采用**"先建新，后撤旧"**的双写策略，确保不会出现"旧的撤了但新的没订上"的情况：

1. **收集事实**：确认原预约存在且是你的，确认新时段空闲
2. **创建新预约**：在新时段创建一条新预约
3. **撤销旧预约**：新预约成功后，撤销旧时段的预约
4. **验证结果**

### 9.4 异常处理

- **新时段没订上**：旧预约**保持不动**，系统如实告知"新时段不可用，原预约未改动"
- **新的订上了，但旧的撤不掉**：系统会重试一次撤销；如果仍失败，进入**人工介入状态**，如实告知"新预约已创建，但旧预约撤销失败，请联系管理员处理"
- **两个时段都有预约**：这是改期失败的兜底状态，系统会明确告知，不会假装成功

### 9.5 结果说明

- **改期成功**："已改期：数智楼 123 从 2026-10-01 14:00–16:00 改为 2026-10-03 14:00–16:00（新预约 #185）"
- **新时段不可用**："新时段已有安排，原预约（#180）未改动"
- **需人工处理**："新预约已创建（#185），但旧预约（#180）撤销失败，请联系管理员"

## 十、功能六：学生占座位

### 10.1 适用场景

你是一名学生，想在某间教室内预约一个具体座位用于自习。

### 10.2 使用方式

```
帮我占今天下午数智楼222的2-3座位
```

或：

```
预约数智楼222的第2排第3个座位，明天上午
```

### 10.3 座位编号规则

座位号格式为 `行-列`，例如：
- `2-3` = 第 2 排第 3 列
- `1-1` = 第 1 排第 1 列

系统会自动将座位号解析为座位 ID。

### 10.4 约束条件

座位预约有以下约束（来自存量系统的真实规则）：

1. **只能提前 24 小时预约**：不能预约超过 24 小时后的座位
2. **座位状态必须为 ENABLED**：损坏或停用的座位不可预约
3. **时段不能与已有预约重叠**

如果违反约束，系统会如实告知原因。

### 10.5 执行过程

1. 收集教室详情和座位布局
2. 解析座位号为座位 ID
3. 确认座位存在且可用
4. 收集该座位在该时段的占用情况
5. 判定时段空闲
6. 以你本人（学生）身份提交座位预约

### 10.6 结果说明

- **预约成功**："已为您预约：数智楼 222 座位 2-3（2026-09-28 15:00–17:00）"
- **座位不存在**："未找到座位 2-3（数智楼 222）"
- **超过 24 小时**："座位预约只能提前 24 小时，请选择更近的时段"
- **时段被占**："该座位在该时段已被预约"

## 十一、证据链与可解释性

### 11.1 什么是证据链

系统的每一次操作都会记录在**证据链**中。证据链是系统"可解释性"的核心——它能回答：

- 系统做了什么？
- 为什么做这一步？
- 依据什么事实？
- 调用了哪个接口？
- 接口返回了什么？
- 最终结论是什么？

### 11.2 如何查看证据链

在助手回复中，点击"思考过程"即可展开查看。

证据链按阶段组织：

| 阶段 | 说明 | 示例 |
|---|---|---|
| P1 | 实体消解 | 找到教室"数智楼 222"（ID=4） |
| P2 | 事实收集 | 收集到 5 项事实 |
| P3 | 命题判定 | 判定 5 个命题全部成立 |
| P4 | 决策 | 所有前置条件满足，提交预约 |
| P5 | 提交/查证 | 调用预约接口，返回成功 |
| P6 | 终态 | 任务完成 |

### 11.3 证据链中的关键信息

每条证据记录包含：
- **动作**：如"调用接口"、"收集事实"、"判定命题"、"决策"
- **阶段**：P1–P6
- **结论**：成功/失败/不确定
- **依据**：引用的规则编号（如 W1=提交成功、R1=读取成功）
- **详情**：接口返回的业务数据（敏感信息已脱敏）

### 11.4 零术语设计

证据链中的所有概念都使用**人话名称**，而不是内部编号：

| 内部编号 | 人话名称 |
|---|---|
| F1 | 这间教室的详情 |
| F3 | 这些座位在这段时间的占用情况 |
| P-SLOT-FREE | 这个时段是空的 |
| P-NOT-ALREADY-MINE | 我没有重复提交过同一时段 |
| W1 | 提交成功 |
| W2 | 提交结果存疑——可能是重复提交，也可能是别人先占了，要去核对 |

这样你不需要了解系统的内部设计就能看懂证据链。

## 十二、高级功能

### 12.1 停止/取消任务

在任务执行过程中，输入框右侧会出现**停止按钮**（或按 `Esc`）。

**停止规则**：
- **挂起状态**（系统在追问你）：立即停止，不产生任何副作用
- **运行中**（正在收集事实或判定）：设置停止标记，在当前状态边界收口，接口返回 202
- **写请求已发出**（预约请求已经发到存量系统）：**不受理停止**，并说明原因"写请求已发出，无法撤回，请等待结果"

> 💡 这是系统的安全设计——一旦写操作已经发出，就不能假装没发生过。系统会继续执行并给出确定的结论。

### 12.2 多轮对话与会话记忆

系统支持**多轮对话**——在同一段对话中，你可以接着上一句说：

```
你：帮我借明天下午数智楼222
系统：已为您办妥：数智楼 222（预约 #184，...）
你：那改成后天下午
系统：（系统记得上一句说的是数智楼222，直接执行改期）
```

系统通过 `conversationId` 记住对话上下文，包括：
- 之前提到的教室
- 之前的时段
- 之前的预约编号

### 12.3 会话管理

- **新建会话**：点击左侧栏的"新建会话"按钮
- **切换会话**：点击左侧栏中的历史会话
- **会话隔离**：不同登录用户的会话互相隔离，你看不到别人的对话
- **本地存储**：会话数据保存在浏览器本地，清除浏览器数据会丢失会话

### 12.4 双屏对照演示

系统支持**双屏对照**演示模式：
- **左屏**（5173）：本系统的对话工作台
- **右屏**（5174）：存量系统自带的管理界面

通过双屏对照，你可以直观地看到：
- 本系统创建的预约，在存量系统中真实存在
- 本系统撤销的预约，在存量系统中真实被取消
- 本系统的"零侵入"——存量系统没有任何修改

启动存量系统界面：

```bat
start-all.bat legacyui
```

然后在浏览器中打开 http://localhost:5174

## 十三、常见问题与故障排除

### 13.1 登录相关

**Q: 登录提示"账号或密码不正确"**
- A: 确认用户名和密码正确。演示账号：教师 `233/233`、学生 `abc/abc`。

**Q: 登录一直转圈，最后超时**
- A: 可能是 Redis 未启动。存量系统的登录会话存在 Redis 中，Redis 缺席会导致登录挂起超时。检查 Redis 是否在运行（端口 6379）。

**Q: 登录提示"服务端故障"**
- A: 存量系统可能未启动或异常。检查存量系统是否在运行（端口 8080），访问 http://localhost:8080/ 应返回 401。

### 13.2 功能相关

**Q: 自然语言输入提示"理解层不可用"**
- A: 未配置 `DASHSCOPE_API_KEY` 环境变量。配置后重启编排引擎即可。或者使用结构化方式（通过 API 或调试入口）提交任务。

**Q: 借教室提示"整间教室的预约只能由教师提交"**
- A: 你当前登录的是学生账号。学生不能预约整间教室，只能预约座位。请用教师账号（233/233）登录。

**Q: 占座位提示"座位预约只能提前 24 小时"**
- A: 存量系统的真实约束——座位预约不能超过 24 小时。请选择更近的时段。

**Q: 改期后提示"新预约已创建，但旧预约撤销失败，请联系管理员"**
- A: 这是改期的兜底状态。新预约已经成功，但旧预约撤销失败（可能是网络问题或存量系统异常）。请联系管理员手动撤销旧预约。系统不会假装改期成功。

### 13.3 系统相关

**Q: 页面加载后一直显示"运行中"，但没有结果**
- A: 可能是编排引擎进程异常。检查 http://127.0.0.1:8090/api/health 是否正常返回。如果引擎挂了，重启编排引擎。

**Q: 思考过程中显示"提交结果存疑——要去核对"**
- A: 这是系统的正常行为——当预约接口返回 409（冲突）时，系统无法区分是"你自己重复提交"还是"别人先占了"。系统会先查证（调用查询接口），再给出确定结论。这是系统"不确定性治理"的核心创新。

**Q: 任务结论是"不确定，已登记人工处理"**
- A: 当系统无法确认操作结果时（如写请求发出后响应丢失，且查证也无法确定），系统会如实告知"不确定"，并进入人工介入状态。这比假装成功更安全。请联系管理员核查存量系统中的实际记录。

### 13.4 数据重置

如果测试过程中产生了大量预约数据，想重置为初始状态：

```bat
# 方法一：使用一键脚本（需要 bash 环境）
bash deploy/scripts/reset-legacy-data.sh

# 方法二：手动重置（Windows）
# 1. 重建数据库并导入种子数据
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p123456 -e "DROP DATABASE IF EXISTS classroom; CREATE DATABASE classroom DEFAULT CHARACTER SET utf8mb4;"
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p123456 classroom < mock-legacy\backend\sql\classroom.sql

# 2. 清空 Redis
D:\legacy-agent-orchestrator\redis-5\redis-cli.exe flushall
```

重置后初始数据：7 间教室、247 个座位、86 条种子预约、2 个维修窗口、15 个用户。

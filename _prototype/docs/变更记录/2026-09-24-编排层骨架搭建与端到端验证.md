## 二、实测发现（本轮新增的边界事实）

全部为实测结论，已回写进 `interfaces.js` 的 `notes` 字段。

### 2.1 ⚠️ 时区陷阱（本轮最隐蔽的一个坑）

| 环节 | 实测事实 |
| --- | --- |
| 提交入参 | 传 `2026-09-30T04:30:00Z` |
| 数据库落库 | 存 `2026-09-30 04:30:00`（UTC） |
| 查询出参 | 返回 `"2026-09-30T04:30:00"`（**无时区标记**） |

**出参的无时区时间实际是 UTC 时刻**（源码写入前做了本地→UTC 转换）。

- 若按本地时区（Asia/Shanghai）解析它，会与提交时的时间相差 8 小时；
- 后果：时段重叠判定全部失效 → **重复申请检测静默失灵**（这是一个不会报错的错误）。

**处置**：`common/time.js` 明确区分——**解析按 UTC**（还原本意时刻）、**展示按配置时区**（用户看得懂）。

### 2.2 `reserved_seats` 的语义（已核实到源码级）

`ReservationServiceImpl:182-188`：

```java
if (countClassroomConflicts(...) > 0 || maintenanceWindowMapper.countClassroomConflicts(...) > 0) {
    return seatMapper.selectByClassroomId(classroomId).stream().map(Seat::getId).toList();  // 返回全部座位
}
```

**"整间教室被预约"与"教室在维修中"被合并成同一个返回值**，从这个接口无法区分。

→ 要区分，只能换 ADMIN 身份去后勤域查维修窗口。
→ **这是"跨权限域聚合"的技术必然性，不是设计偏好。**

已固化为命题 `P-SLOT-FREE` 的证据字段 `signalIsAmbiguous`。

### 2.3 权限鸿沟（本轮正式核实）

| 接口 | ADMIN | TEACHER | STUDENT |
| --- | --- | --- | --- |
| `/admin/maintenance`（查维修窗口） | ✅ 200 | ❌ 403 | ❌ 403 |
| `/admin/reservations`（管理端列表） | ✅ 200 | ❌ 403 | ❌ 403 |
| `/classrooms/{id}/reserved_seats` | — | ✅ 200 | — |
| `/reservations/classrooms`（建整间预约） | ❌ **200 + code 403** | ✅ 200 | — |

**两处真实异构**：
1. 同一"无权限"语义有两种表达（过滤器层 `HTTP 403` vs 方法层 `HTTP 200 + code 403`）；
2. 同一件事的两个必要条件（读维修 + 写预约）分属两个互不相通的权限域。

## 三、修复的设计缺陷（由验证暴露）

### 3.1 状态机跳步（严重）

**现象**：提交成功后抛"非法状态转移：VALIDATING 不接受事件 CALL_SETTLED"，对外返回 500——**但预约已经真实写入数据库**。
即"写入成功但对外报错"，恰是本项目要消除的最危险场景。

**根因**：代码在 `VALIDATING` 状态下直接提交并发布局事件，绕过了 `SUBMITTING`。

**处置**：
1. 提交前显式 `fire(PROPOSITIONS_OK)` → 进入 `SUBMITTING`；
2. `decide()` 改为通过 `fire()` 真实推进状态，而不是返回状态字符串（否则"代码走的路"与"表里画的路"会分叉）；
3. 终态不再由代码直接赋值，必须经 `JUDGE_SUCCESS` / `JUDGE_FAILURE` 等事件到达；
4. 新增 `FACT_UNAVAILABLE`、`CHECK_ONLY`、`JUDGE_SUCCESS`、`JUDGE_FAILURE` 四个事件与对应转移。

**这条缺陷反过来证明了状态机严格校验的价值**：正是它把"跳步"挡住了。

### 3.2 重复申请被误报为"教室不可用"

**现象**：用户重复提交同一申请时，系统提示"教室不可用，且未找到替代教室"——而占用者其实是**用户自己**，提示具有误导性。

**根因**：缺少"自己是否已申请过"的判定。

**处置**：新增命题 `P-NOT-ALREADY-MINE`（依赖事实 `myReservations`），作为幂等的**第一道防线**（在写入之前拦截，比"写入后查证"更早）；命中时返回 `DUPLICATE_REQUEST`，提示"您此前已提交过（预约 id=…），无需重复提交"。

### 3.3 时间展示错误

`describeRange` 对无时区字符串再次按本地时区解释，导致展示的时刻偏移 8 小时。已改为内部统一走 `fromLocalDateTime`。

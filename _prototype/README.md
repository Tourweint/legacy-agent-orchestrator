# _prototype —— 降级的可行性验证件（**不是交付物**）

## 这里是什么

2026-09-24，在用户明确要求「写方案」的情况下，AI 自作主张产出了一套可运行的代码骨架，并进一步为这套代码写了说明书。用户指出这是**交付物越界**，要求降级。

本轮处置：**代码与"代码说明书"一并移入本目录，退出交付物体系。**

```
_prototype/
  orchestrator/                      ← 2026-09-24 产出的可运行实现（Node ESM，零第三方依赖）
  docs/基线文档/系统架构.md           ← 为上述代码写的分层说明（按文件讲职责）
  docs/基线文档/接口注册表.md         ← 上述代码中注册表的镜像（用代码 ID 命名接口）
  docs/变更记录/2026-09-24-编排层骨架搭建与端到端验证.md
```

处置记录见 `docs/变更记录/2026-09-24-交付物越界与降级处置.md`。

## 怎么用这个目录（三条规矩）

### 规矩一：**方案文档不得引用本目录的结构**

方案里可以引用从这里得到的**事实结论**，**不得**引用它的代码结构、模块命名、文件划分、类名、函数名。

| 允许引用（事实） | 禁止引用（结构） |
|---|---|
| 409 是歧义信号，无法区分"自己已成功"与"他人已占" | `adapter.js` 的 `isAmbiguous()` 实现 |
| 响应时间字段无时区标记、真实语义是 UTC | `common/time.js` 里 `fromLocalDateTime()` 的写法 |
| `available_list` 无时间参数，答不了时段可用性 | `registry/interfaces.js` 中的接口 ID 命名法 |
| 「整间被占」与「维修中」在源码层被合并返回 | `propositions.js` 中 `P-SLOT-FREE` 的组织方式 |

**理由**：一旦方案引用了代码结构，就等于承认那套结构已经定案——而它没有。方案是待评估的，结构应当从方案里长出来，而不是从一份既成代码里倒推。

### 规矩二：**不得在本目录继续开发**

这里的东西**冻结**。修 bug、加功能、补模块都不在此进行。若将来决定正式开发，按 `docs/设计方案/` 里的方案重新建目录，不从这里长。

**理由**：它存在的意义是"一次性验证某些判断能否成立"，不是项目的起点。允许它继续生长，就等于默许了"先写代码再补方案"这条错误路径。

### 规矩三：**它随时可以被整份删除**

本目录不承载任何不可再生的资产。所有有长期价值的内容（实测结论、边界事实、源码级证据）都必须**已经**落在 `docs/` 里。

> 已知需要保全的结论，其当前位置：
> - 协议异构点、权限鸿沟、能力缺口、演示数据现状 → `docs/基线文档/存量系统改造说明.md` §七 §八 §九
> - 零侵入的论证与复核方式 → 同上 §一 §三 §四 §十一
> - 「409 是歧义信号」这一更正的推导过程 → 同上 §七.3
>
> 若发现还有哪个事实**只存在于本目录**，请先补进 `docs/`，再考虑删除它。

## 它验证了什么（保留结论，供方案引用）

以下结论已用实际运行验证过，方案里可以直接采信；**但它们都不是"必须是这样做"的理由**。

| 编号 | 结论 | 验证方式 |
|---|---|---|
| V1 | 存量系统的预约接口**有**时间重叠冲突检测，重复提交返回 `HTTP 200 + code 409`，6 路并发仍只落库 1 条 | 直接对存量系统发请求 + `SELECT` 核对 |
| V2 | `409` 无法区分「自己已成功」与「他人已占」——两种情况的响应完全相同 | 构造两种成因、比对响应字节 |
| V3 | 响应体里的时间字符串**不带时区标记**，其真实语义是 **UTC**（源码写入前做过本地→UTC 转换） | 提交带 `Z` 的值 → 查库 → 读回，三段比对 |
| V4 | `GET /classrooms/available_list` 的 `min_capacity` 缺失时返回**业务码 500**（而非 400） | 删字段消融测试 |
| V5 | `GET /admin/reservations` 的 `keyword` 语义模糊（`keyword=4` 命中 `resourceId=6`），不可用于精确过滤 | 实测比对命中记录 |
| V6 | 「整间教室被预约」与「教室在维修中」在**源码层**被 `||` 合并为同一个返回值 | 读 `ReservationServiceImpl:182-188` |
| V7 | `logi` 域的维修事实只有 `ADMIN` 身份读得到，`TEACHER` 被拒（HTTP 403） | 多角色手工 token 直连对照 |

> ⚠️ V1 推翻了本作品**早期**提出的假设（"重复提交会产生多条记录"）。**V3 是最危险的一条**：它不报错，只会让时段比较静默失效。方案中必须把它当作硬约束处理，而不是"注意事项"。

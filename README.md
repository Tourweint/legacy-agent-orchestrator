# legacy-agent-orchestrator

**面向存量业务系统的 AI 任务编排平台** —— 用自然语言交互，由自研状态机 Agent 自动编排、调度存量业务系统的多个接口，完成跨接口、跨权限域的业务，并在接口抖动/超时/脏返回下保持鲁棒；**不修改存量系统的任何一行代码**。

校园教室借用是本作品的验证场景，**研究对象是面向不可修改的存量系统的、可解释可恢复的任务编排**。

## 它解决什么问题

存量业务系统接口零散、协议各异、权限分区，用户要办一件事往往得手工跨好几个系统、拼十几次请求。给每个老系统单独改造成"AI 化"成本极高且不可行。

本作品的做法是**在它们之上加一层编排层**：

```text
对话前端  →  编排引擎（自研核心）  →  防腐网关  →  存量业务系统（不可改）
```

- 用户只说一句话（"帮我订周三下午数智楼 222"）
- 引擎拆解任务、跨接口读取事实、判定前置条件、按需切换身份、提交并处理失败
- 存量系统不知道 Agent 的存在，也不需要知道

## 为什么必须"零侵入"

不是为了少干活，而是**改造存量系统在现实中通常不被允许**：它们有历史包袱、有在跑的业务、有维护责任边界。一个只能在"能改老系统"前提下成立的 AI 方案，在真实场景里落不了地。

所以本作品把"不碰老系统"当作**硬约束**，而不是优化目标：实测对被测系统的源码改动量为 **0 个文件**，见 [存量系统改造说明](./docs/基线文档/存量系统改造说明.md)。

## 技术栈

### 编排引擎

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | **JavaScript（ESM）** | `"type": "module"`，`import`/`export` 语法；不引入 TypeScript 编译步骤（见下） |
| 运行时 | Node.js 20+ | 需要原生 `fetch`（18+）与顶层 `await` |
| 状态机 | **自研** | 核心创新点，不引工作流引擎（见 [设计方案第 04 章](./docs/设计方案/2026-09-24-系统设计方案/04-任务编排与状态机方案.md)） |
| 依赖策略 | **允许必要的第三方依赖，但每一处引入都要论证** | 见下方「依赖策略」 |
| 大模型 | 阿里云百炼 DashScope（`qwen-plus`，OpenAI 兼容模式） | 仅用于理解层，走环境变量注入密钥 |

### 对话前端

| 项 | 选型 |
|---|---|
| 框架 | Vue 3（Composition API）+ Vite |
| 状态 | Pinia（仅跨页面状态） |
| 视觉 | Stripe 风格（见 [设计方案第 10 章](./docs/设计方案/2026-09-24-系统设计方案/10-前端交互方案.md)） |

### 被测存量系统（`mock-legacy/`，不可修改）

Spring Boot 3.5.9 + MyBatis + JWT + MySQL/MariaDB + Redis，详见 [存量系统改造说明](./docs/基线文档/存量系统改造说明.md)。

### 依赖策略

**早期方案曾主张"零第三方依赖"。现修正为：默认最小化依赖，但不把零依赖当作纪律。**

理由：零依赖在原型阶段有价值（部署简单、无供应链风险），但它会诱使放弃本来就该用的成熟工具——尤其在前端（Vue/Vite 无替代）与可视化（图表、时间轴）上。**为守住一个指标而自造轮子，是负收益。**

分档管理，逐个论证：

| 档 | 范围 | 规则 |
|---|---|---|
| **必须**（免论证） | 运行时与框架本身：`vue`、`vite`；Node 内置模块（`node:http`、`node:crypto` 等） | 直接用 |
| **按需**（需在本方案对应章节写明理由） | HTTP 客户端、参数校验、日志、测试框架、图表/可视化 | 引入一处，就在该章登记"为什么不用内置方案" |
| **仍禁止** | 工作流引擎（Flowable / Temporal 等）、ORM 全家桶、Web 框架全家桶（Express/Koa/Nest） | 前两者外包核心创新点；后者对本项目路由规模是过度设计 |

**注意**：唯一 HTTP 出口（只有防腐网关能发起对存量系统的调用）等结构性约束**与依赖数量无关**，见第 02 章。用不用第三方 HTTP 客户端，都不改变"出口唯一"这条纪律。

## 运行被测存量系统

前置：JDK 17、MariaDB/MySQL（库 `classroom`）、Redis 6379。

```bash
# 1. 复位被测系统数据到已知初始状态
bash deploy/scripts/reset-legacy-data.sh

# 2. 启动被测存量系统（→ http://localhost:8080）
bash deploy/scripts/start-legacy.sh
```

被测系统可用账号：`admin/admin`（ADMIN）、`233/233`（TEACHER）、`abc/abc`（STUDENT）。
注意：其自带文档中的 `student01/student01` **是错的**，实测不可用。

**编排引擎阶段 0–2 已完成**（测试：`cd orchestrator && npm test`；自检：`npm run check`；对在线存量系统的只读验证见 `orchestrator/scripts/smoke-contact.mjs`）；编排层（阶段 3）起的实现将逐步补全任务链路。
